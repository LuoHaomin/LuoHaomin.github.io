3.1 流水线基本概念

流水线核心思想

  • 流水线（Pipeline）：将一个任务分解为 K 个子任务，在 K 个不同阶段（使用不同资源）运行，每个子任务执行需要 1 个单位时间，整个任务执行时间为 K 倍单位时间
  • 重叠执行模式：K 个流水段并行执行 K 个不同任务，每个单位时间进入/离开流水线一个任务
  • ⭐ 流水线技术提高的是系统吞吐率，不能缩短单个任务的执行时间

同步流水线

  • 流水段之间采用时钟控制的寄存器文件（clocked registers），即 Pipeline Register
  • 时钟上升沿到达时，所有寄存器同时保存前一流水段的结果
  • 流水段是组合逻辑电路
  • 设计目标：各段相对平衡（延迟时间大致相等）
  • ⭐ 时钟周期取决于延迟最长的流水段（瓶颈段决定时钟频率）

RISC 典型 5 段流水线

阶段 名称 功能
IF Fetch 取指：选择地址（下一条指令地址或转移地址）
ID Decode 译码：确定控制信号，从寄存器文件读取寄存器值
EX Execute 执行：Load/Store 计算有效地址；Branch 计算转移地址并确定方向
MEM Memory 存储器访问（仅 Load 和 Store）
WB Writeback 结果写回
  • 每段延迟为 1 个 cycle
  • 设计适用于同步读写（synchronous reads and writes）的寄存器文件/存储器

流水线性能基本公式

  • 设 ti = stage Si 的时间延迟
  • ⭐ 时钟周期τ=max(ti)（最长的流水段延迟）
  • 时钟频率f=1/τ=1/max(ti)
  • ⭐ 完成时间：k+n−1 个时钟周期内完成 n 个任务
    • 完成第一个任务需要 k 个时钟周期（装入时间 fill）
    • 其他 n−1 个任务需要 n−1 个时钟周期
    • 最后一个任务离开后排空（drain）
  • 理想加速比（相对于串行执行）= k（流水线级数）

流水线正常工作的基本条件

  1. 增加寄存器文件保存段间数据和控制信息
  2. 需要更高存储器带宽
  3. 消除各类 Hazards（结构相关、数据相关、控制相关）

影响性能的因素：瓶颈段、段间时间不均衡、装入/排空时间、hazards

3.2 Hazards 概述与数据相关处理

Hazards 分类

⭐ 处理相关的一般方法：插入 bubble，导致 CPI > 1（单发射理想 CPI = 1）

类型 名称 成因
结构相关（Structural Hazard） 资源冲突 流水线中一条指令可能需要另一条指令使用的硬件资源
数据相关（Data Hazard） 数据依赖 一条指令依赖先前指令产生的结果值
控制相关（Control Hazard） 控制流改变 依赖关系如何确定下一条指令地址（branches, exceptions）

Pipeline CPI 示例（3 条指令）：

情况 完成周期 CPI
无 stall 3 cycles 1.00
1 个 bubble 4 cycles 1.33
2 个 bubble 5 cycles 1.67

结构相关的消除

  • 方法 1：将新指令延迟到前一条指令释放资源后执行
  • 方法 2：增加新的资源（如双存储器端口、分离的指令/数据 Cache）
  • ⭐ 经典 RISC 5 段整型流水线可通过设计做到无结构相关
  • 多周期操作（multipliers, dividers, FP units）可能导致结构相关（没有多个寄存器写端口）

⭐ 三种基本数据相关

类型 名称 别名 成因 出现场景
RAW 写后读 Read After Write 真数据相关（True Dependence） 实际数据交换需求 所有流水线
WAR 读后写 Write After Read 反相关（Anti-Dependence） 重复使用寄存器名 乱序完成流水线
WAW 写后写 Write After Write 输出相关（Output Dependence） 重复使用寄存器名 乱序完成流水线

⭐ 消减数据相关的三种策略

  1. 连锁机制（Interlock）：在 issue 阶段保持当前相关指令，等待相关解除（插入 bubble）
  2. 旁路/定向路径（Bypass / Forwarding）：结果一可用就通过旁路传递数据，避免 stall
  3. 投机（Speculate）：猜测一个值继续执行，猜错再更正

Interlock vs Bypass 对比：

  • ⭐ Fully Bypassed Data Path：ALU 输入端可从 EX/MEM 和 MEM/WB 等多个阶段获取数据
    • EX/MEM → EX（EX-EX forwarding）
    • MEM/WB → EX（MEM-EX forwarding）
    • MEM/WB → MEM（MEM-MEM forwarding，用于 Store）
  • ⭐ Load-Use Hazard：Load 后紧跟使用其结果的指令，即使有旁路也无法避免 1 个 stall（数据在 MEM 结束才可用）
    • 假设 WB 阶段写入寄存器的数据在 D 阶段可并行读取（需要额外的 write data register 和 bypass path）

投机（Speculation）适用场景

  • 分支预测
  • 堆栈指针更新
  • 存储器地址消除歧义（Memory Address Disambiguation）

软件方法避免数据相关

  • 编译器通过指令调度（重排指令序列）来填充 stall 周期
  • 关键技巧：交替安排不同独立数据链的 Load/运算/Store，使数据相关指令间有足够间隔

3.3 控制相关（Control Hazards）

控制相关源于分支和跳转指令改变指令流，是流水线 CPI 上升的重要原因。

控制流信息在流水线中的获取时机

转移类型 所需信息 可用阶段
无条件直接转移 Opcode, PC, offset ID（译码阶段）
基址寄存器无条件转移 Opcode, Register value, offset EX（执行阶段）
⭐ 条件转移 Opcode, Register(条件), PC, offset EX（执行阶段）
普通指令 Opcode, PC（确认非转移） ID（译码阶段）

各类转移的 Stall 开销

转移类型 Bubble 数量 说明
无条件 PC-Relative Jump (j target) 1 个 bubble 转移地址在 ID 阶段计算完成，下一条已取指令被 kill
⭐ 条件分支 (beq x1, x2, target) 2 个 bubble 转移条件在 EX 阶段才确定，IF 和 ID 阶段取的指令都可能出错
Jump Register (jr x1) 2 个 bubble 目标地址 = x1，在 EX 阶段获得

Kill 机制：一旦确定分支方向，错误路径的指令被替换为 bubble。

⭐ 延迟槽技术（Branch Delay Slots）

  • 早期 RISC 机器使用：分支/跳转后的延迟槽中的指令总是在控制流变化之前执行
  • 语义保证：0x100 j target; 0x104 add x1,x2,x3 → add 必定在跳转前执行
  • 软件必须用有用指令或 NOP 填充延迟槽
  • Post-1990 RISC ISA 取消了延迟槽，原因：
    • NOP 增加 I-cache 失效率
    • 使先进微架构复杂化（如 4 发射 30 段流水线）
    • 好的分支预测技术减少了对延迟槽的需求

⭐ 控制相关的四种解决方法

方法 策略 说明
#1 Stall 暂停直到分支方向确定 最简单，性能最差
#2 预测分支失败（Predict Not Taken） 先执行后继指令，猜错则撤销 需保证分支结果出来前不改变处理器状态
#3 预测分支成功（Predict Taken） 先跳到目标地址，后确定是否成功 前提：先知道目标地址，后知道方向
#4 延迟转移（Delayed Branch） 填充延迟槽 已在上文讨论

CPI > 1 的原因总结

  1. 全定向路径代价过高：不常用路径可能增加时钟周期长度，得不偿失
  2. ⭐ Load 操作有两个时钟周期延迟：MIPS-I 用延迟槽（软件可见），MIPS-II 取消延迟槽改用硬件 interlock（MIPS = “Microprocessor without Interlocked Pipeline Stages”）
  3. Jumps/Branches 导致流水线断流（bubbles）

分支预测对 CPI 的影响

$$
\text{CPI}{pipeline} = 1 + p{branch} \times p_{mispredict} \times penalty
$$

控制相关策略的定量评估见 3.7 节。

3.4 陷阱与中断（Exceptions & Interrupts）

术语定义

术语 定义 来源
异常（Exception） 程序执行过程中引起的异常内部事件 内部（如 page fault, arithmetic underflow）
陷阱（Trap） 因异常情况被迫将控制权移交给监控程序 异常的子集
中断（Interrupt） 运行程序之外的外部事件导致控制权转移 外部（如 I/O 设备）
  • ⭐ 陷阱和中断通常由同样的流水线机制处理

异常处理历史

  • Univac-I (1951)：首个带 traps 的系统，算术溢出触发修复例程
  • Univac 1103 (1955)：增加外部中断机制（实时采集风洞数据）
  • DYSEAC (1954)：首个带 I/O 中断的系统（双 PC 切换），也是首个 DMA 系统

异步中断（Asynchronous Interrupts）

I/O 设备发出中断请求信号，处理器决定响应时：

  1. 执行完当前指令 Ii−1（精确中断）
  2. 将 Ii 的 PC 值保存到 EPC 寄存器
  3. 关中断，转移到监控模式的中断处理程序

中断处理程序要点：

  • 嵌套中断前需保存 EPC 到 GPRs
  • 读取状态寄存器记录中断原因
  • 使用 ERET（Return-From-Environment） 返回：开中断、恢复用户模式、恢复硬件状态

同步陷阱（Synchronous Trap）

  • 由特定指令执行异常引起
  • 指令通常无法完成，需在处理后重新启动
  • 系统调用（陷阱）视为已完成（特殊跳转指令，切换到特权模式）

⭐ 5 段流水线异常处理

各阶段可能产生的异常：

阶段 异常类型
IF Page fault, misaligned address, memory protection violation, I-cache miss
ID Undefined or illegal opcode
EX Arithmetic exception (overflow)
MEM Page fault, misaligned address, memory protection violation, D-cache miss
WB 无

处理机制：

  • Commit Point（提交点） 在 WB 阶段
  • 异常标志保留到提交阶段；同一指令早期阶段异常覆盖后续异常
  • 在提交阶段并入异步中断请求（覆盖其他异常）
  • 提交时检测到异常：更新 Cause 和 EPC 寄存器，终止所有流水段，跳转到处理程序

⭐ 异常推测（Exception Speculation）机制

异常推测是流水线处理异常的核心机制：

  1. 预测机制：预测无异常（异常概率低）
  2. 检查机制：在指令执行最后阶段检测异常
  3. 恢复机制：仅在提交阶段改变机器状态，异常后可丢弃部分执行的指令
  4. 定向路径：允许后续指令使用未提交的结果

3.5 流水线性能分析：吞吐率（Throughput）

基本度量参数

  • ⭐ 吞吐率（Throughput, TP）：单位时间内完成的任务数量
  • 加速比（Speedup, S）：见 3.6 节
  • 效率（Efficiency, E）：见 3.6 节

⭐ 1. 各段时间均相等的流水线

完成 $n$ 个任务的总时间：

$$
T_k = k\Delta t + (n-1)\Delta t = (k+n-1)\Delta t
$$

实际吞吐率：

$$
TP = \frac{n}{T_k} = \frac{n}{(k+n-1)\Delta t}
$$

最大吞吐率（连续流动稳定状态）：

$$
TP_{max} = \lim_{n\to\infty} \frac{n}{(k+n-1)\Delta t} = \frac{1}{\Delta t}
$$

  • n≫k 时，TP≈TPmax
  • 实际吞吐率恒小于最大吞吐率，还与段数 k 和任务数 n 有关

⭐ 2. 各段时间不完全相等的流水线

设 $\Delta t_i$ 为第 $i$ 段的时间（共 $k$ 段）：

$$
TP = \frac{n}{\sum_{i=1}^{k}\Delta t_i + (n-1)\max(\Delta t_1, \Delta t_2, \ldots, \Delta t_k)}
$$

$$
TP_{max} = \frac{1}{\max(\Delta t_1, \Delta t_2, \ldots, \Delta t_k)}
$$

⭐ 瓶颈段（Bottleneck Stage）

  • 流水线中时间最长的段称为瓶颈段
  • 例：4 段流水线，S1=S2=S4=Δt，S3=3Δt（瓶颈段）
    • TPmax=1/(3Δt)，远低于理想值 1/Δt

⭐ 3. 解决瓶颈的两种方法

方法一：细分瓶颈段

  • 将瓶颈段 S3（3Δt）细分为 S3a, S3b, S3c（各 Δt）
  • 改进后 TPmax=1/Δt
  • 原理：拆分组合逻辑，消除时间瓶颈

方法二：重复设置瓶颈段

  • 并行设置 S3a, S3b, S3c 三个相同段
  • 每 Δt 可以接受一个新任务进入 S3
  • 缺点：控制逻辑复杂，硬件增加
  • 原理：空间并行换取时间

3.6 流水线性能分析：加速比与效率

⭐ 加速比（Speedup）

定义：完成同样一批任务，不使用流水线所用时间 $T_s$ 与使用流水线时间 $T_k$ 之比

$$
S = \frac{T_s}{T_k}
$$

各段时间相等时

  • 顺序执行：Ts=nkΔt
  • 流水线执行：Tk=(k+n−1)Δt

$$
S = \frac{nk}{k+n-1}
$$

$$
S_{max} = \lim_{n\to\infty} \frac{nk}{k+n-1} = k
$$

  • n≫k 时，S≈k（加速比等于流水线级数）
  • 思考题：流水线段数是否越多越好？（考虑寄存器开销、hazards 增加）

各段时间不等时

$$
S = \frac{n\sum_{i=1}^{k}\Delta t_i}{\sum_{i=1}^{k}\Delta t_i + (n-1)\max(\Delta t_1, \Delta t_2, \ldots, \Delta t_k)}
$$

⭐ 效率（Efficiency）

定义：流水线设备实际使用时间与整个运行时间的比值（利用率 utilization）

各段时间相等时

  • 各段效率相同：e1=e2=⋯=ek=TknΔt=k+n−1n

$$
E = \frac{e_1 + e_2 + \cdots + e_k}{k} = \frac{kn\Delta t}{kT_k} = \frac{n}{k+n-1}
$$

$$
E_{max} = \lim_{n\to\infty} \frac{n}{k+n-1} = 1
$$

  • n≫k 时，E≈1

时空图视角：效率 = $n$ 个任务占用的时空面积 / $k$ 个段总的时空面积

各段时间不等时：

$$
E = \frac{n \cdot \sum_{i=1}^{k}\Delta t_i}{k\left[\sum_{i=1}^{k}\Delta t_i + (n-1)\max(\Delta t_1, \ldots, \Delta t_k)\right]}
$$

⭐ 三个性能参数间的核心关系

$$
E = TP \cdot \Delta t \quad \text{（效率 = 吞吐率 x 时钟周期）}
$$

$$
E = \frac{S}{k} \quad \text{（效率 = 实际加速比 / 最大加速比）}
$$

  • 当 E=1 时，S=k，实际加速比达到最大值

⭐ Pipeline Speedup 公式（含 stall）

$$
\text{CPI}_{pipelined} = \text{Ideal CPI} + \text{Average Stall Cycles per Inst}
$$

$$
\text{Speedup} = \frac{\text{Ideal CPI} \times \text{Pipeline Depth}}{\text{Ideal CPI} + \text{Pipeline Stall CPI}} \times \frac{\text{Cycle Time}{unpipelined}}{\text{Cycle Time}{pipelined}}
$$

对简单 RISC（CPI = 1）：

$$
\text{Speedup} = \frac{\text{Pipeline Depth}}{1 + \text{Pipeline Stall CPI}} \times \frac{\text{Cycle Time}{unpipelined}}{\text{Cycle Time}{pipelined}}
$$

单周期 vs 多周期 vs 流水线性能对比

单周期 多周期 流水线
CPI 1 > 1 ~1（理想情况）
时钟周期 长（= 所有段之和） 短（= 最长段） 短（= 最长段）
吞吐率 低 中 高
硬件成本 高（硬件不能复用） 低（硬件复用） 中

3.7 结构相关对性能的影响与控制相关策略定量评估

⭐ 结构相关对性能的影响

结构相关即使只增加少量 stall，对性能影响也可能超过时钟频率提升带来的收益。

核心问题：若每条指令平均访存 1.3 次，每周期只能访存 1 次 → 平均 CPI $\geq$ 1.3

Dual-port vs Single-port 实例对比：

机器 A（双端口/Harvard） 机器 B（单端口）
端口 Dual-ported memory Single-ported memory
时钟频率 基准 A 的 1.05 倍
Ideal CPI 1 1
Load 占比 — 40%
平均指令时间 Clock cycle time $(1 + 0.4 \times 1) \times \text{cc time} / 1.05 = 1.3 \times \text{cc time}$
  • 机器 B 虽然时钟快 5%，但由于结构相关，平均指令时间反而慢 30%

⭐ 分支策略效果定量评估

公式：

$$
\text{Pipeline Speedup} = \frac{\text{Pipeline Depth}}{1 + \text{Branch Frequency} \times \text{Branch Penalty}}
$$

条件+无条件分支频率 = 14%，其中 65% 改变 PC

调度策略 Branch Penalty CPI Speedup vs Unpipelined Speedup vs Stall
Stall pipeline 3 1.42 3.5 1.00
Predict taken 1 1.14 4.4 1.26
Predict not taken 1 1.09 4.5 1.29
Delayed branch 0.5 1.07 4.6 1.31

CPI 计算说明：

  • Stall: 1+3×14%=1.42
  • Predict taken: 1+1×14%×100%=1.14
  • Predict not taken: 1+1×14%×65%=1.09
  • Delayed branch: 1+0.5×14%=1.07

关键结论：

  • ⭐ 分支预测（predict not taken）性能优于 predict taken，因为 65% 条件分支不跳转
  • ⭐ 延迟分支效果最好（penalty = 0.5），但现代处理器因其他原因取消了延迟槽

3.8 多周期操作与 MIPS 扩展流水线

浮点操作无法在 1-2 个 cycle 内完成，需要在整型流水线基础上增加浮点处理能力，这引入了一系列新的挑战。

⭐ MIPS 扩展的四个功能部件

功能部件 处理操作
Integer Loads, Stores, Integer ALU, Branches
FP/Integer 乘法器 浮点数和整数乘法
FP 加法器 FP 加、减、类型转换
FP/Integer 除法器 浮点数和整数除法

⭐ Latency 与 Repeat Interval

  • 延时（Latency）：若 latency = x，则第 (x+1) 条指令可使用该结果
  • 循环间隔（Repeat/Initiation Interval）：发射相同类型操作所需的间隔周期数
功能部件 Latency Repeat Interval
Integer ALU 0 1
Data Memory (loads) 1 1
FP Add 3 1
FP Multiply 6 1
⭐ FP Divide（含 integer divide, FP sqrt） 24 25

新引入的问题

结构冲突增多

  • 非流水的 Divide 部件使 EX 段增长 24 个 cycles
  • 一个周期内可能有多个寄存器写操作（多条指令同时到达 WB）

⭐ 乱序完成（Out-of-Order Completion）带来的新相关

  • 指令可能乱序到达 WB → 出现 WAW（Write After Write）
  • 由于在 ID 段读寄存器，暂无 WAR 相关
  • ⭐ 乱序完成导致异常处理复杂化（详见 3.9 节）

RAW stall 增多

  • FP 操作延迟大（6-24 cycles），导致数据相关 stall 显著增加
  • 需要更多代价增加定向路径

解决新结构相关的方法

  • Option 1：在 ID 段跟踪写端口使用，发现冲突则暂停发射
  • Option 2：在进入 MEM/WB 时暂停冲突指令，让长延迟指令先执行

ID 段相关检测（发射前）

发射前须检查三类问题：

  1. 结构相关：循环间隔检测 + 寄存器写端口可用性
  2. RAW 相关：维护待写目的寄存器列表，不发射以待写寄存器为源的指令，插入 latency 个 stall
  3. WAW 相关：不发射目的寄存器与待写列表有冲突的指令

GPR 与 FPR 间数据传送

MOVI2FP 和 MOVFP2I 指令造成额外数据相关，也需按上述方式处理。

3.9 精确中断与非精确中断

浮点长延迟操作使精确中断的实现变得困难，这是高性能处理器设计中的关键挑战。

⭐ 精确中断（Precise Interrupt）

  • 定义：流水线可以控制使得引起异常的指令之前的指令都执行完，故障后的指令可以重新执行
  • 按照指令的逻辑序处理异常
  • 理想情况：引起故障的指令没有改变机器的状态
  • 必须保证故障指令不产生副作用

非精确中断（Imprecise Interrupt）

  • 在发现故障前，故障点后的指令已经写了结果
  • 例：ADDF 和 SUBF 在 DIVF 前完成 → 如果 DIVF 导致异常，状态已被破坏
  • 原来的 supercomputer 方法：直接忽略，按非精确处理
  • 现代计算机要求精确中断：IEEE FP 标准、虚拟存储器

⭐ 处理中断的四种方法

方法 策略 代表系统
方法 1 忽略问题，当非精确处理 早期 supercomputer
方法 2 缓存操作结果，按指令序确认 PowerPC 620, MIPS R10000
方法 3 非精确处理 + 软件修正 保存足够状态，软件仿真未完成指令
方法 4 暂停发射直到先前指令确认无异常 MIPS R2000-R4000, Pentium

方法 2 详述：缓存结果，按序提交

  • Future File（PowerPC 620, MIPS R10000）：缓存执行结果，按指令序提交
  • History File（CYBER 180/990）：尽快提交，缓存区存放原操作数，异常时回卷

方法 3 详述：非精确 + 软件修正

  • 保存所有流水线 PC 值
  • 中断返回后从最后一条已完成的指令之后开始
  • 软件仿真未完成的指令执行

⭐ 方法 4 详述：暂停发射

  • 暂停发射，直到确认先前指令可无异常完成
  • 在 EX 段前期确认（MIPS 流水线在前三个周期中确认）
  • MIPS R2000 到 R4000 以及 Pentium 使用这种方法

关键结论

  • ⭐ 精确中断对整数流水线而言实现不太困难
  • 浮点长延迟操作使精确中断实现困难（指令乱序完成）
  • 高性能机器（Alpha 21164, MIPS R10000）支持精确中断，但精确模式慢 10+ 倍，一般用于代码调试
  • IEEE FP 标准和虚拟存储器要求精确中断

3.10 MIPS R4000 深流水线与浮点操作

MIPS R4000 是深流水线（Superpipelining）设计的典型案例。

MIPS R4000 概况（1991）

  • ⭐ 64-bit 机器，主频 100-200 MHz
  • 较深的流水线（Superpipelining，级数较多）
  • 8 级整数流水线

⭐ R4000 的 8 级整数流水线

阶段 名称 功能
IF 取指前半 选择 PC 值，初始化指令 cache 访问
IS 取指后半 完成访问指令 cache
RF 译码/读寄存器 指令译码、寄存器读取、相关检测、I-cache 命中检测
EX 执行 计算有效地址、ALU 操作、分支目标地址和条件检测
DF 取数据前半 访问数据 cache 前半部分
DS 取数据后半 访问数据 cache 后半部分
TC Tag 检测 确定数据 cache 是否命中
WB 写回 Load 和 R-R 操作结果写回

⭐ 需注意的性能问题

  • Load 延迟 2 个 cycles（结果在 DS 结束时可用）：Load 与相关指令间必须有 2 条指令或 2 个 bubbles
  • 分支延迟 3 个 cycles（目标地址在 EX 后才知道）：分支与目标间需要 3 条指令或 3 个 bubbles
  • ALU 输入端有 4 个定向源：EX/DF, DF/DS, DS/TC, TC/WB

R4000 浮点操作

  • 3 个功能部件：FP Adder, FP Multiplier, FP Divider
  • 乘/除操作最后一步使用 FP Adder
  • FP 操作需要 2（negate）到 112（square root）个 cycles

8 种 FP 流水段（每种仅 1 个副本）：

Stage 功能部件 描述
U — Unpack FP numbers
S FP Adder Operand shift stage
A FP Adder Mantissa ADD stage
R FP Adder Rounding stage
E FP Multiplier Exception test stage
M FP Multiplier First stage of multiplier
N FP Multiplier Second stage of multiplier
D FP Divider Divide pipeline stage

⭐ 双精度浮点操作延迟与初始化间隔

浮点指令 延迟 初始化间隔 使用的流水段
加、减 4 3 U, S+A, A+R, R+S
乘 8 4 U, E+M, M, M, M, N, N+A, R
除 36 35 U, A, R, D^28, D+A, D+R, D+A, D+R, A, R
求平方根 112 111 U, E, (A+R)x108, A, R
取反 2 1 U, S
求绝对值 2 1 U, S
浮点比较 3 2 U, A, R

R4000 关键结论

  • ⭐ 超深流水线（8 级）虽然提高时钟频率，但增加了 Load 延迟和分支延迟
  • FP 除法延迟高达 36 cycles，初始化间隔 35（几乎完全串行）
  • FP 流水段资源共享（如乘/除最后用 Adder）导致结构相关

3.11 全章总结

流水线核心要点

  • ⭐ 流水线技术不能提高单个任务的执行效率，提高的是整个系统的吞吐率
  • 多个任务同时执行，但使用不同的资源（重叠/并发/并行）

性能分析三指标总结

指标 含义 关键公式
吞吐率 TP 单位时间完成任务数 $TP = n/[(k+n-1)\Delta t]$，$TP_{max} = 1/\Delta t$
加速比 S 流水线 vs 非流水线的速度比 $S = nk/(k+n-1)$，$S_{max}=k$
效率 E 设备利用率 $E = n/(k+n-1)$，$E_{max}=1$
关系 — $E = S/k = TP \cdot \Delta t$

流水线性能影响因素

  1. ⭐ 瓶颈段——最慢的那一段决定时钟频率
  2. 段间时间不均衡——降低加速比
  3. 装入时间和排空时间——n 较小时加速比显著降低
  4. Hazards——导致 bubble，CPI > 1

三类 Hazards 总结

类型 成因 解决方法
结构相关 资源竞争 增加资源（双端口）、stall
数据相关 RAW/WAR/WAW Bypass/Forwarding、Interlock、编译器调度、Speculation
控制相关 分支/跳转 分支预测、延迟转移、stall

⭐ 流水线友好 ISA 设计原则

  • 所有指令等长
  • 只有很少的指令格式
  • 只用 Load/Store 访问存储器

以上原则使得流水线更容易实现高效率，也是 RISC 设计哲学的核心。

3.12 公式速查表

公式 含义 应用场景
$\tau = \max(t_i)$ 时钟周期 = 最长流水段延迟 确定流水线时钟频率
$T_k = (k+n-1)\Delta t$ 完成 $n$ 个任务的总时间 各段时间相等
$TP = \dfrac{n}{(k+n-1)\Delta t}$ 实际吞吐率 各段时间相等
$TP_{max} = \dfrac{1}{\Delta t}$ 最大吞吐率 稳定连续流动
$TP = \dfrac{n}{\sum \Delta t_i + (n-1)\max(\Delta t_i)}$ 实际吞吐率 各段时间不等
$S = \dfrac{nk}{k+n-1}$ 加速比 各段时间相等
$S_{max} = k$ 最大加速比 $n \gg k$
$E = \dfrac{n}{k+n-1}$ 效率 各段时间相等
$E_{max} = 1$ 最大效率 $n \gg k$
$E = TP \cdot \Delta t = \dfrac{S}{k}$ 三指标关系 通用
$\text{CPI}_{pipe} = \text{Ideal CPI} + \text{Avg Stall}$ 含 stall 的 CPI 实际性能评估
$\text{Speedup} = \dfrac{\text{CPI}{ideal} \times \text{Depth}}{\text{CPI}{pipe}} \times \dfrac{\text{CC}{unpipe}}{\text{CC}{pipe}}$ Pipeline Speedup 考虑 stall 的加速比
$\text{Speedup} = \dfrac{\text{Depth}}{1 + f_{branch} \times p}$ 分支对加速比的影响 控制相关评估
$\text{CPI}{pipe} = 1 + p{branch} \times p_{mispredict} \times \text{penalty}$ 分支预测对 CPI 的影响 分支预测评估

Bypass/Forwarding 技术 结果一可用就通过旁路传递，避免 stall ⭐⭐⭐
Load-Use Hazard 概念 Load 后紧跟使用其结果的指令，至少 1 cycle stall ⭐⭐⭐

3.14 本章关键概念清单

  • 流水线基本原理：将任务分为 K 段重叠执行，提高吞吐率而非单任务速度
  • 同步流水线时钟周期：τ=max(ti)，由瓶颈段决定
  • 5 段流水线：IF → ID → EX → MEM → WB，每段 1 cycle
  • 结构相关（Structural Hazard）：资源冲突，通过增加资源或 stall 解决
  • RAW/WAR/WAW 三种数据相关：RAW 是真数据相关，WAR/WAW 由寄存器重名引起
  • Bypass/Forwarding：最有效的 RAW 消除手段
  • Load-Use Hazard：即使有旁路也至少 1 cycle stall
  • Interlock：硬件阻塞，等待相关解除
  • 控制相关（Control Hazard）：条件分支 2 bubbles，无条件跳转 1 bubble
  • 分支预测策略：stall / predict taken / predict not taken / delayed branch
  • 延迟槽（Branch Delay Slots）：分支后指令必定执行，现代 ISA 已取消
  • 异常与中断：异常（内部）与中断（外部），统一流水线机制处理
  • 精确中断：异常前指令完成，异常后指令可重执行
  • 异常推测机制：预测无异常 + 提交点确认 + 恢复机制
  • Commit Point：WB 阶段，在此确认异常并改变机器状态
  • 吞吐率公式：TP=n/[(k+n−1)Δt]，最大值 1/Δt
  • 加速比公式：S=nk/(k+n−1)，最大值 k
  • 效率公式：E=n/(k+n−1)，最大值 1
  • 三指标关系：E=S/k=TP⋅Δt
  • Pipeline Speedup 公式：考虑 stall 和时钟变化的加速比计算
  • 瓶颈段消除：细分瓶颈段或重复设置瓶颈段
  • 多周期 FP 操作：引入 WAW、更多 RAW stall、结构相关
  • 乱序完成：FP 操作延迟不同导致，使精确中断困难
  • 精确中断四种方法：忽略 / 缓存按序 / 非精确+软件修正 / 暂停发射
  • MIPS R4000 8 级流水线：超深流水线提高频率但增加延迟
  • 流水线友好 ISA：等长指令、少格式、Load/Store 架构
