一、MSI 协议状态追踪（完整表）— 1 道

题 1：MSI 三处理器操作序列追踪 ⭐⭐⭐

题目：3 个处理器 P1、P2、P3 共享变量 x（初值 x=0，位于内存）。各 Cache 初始对 x 均为 Invalid（I）。按下列顺序依次执行（写回 Cache + 写作废 MSI 协议，M 收到 BusRd 时迁到 S）：

请逐步追踪每个 Cache 的状态、产生的总线事务、以及数据来源（内存或某 Cache）。

考点：MSI 三态转换；BusRd / BusRdX / BusUpgr / Flush / BusWB 的语义；S→M 用 BusUpgr（不读块）与 I→M 用 BusRdX（要读块）的区别；M 收到 BusRd 时 M→S + Flush。

解答：

约定：空格表示该 Cache 无此块副本（视作 I）。”数据来源”指请求方实际取到数据的来源。

步骤 操作 P1 P2 P3 总线事务 数据来源 说明
初值 — I I I — — 各 Cache 均无副本，内存 x=0
1 P1: R(x) S I I BusRd Memory I→S，发 BusRd，无其他副本
2 P3: R(x) S I S BusRd Memory I→S；P1 在 S 不变（命中其他 cache，shared）
3 P1: W(x)=10 M I I BusRdX Memory S→M 用 BusRdX：作废 P3（S→I），P1 读块并改写
4 P2: R(x) S S I BusRd, Flush P1 cache P2 I→S 发 BusRd；P1 在 M 故 M→S 并 Flush（C2C + 更新内存）
5 P3: W(x)=20 I I M BusRdX Memory P3 I→M 发 BusRdX：作废 P2（S→I），P3 读块改写
6 P2: W(x)=30 I M I BusRdX, Flush P3 cache P2 I→M 发 BusRdX；P3 在 M 故 M→I 并 Flush（让出所有权，供 P2 读入）
7 P1: R(x) S S I BusRd, Flush P2 cache P1 I→S 发 BusRd；P2 在 M 故 M→S 并 Flush

最终状态：P1=S, P2=S, P3=I；内存 x=30；P1/P2 cache 中 x=30。

总线事务统计：BusRd ×3（步 1、2、4/7 中的读），BusRdX ×3（步 3、5、6），Flush ×3（步 4、6、7）。

注意步骤 3：P1 由 S→M。笔记给出两种写法 —— 发 BusRdX 或 BusUpgr。严格 MSI 中 S→M 可用 BusUpgr（仅作废，不读块，因为本地已有副本）；但若实现为 BusRdX 也可（多读一次无害）。下表统一采用更省的 BusUpgr 版本变体：

步骤 操作 P1 P2 P3 总线事务（BusUpgr 版） 说明
3 P1: W(x)=10 M I I BusUpgr S→M 仅作废，不读块（本地已有副本）
5 P3: W(x)=20 I I M BusRdX I→M 必须读块，用 BusRdX（不是 BusUpgr！）
6 P2: W(x)=30 I M I BusRdX, Flush I→M 用 BusRdX

要点/易错：

  1. S→M 用 BusUpgr（已有副本，不需读内存）；I→M 用 BusRdX（必须读块进来）。这是最高频考点。
  2. M 收到 BusRd ⇒ M→S 并 Flush（C2C 传送 + 更新内存）；M 收到 BusRdX/BusUpgr ⇒ M→I 并 Flush（让出所有权）。
  3. S 收到 BusRd 不变；S 收到 BusRdX/BusUpgr ⇒ S→I（被作废）。
  4. M 态连续写（同处理器）不发任何总线事务（已独占）—— 此例未出现，但要记住。
  5. Flush 与 BusWB 区别：Flush 由 BusRd/BusRdX 触发（响应其他处理器请求），BusWB 由块替换触发（主动让位）。

二、MESI / MOESI 追踪与分析 — 2 道

题 1：MESI 协议状态追踪（体现 E 态节省）⭐⭐

题目：2 个处理器 P1、P2，变量 x 初值 0，各 Cache 初始 I。MESI 协议（含 shared signal wired-OR）。操作序列：

请追踪状态，并对比：若用 MSI 协议，步骤 1-2 会产生几个总线事务？

考点：E 态进入条件（shared signal 未置位）；E→M 写无总线事务（MESI 相比 MSI 的核心收益）；shared signal 的 wired-OR 实现。

解答：

步骤 操作 P1 P2 shared 线 总线事务 说明
初值 — I I — — —
1 P1: R(x) E I 未置位 BusRd I→E：P1 发 BusRd，系统中无其他副本，shared 线未被任何 cache 置位 ⇒ 进入 E（独占干净）
2 P1: W(x)=5 M I — （无） E→M 无总线事务！ 本地独占，直接改写即可
3 P2: R(x) S S 置位（P1 响应） BusRd, Flush P2 I→S 发 BusRd；P1 在 M 故 M→S 并 Flush（供数 + 更新内存），shared 线被 P1 置位 ⇒ P2 进入 S
4 P1: W(x)=8 M I — BusUpgr S→M 用 BusUpgr：作废 P2，不读块

对比 MSI：同样序列下，步骤 1 P1 读 ⇒ I→S（BusRd）；步骤 2 P1 写 ⇒ S→M 发 BusRdX（或 BusUpgr）。即 MSI 中步骤 1-2 至少两次总线事务（BusRd + BusRdX/BusUpgr），而 MESI 中步骤 2 的 E→M 无总线事务，整个序列少一次总线事务。

要点/易错：

  1. E 态进入：PrRd 时若 shared signal 未被置位（系统中无其他副本）⇒ I→E；若被置位 ⇒ I→S。
  2. E→M 写不发总线事务（已是独占，无需作废任何人）—— 这是 MESI 最大收益。
  3. E 收到 BusRd ⇒ E→S（被分享了，不再独占）；E 收到 BusRdX/BusUpgr ⇒ E→I。
  4. shared signal 必须所有 cache 控制器可见，做成 wired-OR（任一 cache 有该块即拉高）。
  5. M 态 flush 时更新内存和请求方；若不更新内存（只给请求方）则需引入 Owned 态 → 见 MOESI。

题 2：MOESI 协议中 Owned 态分析 ⭐

题目：回答下列关于 MOESI 协议中 Owned（O）态的问题：

(a) O 态在什么情况下进入？写出至少一条进入 O 态的状态迁移。

(b) 比较 O 态与 S 态 cache 块的”数据是否与内存一致”。

© 给定场景：P1 独占修改了 x（M 态，内存陈旧），随后 P2 读 x。请分别说明在 MESI 和 MOESI 下，P1 的状态如何变化、内存是否被更新、总线事务有何不同。

考点：Owned 态语义（共享脏、唯一 owner）；O vs S 的”与内存一致性”区别；MOESI 相比 MESI 在 M 被 Read 时省一次内存写回。

解答：

(a) O 态的进入条件：当一个 Modified 块被其他处理器读共享时，该块的拥有者从 M 迁到 O（而不是 MESI 中的 M→S + 回写内存）。

典型进入迁移：

  • M 收到 BusRd ⇒ M→O（MOESI）并发 Flush 供数给请求方，但不更新内存（内存仍陈旧）。拥有者继续负责供数。
  • 此外，S 态的 cache 若其所在系统中有其他 cache 处于 O，则自身保持 S（数据可能陈旧）；若 O 态 cache 被替换或写回，所有权转移。

(b) O 与 S 的”与内存一致性”区别：

状态 是否独占 是否修改（脏） 数据与内存是否一致
O（Owned） 否（被多 cache 共享） 是（脏） 否（内存陈旧，owner 有最新值）
S（Shared） 否 视情况 不一定：若系统中存在 O 副本 ⇒ S 数据陈旧；若无 O（纯 E/S 共享）⇒ S 与内存一致

关键点：当内存数据在多个 cache 中都有副本时，有且仅有一个 cache 处于 O，其余处于 S。O 是”共享脏”，S 在有 O 存在时是”共享但数据陈旧”。

© MESI vs MOESI 对比：

MESI MOESI
P1 初始状态 M M
P2 读 x 触发 BusRd BusRd
P1 状态变化 M → S M → O
P1 是否 Flush 是（供数给 P2） 是（供数给 P2）
内存是否被更新 是（Flush 同时写回内存） 否（只供数给 P2，内存仍陈旧）
P2 状态 S S（但此时系统中存在 O，即 P1）
后续若 P3 再读 x 由内存供数（P1 已是 S，内存已最新） 由 P1（O）供数，内存仍不更新

要点/易错：

  1. O = 共享脏，是 MESI 的 M 在被读共享时”不回写内存”的产物。引入 O 的动机是：M 态 flush 时若内存慢，写回内存成为瓶颈，故让 owner 继续持有最新值、避免重复写回。
  2. O 态唯一：一个被共享的脏块只能有一个 O，其余副本都是 S。
  3. O 收到 BusRd ⇒ O（不变）+ Flush（继续供数）；O 收到 BusRdX ⇒ I + Flush（让出所有权）。
  4. 不要混淆：MESI 的 M→S（回写内存）与 MOESI 的 M→O（不回写内存）。

三、目录协议分析 — 1 道

题 1：目录协议 Read/Write Miss 响应 ⭐⭐

题目：一个 4 处理器 DSM 系统（P1-P4），每个 home 结点维护一个目录，目录项含 4 位 presence bits（每位对应一个处理器）+ 3 态状态（Uncached / Shared / Modified）。考虑一个 Cache 块 B，其 home 在 P2 结点。初始：目录项 presence bits = 0000，state = Uncached。

按以下顺序处理请求，逐步给出目录项状态变化和目录发出的消息：

考点：presence bits 含义；Read Miss / Write Miss 时目录据当前 state（Uncached/Shared/Modified）的不同响应；Single-Writer Multiple-Readers 不变式；Fetch / Fetch-Invalidate / Invalidate 消息。

解答：

记目录项为 state | presence = b1b2b3b4（bi=1 表示 Pi 有副本）。

步骤 请求 目录变化前 → 后 目录发出的消息 请求方最终状态
初值 — Uncached | 0000 — —
1 P1 Read Miss Uncached | 0000 → Shared | 1000 从 home 内存读块，发数据给 P1 P1 = S
2 P4 Read Miss Shared | 1000 → Shared | 1001 home 直接发数据给 P4（已是 Shared，无需打扰 P1） P4 = S
3 P3 Write Miss Shared | 1001 → Modified | 0010 据 presence bits 向 P1、P4 发 Invalidate；收齐 ACK 后复位 b1、b4；从内存发数据给 P3 P1=I, P4=I, P3=M
4 P1 Read Miss Modified | 0010 → Owned | 1010 home state=M：发 Fetch 给拥有者 P3；P3 Write-Back 数据（降为 S）给 home，home 发数据给 P1；置位 b1 P1=S, P3=S（home 视为 Owned，P3 视本地为 S）
5 P4 Write Miss Owned | 1010 → Modified | 0001 据 presence bits 向 P1、P3 发 Invalidate；收齐 ACK 复位 b1、b3；home 发数据给 P4；置位 b4 P1=I, P3=I, P4=M

说明：

  • 步骤 3：Write Miss 时目录当前是 Shared，必须作废所有共享者（P1、P4）才能授予 P3 独占写权。这是 Single-Writer Multiple-Readers 不变式的体现。
  • 步骤 4：目录当前是 Modified（P3 是 owner），Read Miss 需要 P3 先 Write-Back（Fetch），P3 降为 S，目录自身可记为 Owned（共享脏）。然后才把数据给 P1。
  • 步骤 5：Write Miss 时目录是 Owned（有共享者 P1、P3），需先作废它们再授予 P4。

要点/易错：

  1. Read Miss 三分支：home=Uncached（从内存取）/ Shared（直接给）/ Modified（先 Fetch 拥有者，拥有者降 S，再给请求方）。
  2. Write Miss 三分支：home=Uncached（从内存取，直接给 M）/ Shared（作废所有 sharer 再给）/ Modified（Fetch-Invalidate 拥有者，要其数据 + 作废，再给请求方 M）。
  3. presence bits 是目录协议避免广播的关键：作废只发给 presence bit=1 的处理器，而非全广播。
  4. 目录端常用 MOSI/MOESI（多 Owned 态记录共享脏拥有者），私有 cache 端用 MSI。

四、True / False Sharing — 1 道

题 1：True Sharing vs False Sharing 与 Padding ⭐⭐⭐

题目：两个变量 int a 和 int b（各 4 字节）位于同一 Cache 块（Cache 块大小 16 字节，块内布局 a@offset0, b@offset4，其余 8 字节为填充）。初始 P1、P2 都已读过 a、b，块在两 Cache 中均为 S 态。

(a) 每次循环中，P1 写 a 后 P2 读/写 b 会发生什么？属于哪种 miss？

(b) 整个 1000 次循环中，P2 因 P1 的写产生多少次 Cache miss（假设每次 P1 写都作废 P2 的整个块）？

(d) 若把 (a) 改为”P2 读 a”（而非读 b），miss 类型如何变化？

考点：True Sharing（同变量）vs False Sharing（同块不同变量）；Cache 块作废粒度；padding 对齐到块边界消除 false sharing。

解答：

(a) P1 写 a ⇒ P2 的整个 Block(a,b) 被作废（写作废协议以块为粒度）。P2 下次读/写 b 时 Cache miss。由于 P2 访问的是 b（不同于 a），且 b 的值并未改变，这次 miss 没有传递任何有用的新值，属于 False Sharing Miss。

(b) 每次 P1 写 a 都作废 P2 的块。若 P1、P2 严格交错（P1 写一次 → P2 写一次），则 P2 每次写 b 前 miss 一次 ⇒ 1000 次 false sharing miss（理论上界；实际取决于交错程度，但量级如此）。这是 false sharing 的典型危害：变量根本不冲突，却因同块而被反复作废。

padding 后，P1 写 a 只作废 a 所在块，P2 的 b 块不受影响 ⇒ false sharing miss 降为 0。

(d) 若 P2 读的是 a（与 P1 写的同一变量），则 P2 读到的是 a 的真实新值，这次 miss 确实传递了新数据 ⇒ 属于 True Sharing Miss。即便 cache 块大小为 1 个字（仅含 a），这次 miss 仍会发生。

True Sharing 是（同一变量） 是
False Sharing 否（同块不同变量） 否（块缩小到 1 字即消失）

要点/易错：

  1. 作废粒度是块，不是变量 —— 这是 false sharing 的根源。
  2. 判断 true/false sharing 只需问：“若 cache 块缩小到恰好包含一个变量，miss 是否还发生？” 是 ⇒ true；否 ⇒ false。
  3. Coherence miss（第 4 个 C）= true sharing + false sharing，几乎不随 cache 增大而改善，但随处理器数增加而上升。
  4. padding 代价是浪费空间（牺牲空间局部性），仅在确有 false sharing 时使用。

五、SC 顺序一致性判断 — 2 道

题 1：SC 合法性判断（构造全局序）⭐⭐⭐

题目：两个处理器，x、y 初值均为 0。下列执行中，括号内为读到的值：

即 P1 的读 y 读到 0，P2 的读 x 也读到 0。问：这个执行结果在 SC 下是否合法？若合法，给出一个满足程序序的全局序；若不合法，说明为何。

考点：SC 定义（存在全局序 + 程序序保持 + load 取最近 store 值）；典型 SC 反例识别。

解答：

尝试构造全局序。记程序序：P1 中 W(x)=1 <p R(y)，P2 中 W(y)=1 <p R(x)。

若存在合法 SC 全局序，必须满足：

  • W(x)=1 在 R(y) 之前（P1 程序序）；
  • W(y)=1 在 R(x) 之前（P2 程序序）；
  • R(y) 读到 0 ⇒ 全局序中 R(y) 之前没有W(y)=1；
  • R(x) 读到 0 ⇒ 全局序中 R(x) 之前没有W(x)=1。

由后两条：R(y) 在 W(y)=1 之前，R(x) 在 W(x)=1 之前。

结合程序序：

  • P2：W(y)=1 <p R(x)，又 R(x) <m W(x)=1 ⇒ W(y)=1 <m W(x)=1；
  • P1：W(x)=1 <p R(y)，又 R(y) <m W(y)=1 ⇒ W(x)=1 <m W(y)=1。

得到 W(y)=1 <m W(x)=1 且 W(x)=1 <m W(y)=1，矛盾（循环依赖）。

结论：该执行在 SC 下不合法。 这是一个经典 SC 反例：两个处理器各自的 store 还没全局可见时，对方就 load 到了旧值 0。在严格 SC 下，至少有一个 load 必须读到 1。

合法结果（参考）：SC 下合法的结果有三种 —— (r1=1,r2=0)、(r1=0,r2=1)、(r1=1,r2=1)；(r1=0,r2=0) 非法。

要点/易错：

  1. 判 SC 方法：假设存在全局序 ⇒ 推出矛盾 ⇒ 不满足 SC。
  2. 这个例子正是 store buffer / W→R 放松 导致的：store 暂停在 write buffer，load 先执行读到旧值。x86 TSO 允许此结果（W→R 被放松），所以 (0,0) 在 x86 上合法。
  3. SC 要求 store 对所有处理器原子可见（写原子性）后才能被读到。

题 2：SC 经典反例（flag 通信）⭐⭐⭐

题目：A、flag 初值 0。

程序员期望 P2 一定打印 A=1。问：

(a) 在严格 SC 下，P2 打印的结果是什么？为什么？

(b) 若处理器使用 write buffer with bypassing（store 先进 write buffer，后续 load 可绕过 store 执行），P2 可能打印什么？这违反了 SC 的哪一条序？

© 如何用 fence 保证正确性？

考点：SC 的 W→R 保序；write buffer 破坏 SC；fence 修复。

解答：

(a) SC 下 P2 一定打印 A=1。 理由：SC 保持程序序，P1 中 S(A) <p S(flag) ⇒ 全局序中 S(A) <m S(flag)。P2 读到 flag=1 ⇒ S(flag) <m L(flag)。又 L(flag) <p L(A)（P2 程序序）⇒ L(flag) <m L(A)。链起来：S(A) <m S(flag) <m L(flag) <m L(A)，故 L(A) 之前 A 已被写为 1 ⇒ 打印 1。

(b) 有 write buffer 时，P2 可能打印 A=0。 机制：P1 的 S(A)=1 停在 write buffer 未全局可见，S(flag)=1 也进 write buffer 但可能先被刷出（或 P1 的后续操作绕过它们）；更关键的是，即使 P1 正常，P2 自身若也有 write buffer 且 load 可绕过，可能出现 flag 已为 1 但 A 的写尚未对 P2 可见。这违反了 SC 的 Store → Load 保序（W→R）：P1 的 S(A) <p S(flag) 虽保持，但 P1 的 store 对外可见顺序可能被 write buffer 重排；从 P2 角度，S(flag) 可见而 S(A) 不可见，相当于 store 全局序被破坏。

更精确地说：write buffer 让 store 的”处理器本地完成”与”全局可见”分离，允许 load 绕过未全局可见的 store，从而放松 W→R。

© 用 fence：在 P1 的两条 store 之间，或在 P2 的 load 之前插入 fence。

x86（TSO）中 mfence 即可保证。fence 强制之前的 store 全局可见后，之后的 load/store 才能执行。

要点/易错：

  1. SC 破坏的三个常见优化：write buffer（放松 W→R）、overlapping writes（破坏 W→W 全局序）、non-blocking reads（放松 R→R、R→W）。本题属第一种。
  2. x86 是 TSO，放松 W→R，所以不加 fence 时 P2 可能打印 0 —— 这就是为什么写无锁代码必须配对 fence / 用 atomic 带 acquire-release 语义。
  3. SC 要求 store 原子性全局可见（一个 store 要么所有处理器都看不到，要么都看到），write buffer 破坏了这一点。

六、Amdahl / 远程访问 CPI — 1 道

题 1：Amdahl 定律 + 远程访问 CPI ⭐⭐⭐

题目：

(1) 想用 100 个处理器达到 80 倍加速比，求原程序中并行部分所占比例 p（即串行部分比例）。

(2) 某多处理机有 32 个处理器，处理器时钟周期 10 ns，基本 CPI=1.0（所有访存命中 Cache）。远程访问一次需 2000 ns，有 0.5% 的指令触发远程访问（远程请求时本处理器挂起）。求有/无远程访问两种情况的速度比。

考点：Amdahl 加速比公式；含远程访问的 CPI 计算；两个必背数值（0.25%、CPI=2.0）。

解答：

(1) Amdahl 反求 p：

$$
\text{Speedup} = \frac{1}{\dfrac{p}{N} + (1-p)} = 80, \quad N = 100
$$

$$
\frac{1}{\dfrac{p}{100} + (1-p)} = 80 ;\Rightarrow; \frac{p}{100} + 1 - p = \frac{1}{80} = 0.0125
$$

$$
1 - p\left(1 - \frac{1}{100}\right) = 0.0125 ;\Rightarrow; 1 - 0.99p = 0.0125
$$

$$
0.99p = 0.9875 ;\Rightarrow; p = \frac{0.9875}{0.99} = 0.99747\ldots \approx 0.9975
$$

并行比例 p ≈ 99.75%，串行比例 ≈ 0.25%。即程序中仅有 0.25% 的串行部分时，100 核才能达到 80 倍加速。这说明大规模并行对串行部分极其敏感。

（验证：p/100 = 0.009975，1−p = 0.0025，和 = 0.012475 ≈ 1/80，Speedup ≈ 80.16 ✓）

(2) 远程访问 CPI：

远程访问开销（周期数）：

$$
\text{远程开销} = \frac{2000,\text{ns}}{10,\text{ns}} = 200,\text{cycles}
$$

有远程访问时的 CPI：

$$
\text{CPI}{\text{remote}} = \text{CPI}{\text{base}} + \text{远程率} \times \text{远程开销}
= 1.0 + 0.5% \times 200 = 1.0 + 1.0 = \mathbf{2.0}
$$

速度比：

$$
\frac{\text{CPI}{\text{remote}}}{\text{CPI}{\text{no-remote}}} = \frac{2.0}{1.0} = 2
$$

无远程访问的机器是有远程访问机器的 2 倍快。即便只有 0.5% 的指令触发远程访问，CPI 也翻倍 —— 通信延迟对性能杀伤极大。

要点/易错：

  1. 两个必背数值：100 核 80 加速 ⇒ 串行 0.25%；0.5%×200 ⇒ CPI=2.0。
  2. Amdahl 公式中分母是 p/N + (1-p)，别把 p 和 (1−p) 写反。
  3. 远程开销要换算成周期数（时间 ÷ 时钟周期），再乘以远程率（概率）累加到 CPI。
  4. Amdahl 的极限：N→∞ 时 Speedup_max = 1/(1−p)，即受串行部分封顶。

七、松弛模型 + 同步原语概念题 — 3 道

题 1：松弛一致性模型辨析 ⭐⭐⭐

题目：填表并回答：

(a) 完成下表，标出各松弛模型保留和放松的序（R→R, R→W, W→R, W→W），并写出典型架构。

(b) 为什么”所有松弛模型都至少保证对同一存储单元访问的 W→R 和 W→W 程序序”？

© x86 程序员写无锁代码时最需要注意哪条被放松的序？

考点：SC/TSO/PSO/RMO/WO/RC 的放松序归属；同址保序的必要性；x86=TSO 放松 W→R。

解答：

(a) 松弛模型对照表（✓=保留，✗=放松）：

模型 R→R R→W W→R W→W 典型架构 放松的序
SC ✓ ✓ ✓ ✓ 理论模型 无
TSO ✓ ✓ ✗ ✓ x86 W→R
PSO ✓ ✓ ✗ ✗ SPARC V8 W→R, W→W
RMO ✗ ✗ ✗ ✗（仅同址） SPARC V9 除同址外全部
WO 同步操作保序，普通 R/W 乱序 — PowerPC 普通操作的 R→W、R→R 等
RC 仅 acquire/release 间保序 — — 比 WO 更细粒度

(b) 若不保证同址 W→R 和 W→W，处理器可能读到自己刚写的旧值或看到自己写的乱序 —— 这破坏了最基本的”单处理器顺序执行”直觉（也破坏一致性）。因此所有模型都保留同址的 W→R 和 W→W。差异只在于不同地址操作的乱序许可度。

© x86 是 TSO，放松 W→R。程序员最需注意：一个 store 后紧跟的 load（不同地址）可能读到旧值（store 还在 write buffer）。写无锁代码（如 Dekker 互斥、发布数据 + flag）时，store 数据和 store flag 之间、或读 flag 后读数据，需插入 mfence 或使用带 acquire/release 语义的 atomic 操作。

要点/易错：

  1. SC=全保序，TSO=放松 W→R（x86），RMO=除同址外全放松（SPARC V9），WO/RC=仅同步保序（PowerPC）。
  2. PSO 在 TSO 基础上又放松 W→W（SPARC V8）。
  3. 别记反：TSO 放松的是 W→R（store→load），不是 R→W。
  4. 各架构 fence 指令：x86=mfence，ARM=DMB，PowerPC=Sync/EIEIO，SPARC V9=Membar #LoadLoad 等（细粒度）。

题 2：同步原语概念 ⭐⭐

题目：简答下列关于同步原语的问题：

(a) 给出 Acquire 语义和 Release 语义的定义，并说明它们如何保护临界区。

(b) Test&Set、Compare&Swap(CAS)、Load-Linked/Store-Conditional(LL-SC) 各自的语义？哪些是阻塞型、哪些是非阻塞型？

© 用 exchange 指令实现一个自旋锁（spinlock），并指出其在高竞争下的性能问题。

(d) Fence 指令的作用是什么？为什么不能滥用？

考点：Acquire/Release 语义；原子 RMW 指令族；自旋锁实现；fence 的代价。

解答：

(a) Acquire / Release 语义：

  • Acquire 语义：acquire 操作（如 lock）之后的读/写不能重排到 acquire 之前。保证进入临界区后，临界区内的操作不会跑到锁获取之前（避免看到未受保护的共享状态）。
  • Release 语义：release 操作（如 unlock）之前的读/写不能重排到 release 之后。保证临界区内的操作在锁释放前都已完成（让下一个获取者看到最新值）。

二者共同保护临界区：acquire 筑起”入口屏障”，release 筑起”出口屏障”，确保临界区内操作不被重排出区。

(b) 原子 RMW 指令：

指令 语义 类型
Test&Set(m), R R←M[m]；若 R==0 则 M[m]←1 阻塞型（自旋等待）
Compare&Swap(m), Rt, Rs 若 Rt==M[m] 则 M[m]←Rs（成功）；否则失败返回当前值 非阻塞型（失败可重试，无锁推进）
LL-SC LL 读出 m 并标记；SC 仅当标记未被无效化才写成功 非阻塞型（SC 失败重试）
  • 阻塞型：Test&Set、Fetch&Add、Swap、exchange —— 在锁竞争下自旋，高竞争时产生总线风暴（bus traffic storm）。
  • 非阻塞型：CAS、LL-SC —— 无锁推进（lock-free），失败则重试，竞争下仍能前进。

© exchange 实现自旋锁：

高竞争下问题：每次 exchange 都是对 S 的原子 RMW，会作废其他 cache 的 S 副本并产生总线事务。N 个处理器同时自旋 ⇒ 总线风暴（bus/ping-pong traffic），总线带宽被耗尽，性能急剧下降。改进：Test-and-Test&Set（先普通 load 自旋等 S=0，再 Test&Set），或用排队锁（ticket lock / MCS lock）。

(d) Fence 作用：

  • Fence（Memory Barrier）强制某些存储器操作串行化：fence 之前的 load/store 必须在 fence 之后的 load/store 开始前完成（全局可见）。
  • 用于在松弛一致性模型下恢复 SC 语义的局部保证（如保护发布-等待模式、临界区）。
  • 不能滥用：fence 代价高（要排空 write buffer、等待未完成的 store/load、阻止乱序），频繁使用会严重降低性能。只在确实需要保序处（临界区边界、发布数据后、读 flag 前）使用。

要点/易错：

  1. Acquire 管”之后的不能往前”，Release 管”之前的不能往后” —— 方向别记反。
  2. CAS 和 LL-SC 是非阻塞的（失败重试），Test&Set/Swap 是阻塞的（自旋）。
  3. 自旋锁在高竞争下性能差根因：每次 RMW 作废所有副本 + 总线广播。
  4. 各架构 fence：x86=mfence，ARM=DMB，PowerPC=Sync，SPARC V9=Membar #LoadLoad/#StoreStore/…。

题 3：Dekker 算法在 TSO 下为何失效 ⭐⭐

题目：Dekker 互斥算法（2 进程版）核心：

(a) 在严格 SC 下，Dekker 算法能否保证互斥？简述理由。

(b) 在 x86 TSO（放松 W→R）下，Dekker 算法可能失效（两进程同时进入临界区）。解释 store buffer 如何导致这一结果。

© 如何修复（加 fence）？

考点：SC vs TSO 的 W→R 差异；store buffer 破坏 Dekker；StoreLoad fence 修复。

解答：

(a) SC 下保证互斥。 SC 保持程序序：P1 中 S(flag1)=1 <p L(flag2)，P2 中 S(flag2)=1 <p L(flag1)。若两者都进入临界区，则 P1 的 L(flag2) 必读到 0（跳出循环），意味着 P2 还没执行 S(flag2)=1；但 P1 已执行 S(flag1)=1，由程序序 P2 的 S(flag2)=1 <p L(flag1)，P2 的 L(flag1) 会读到 P1 设的 1 ⇒ P2 不会跳出循环。矛盾。故 SC 下互斥成立。

(b) TSO 下失效。 TSO 放松 W→R：S(flag1)=1 停在 P1 的 write buffer 中尚未全局可见，P1 紧接着的 L(flag2) 可绕过该 store 直接执行。同理 P2 的 S(flag2)=1 也停在 P2 的 write buffer，P2 的 L(flag1) 绕过执行。结果：P1 读 flag2 读到 0（P2 的 flag2 还没刷出），P2 读 flag1 读到 0（P1 的 flag1 还没刷出）⇒ 两者都跳出循环，同时进入临界区，互斥被破坏。

时序示意：

© 修复：在 store 和随后的 load 之间插入 StoreLoad fence，强制 store 全局可见后再 load。

x86 的 mfence（或 lock 前缀指令、xchg）即提供 StoreLoad 屏障。加 fence 后，flag1 全局可见 ⇒ P2 必能读到 ⇒ 互斥恢复。

要点/易错：

  1. Dekker / Peterson 这类纯 Load/Store 互斥算法依赖 SC，在 TSO 及更弱的模型下会失效。
  2. 根因是 store buffer + W→R 放松：store 未全局可见，load 先执行读到旧值。
  3. 修复一律是 StoreLoad fence（x86 的 mfence / lock / xchg）。
  4. 现代架构上更推荐用硬件原子指令（CAS / LL-SC 带-acquire/-release）实现锁，而非 Dekker 类软件算法。
