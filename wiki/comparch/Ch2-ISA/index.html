2.1 ISA 的定义与特性

什么是 ISA？

  • 软件子系统与硬件子系统的关键界面
  • 一组直接由硬件执行的指令，包括：
    • 程序员可见的机器状态（寄存器、存储器等）
    • 程序员可见的指令集合（操作机器状态的指令）

ISA 应具备的六大特性

特性 说明
成本 实现代价低
简洁性 易于理解和实现
架构与实现分离 可持续多代，保持向后 (backward) 兼容
可扩展空间 可用于不同应用领域（desktop / server / embedded）
易编程/编译/链接 为高层软件提供方便的功能
性能 方便低层硬件子系统高效实现

⭐ IBM 360 的历史意义

  • 第一个将 ISA 与实现分离的系列机
  • 现代延续：
    • x86-64：Intel / AMD 多家公司实现同一 ISA
    • ARM：TI、Qualcomm、Samsung、Marvell 等公司实现同一 ISA

2.2 用户级 ISA vs 特权级 ISA

两个重要的系统界面

界面 全称 说明
ISA Instruction Set Architecture 用户级 ISA + 特权级 ISA
ABI Application Binary Interface 二进制兼容的接口标准

用户级 ISA vs 特权级 ISA

  • 用户级 ISA：适用于操作系统和应用程序
  • 特权级 ISA：适用于硬件资源的管理（操作系统），如 RISC-V 的 hardware thread

关键点：ISA 界面 = 用户级 ISA + 特权级 ISA

2.3 ISA 的实现方式

ISA 通常设计时会考虑特定的微体系结构（实现）方式，但 ISA 理论上可以用任何微体系结构方式实现。

实现方式 特点 示例
Accumulator 硬连线 (hardwired)、无流水线 早期机器
CISC 微程序实现 (microcoded) x86
RISC 硬布线、流水线 (hardwired, pipelined) ARM, RISC-V, MIPS
VLIW 固定延时、顺序执行、多流水线并行 IA-64 (Itanium)
JVM 软件解释执行 (software interpretation) Java 虚拟机

⭐ 实例：ISA 可用不同方式实现

ISA 微架构实现
x86 (Intel Ivy Bridge) 硬布线流水线的 CISC 机器（带部分微码支持）
SPARC 软件解释 (Simics)
JVM 硬件 JVM 处理器 (ARM Jazelle)
RISC-V 多种实现方式均可

2.4 存储器寻址

基本概念

  • Memory 被视为一个大的一维数组，地址即为数组索引
  • 80 年以来几乎所有机器的存储器都是按字节编址
  • 一个存储器地址可以访问：一个字节、2 字节、4 字节、更多字节

字的定义

  • 不同体系结构对 字 (word) 的定义不同：
    • 16 位字：Intel x86
    • 32 位字：MIPS

2.4.1 字节序 (Endian)

Little Endian vs Big Endian：一个字内部字节的存放顺序

字节序 字地址对应位置 代表
Big Endian 最左边字节是字地址 IBM 360/370, Motorola 68k, MIPS, SPARC, HP PA
Little Endian 最右边字节是字地址 Intel 80x86, DEC Vax, DEC Alpha (Windows NT)

示例：地址 xxx00 指定一个字 (int)，存储器从 xxx00 处连续存放 ffff0000

字节序 xxx00 xxx01 xxx02 xxx03
Little Endian 00 00 ff ff（最低字节在前）
Big Endian ff ff 00 00（最高字节在前）

2.4.2 对齐问题 (Alignment)

定义：对 s 字节的对象，如果访问地址 A mod s = 0，则称为边界对齐。

为什么要对齐？

  • 存储器本身读写通常是边界对齐的
  • 非边界对齐的访问可能需要两次存储器访问 + 拼接（或发生异常）

示例：

  • 4 字节 (32 位) 字：地址必须是 4 的倍数（末 2 位为 00）
  • 8 字节 (64 位) 双字：地址必须是 8 的倍数（末 3 位为 000）

2.5 寻址方式 (Addressing Modes)

定义

  • 寻址方式：如何说明要访问的对象地址
  • 有效地址 (Effective Address)：由寻址方式确定的某一存储单元的实际存储器地址

5 种基本寻址方式

寻址方式 说明 示例 (MIPS)
1. 寄存器寻址 操作数在寄存器中 ADD rd, rs, rt
2. 偏移寻址 (Base/Displacement) 寄存器值 + 偏移量 → 有效地址 LW rt, offset(rs)
3. 立即寻址 操作数在指令中 ADDI rt, rs, imm
4. PC 相对寻址 PC + 偏移量 → 分支目标 BEQZ R4, name
5. 伪直接寻址 (Pseudo-direct) 指令中 26 位偏移 + PC → 跳转目标 J name

⭐ 寻址方式使用频率统计 (SPEC89，VAX)

  • 偏移寻址：使用最多（~40%+）
  • 立即寻址：~15-20%
  • 寄存器间接寻址：~10-15%
  • 偏移寻址 + 立即寻址 + 寄存器间址 的使用频度达到 75%–99%

⭐ 偏移字段和立即数字段的大小选择

字段 建议大小 可满足的需求
偏移字段 12–16 bits 75%–99%
立即数字段 8–16 bits 50%–80%

设计原则：更小的字段 → 指令编码更紧凑，但可能不满足某些需求

立即数大小的分布

  • 小常数是最常见的
  • Alpha 架构 SPEC CPU2000 测试：
    • 整数程序 (CINT2000)：约 20% 的立即数为负
    • 浮点程序 (CFP2000)：约 30% 的立即数为负
    • VAX（支持 32 位立即数）：约 20%-25% 的立即数超过 16 位

2.6 操作数的类型、表示和大小

操作数类型与表示

  • 操作数类型和操作数表示是软硬件的主要界面之一
  • 操作数类型（面向应用/软件的数据类型）：
    • 整型、浮点型、字符、字符串、向量类型等
    • 操作数类型由操作码确定
  • 操作数表示（硬件能识别的格式）：
    • 整型：原码、反码、补码 (2’s complement)
    • 浮点：IEEE 754 标准
    • 十进制：BCD 码 / 二进制十进制表示

常用操作数大小

类型 大小 说明
ASCII character 1 byte (8 bits) 64 位寄存器可存 8 个字符
Unicode / Short integer 2 bytes = 16 bits 半字 (half word)
Integer 4 bytes = 32 bits 字 (word)，多数 RISC 的字长
Single-precision float 4 bytes = 32 bits 字
Long integer 8 bytes = 64 bits 双字 (double word)
Double-precision float 8 bytes = 64 bits 双字
Extended-precision float 10 bytes = 80 bits Intel 专用
Quad-precision float 16 bytes = 128 bits

基准测试结论：

  • 对单字 (32 位)、双字 (64 位) 的数据访问具有较高的频率
  • 支持 64 位双字操作更具一般性

MIPS 的数据表示

  • 整数：字节 (8 位) / 半字 (16 位) / 字 (32 位) / 双字 (64 位)
  • 浮点数：单精度 (32 位) / 双精度 (64 位)
  • 字节/半字/字装入 32/64 位寄存器时：
    • 零扩展 或 符号位扩展 填充剩余部分
    • 装入后按 32/64 位整数运算

2.7 操作类型

操作类型分类

类型 包含操作
算术运算 整数算术 + 浮点算术
逻辑运算 AND, OR, XOR, 移位等
数据传送 Load, Store, Move
控制转移 条件分支、跳转、过程调用/返回
系统操作 系统调用、特权操作
字符串/十进制 部分机器支持
图形/多媒体 部分机器支持，SIMD 扩展

前三类操作几乎所有计算机都支持；后四类各机器支持程度差别很大

⭐ x86 Top 10 指令使用频率

排名 指令 占比
1 load 22%
2 conditional branch 20%
3 compare 16%
4 store 12%
5 add 8%
6 and 6%
7 sub 5%
8 move register-register 4%
9 call 1%
10 return 1%
合计 96%

结论：简单指令主导指令频率 (Simple instructions dominate instruction frequency)

ISA 对操作类型的选择原则

原则 说明
完整性 具备基本指令种类
规整性 所有运算部件能在所有数据存储单元间操作；对所有数据存储单元同等对待
正交性 数据类型独立于寻址方式；寻址方式独立于操作
高效率 指令执行速度快、使用频度高
兼容性 系列机保持兼容

2.8 控制流指令

四种控制流改变类型

类型 说明 使用频率
条件分支 (Conditional Branch) 满足条件时转移 最高 (~75%+)
跳转 (Jump) 无条件转移 较低
过程调用 (Call) 保存返回地址，跳转 较低
过程返回 (Return) 恢复返回地址 较低

Conditional branches dominate（条件分支占主导地位）

控制流指令中的寻址方式

  1. PC-relative 方式（相对寻址）
  • 例如：条件转移
  • shorter offsets 最常见（SPEC 测试表明大部分分支目标在附近）
  1. 寄存器间接跳转（用于编译时不知道目标地址的情况）
  • Case / switch 语句
  • 虚函数 (Virtual function)
  • 高阶函数 (Higher-order functions)
  • 函数指针 (Function pointers)
  • 动态共享库 (Dynamically shared libraries)

分支条件类型

条件类型 使用频率
小于 (Less than / Less or equal) 最高
等于 (Equal) 中等
大于 (Greater than) 较低
其他 很低

Less than (or equal) conditions dominate（小于条件占主导）

分支目标地址与当前指令的距离

  • SPEC CPU2000 测试 (Alpha)：shorter offsets 最常见
  • 大部分分支跳转距离很短

2.9 指令编码

三种编码方式

编码方式 优点 缺点 代表
变长 (Variable) 代码密度高，编码效率高 译码复杂，不利于流水线 x86 (1–15 字节)
定长 (Fixed) 译码简单，流水线友好 代码密度较低 MIPS (32 位), RISC-V (基础 32 位)
混合 (Hybrid) 兼顾两者 译码稍复杂 ARM (Thumb + ARM), RISC-V (RV32C 压缩扩展)

编码选择策略

  • 代码规模最重要 → 使用变长指令格式
  • 性能至关重要 → 使用固定长度指令
  • 有些嵌入式 CPU 附加可选模式（性能 vs 代码量）
    • RISC-V 的 RV32IC（C = 压缩扩展）
    • ARM Thumb / microMIPS
  • 有些机器使用边执行边解压的方式（如 IBM CodePack PowerPC）

2.10 MIPS 指令格式

MIPS 寄存器

整数寄存器 (GPRs)：32 个 64 位通用寄存器 (R0–R31)

  • R0 的值永远是 0（$zero）
  • 约定命名（部分）：
编号 名称 用途
$0 $zero 常数 0
$v0–$v1 expression evaluation 函数返回值
$a0–$a3 arguments 函数参数
$t0–$t9 temporary 临时寄存器，caller saves
$s0–$s7 callee saves 被调用者保存
$gp global pointer 全局区域指针
$sp stack pointer 栈指针
$fp frame pointer 帧指针
$ra return address 返回地址

浮点寄存器 (FPRs)：32 个 64 位

  • 可存 32 个单精度 (32 位) 或 32 个双精度 (64 位)
  • 单精度时只用到一半

MIPS 三种指令格式（32 位固定长度）

R-type（寄存器-寄存器操作）

  • ALU 指令、专用寄存器读/写、寄存器跳转、move 指令
  • 操作：Regs[rd] ← Regs[rs] funct Regs[rt]
  • funct 字段指定具体运算

I-type（立即数 / Load / Store / 分支）

  • Load：有效地址 = Regs[rs] + immediate，从存储器取数据到 rt
  • Store：有效地址 = Regs[rs] + immediate，将 rt 的值存入存储器
  • 立即数指令：Regs[rt] ← Regs[rs] op immediate
  • 分支指令：转移目标 = PC + 4 + 4 × immediate

J-type（跳转）

  • 跳转指令、跳转并链接、自陷、异常返回
  • 指令字低 26 位是偏移量，与 PC 值组合形成跳转地址

MIPS 控制类指令

指令 名称 含义
J name 跳转 PC[36…63] ← name << 2
JAL name 跳转并链接 Regs[R31] ← PC+4; PC ← name<<2
JALR R3 寄存器跳转并链接 Regs[R31] ← PC+4; PC ← Regs[R3]
JR R5 寄存器跳转 PC ← Regs[R5]
BEQZ R4, name 等于零时分支 if (Regs[R4]==0) PC ← name
BNE R3, R4, name 不相等时分支 if (Regs[R3]!=Regs[R4]) PC ← name
MOVZ R1, R2, R3 等于零时移动 if (Regs[R3]==0) Regs[R1] ← Regs[R2]

MIPS 的主要特征

  • Load/Store 型结构：只有专门的 Load/Store 指令访问存储器
  • ALU 指令操作数来自寄存器或立即数
  • 降低指令集和硬件的复杂性，依赖优化编译技术
  • 最初仅 58 条指令 → 逐步增加到约 400 条

⭐ MIPS 的缺陷

缺陷 说明
过度针对 5 级流水线优化 延迟转移 (delayed branch) 导致超标量实现困难
位置无关代码 (PIC) 支持不足 直接跳转无 PC 相对寻址，需间接跳转实现 PIC
16 位立即数消耗编码空间 仅 1/64 的编码空间可供扩展
乘除使用 HI/LO 特殊寄存器 增加上下文切换开销、代码尺寸
浮点假设为独立协处理器 整型/浮点转换需额外 mov 指令
非开放专属 ISA 不能自由使用

2.11 CISC vs RISC

CISC 设计思想

目标：强化指令功能，减少运行的指令条数，提高系统性能

方法：

  1. 面向目标程序的优化
  • 统计分析目标程序执行情况
  • 找出使用频度高、执行时间长的指令串
  • 优化使用频度高的指令
  • 用新指令替代使用频度高的指令串

优化途径：

  • 增强运算型指令（如 sin(x), cos(x), SQRT(X)）
  • 增强数据传送类指令（数据块传送，支持向量/矩阵运算）
  • 增强程序控制指令
  1. 面向高级语言和编译器的优化
  • 缩小高级语言 (HL) 与机器语言 (ML) 之间的差距
  • 统计源程序中各种语句的使用频度
  • 增强相关指令功能，增加专门指令
  1. 高级语言计算机系统
  • 极端情况：HL 和 ML 合二为一（如 LISP 机、PROLOG 机）

RISC 设计思想

目标：通过简化指令系统，用高效方法实现最常用指令

方法：充分发挥流水线的效率，降低（优化）CPI

核心原则：减少指令平均执行周期数 CPI 是 RISC 思想的精华

RISC 的特点

特点 说明
大多数指令在单周期内完成 简化指令功能
Load/Store 结构 只有 Load/Store 访存
硬布线控制逻辑 不用微程序
减少指令和寻址方式的种类 简化译码
固定指令格式 流水线友好
面向寄存器结构 减少访存
重视流水线执行效率 尽量减少断流
重视优化编译技术 软件配合

⭐ RISC 为什么快？

$$
ExecuteTime = IC \times CPI \times T
$$

指标 CISC RISC 原因
IC (指令条数) 1 1.3–1.4 RISC 的 IC 仅比 CISC 多 30%–40%
CPI 2–15 (实际 4–6) 1.1–1.4 (理想 CPI≈1) RISC 通过流水线大幅降低 CPI
T (时钟周期) 33ns–5ns 10ns–2ns RISC 硬布线逻辑，功能简单，时钟快

RISC 降低 CPI 的方法：

  • 硬件方面：硬布线控制、减少指令种类、固定格式、Load/Store、多级流水线
  • 软件方面：优化编译技术

2.12 各类 ISA 实例与评价

MIPS

  • Stanford 1980 年提出，受 IBM 801 影响
  • 第一个商业实现 R2000 (1986)
  • 典型的 RISC ISA，Load/Store 结构
  • 主要缺陷：过度优化 5 级流水线、PIC 支持不足、编码空间不足

SPARC (Scalable Processor Architecture)

  • Sun Microsystems 专属 ISA，源自 Berkeley RISC-I/II
  • SPARC V8 (1990)：用户级 90 条整型指令 + 50 条浮点 + 20 条特权指令
  • 主要缺陷：
    • 寄存器窗口 (Register Windows)：消耗面积和功耗大
    • 使用条件码：增加依赖关系，使实现复杂化
    • Load/Store 相邻寄存器对指令：使寄存器重命名复杂化
    • 非精确浮点异常
    • 缺乏位置无关寻址和足够编码空间

Alpha (DEC)

  • DEC 90 年代初定义的 RISC ISA
  • 摒弃了分支延迟、条件码、寄存器窗口等当时流行的特性
  • 64 位寻址、设计简洁、高性能
  • 主要缺陷：
    • 避免了 8/16 位 Load/Store（字寻址内存系统），后续添加特殊指令弥补
    • 非精确浮点陷阱模型
    • 缺少整数除法指令（建议软件牛顿迭代法）→ 浮点除法比整数除法快
    • 无足够操作码空间支持压缩扩展
    • 包含有条件移动 (conditional move)，使寄存器重命名复杂化
    • 商业风险：被 Intel 收购后逐步淘汰

ARMv7 (32 位)

  • 世界上使用最广的体系结构
  • 封闭标准，不允许剪裁/扩充
  • 整型指令 600+ 条
  • 主要缺陷：
    • 不支持 64 位地址（ARMv8 修正）
    • 特权结构渗透到用户级
    • Thumb 压缩 ISA 性能差
    • Thumb-2 有三种编码格式，译码复杂
    • PC 可寻址（几乎任何指令可改变控制流）——非常危险
    • 分支使用条件码 + 谓词指令

ARMv8

  • 2011 年发布，64 位地址、32 位指令
  • 摒弃了 PC 可直接访问、谓词指令、load-multiple/store-multiple
  • 指令编码归一化
  • 主要缺陷：
    • 仍使用条件码（比 ARMv7 少）
    • 大量特殊寄存器
    • 大量 subword-SIMD 扩展 → 指令集厚重（1070 条指令，53 种格式，8 种寻址方式，说明文档 5778 页）
    • 用户和特权架构紧密耦合
    • 不再支持压缩指令编码
    • 仍是封闭标准

OpenRISC

  • 开源处理器设计项目，源自 Hennessy & Patterson 教科书
  • 主要缺陷：
    • ISA 和实现紧密耦合（非纯 ISA 规范）
    • 固定 32 位编码阻碍压缩扩展
    • 延迟插槽 (Delay slots)
    • 64 位版本从未真正实现

80x86

  • 过去 40 年最流行的 ISA（笔记本/台式/服务器）
  • 流行原因：IBM PC 诞生之初的可用性、二进制兼容性、微结构实现、制造技术
  • 指令集设计质量并不是它流行的原因之一
  • 主要缺陷：
    • 1300 条指令，多种寻址方式，大量特殊寄存器
    • 所有乱序执行实现都动态翻译为内部 RISC 风格指令
    • 不利于虚拟化（特权指令在用户模式无声失败）
    • 指令长度任意 1–15 字节
    • 寄存器组数量极少，大多数执行特殊功能
    • 隐式条件码、谓词移动操作使微架构实现复杂
    • 专有指令集

特性 MIPS SPARC Alpha ARMv7 ARMv8 OpenRISC x86
开放免费 ✓ ✓
64 位地址 ✓ ✓ ✓ ✓ ✓ ✓
压缩指令 ✓ ✓ 部分
特权/用户分离 ✓

2.13 RISC-V ISA

设计理念

RISC-V 是 UC Berkeley 设计的第 5 代 RISC 指令集，设计目标是通用的 ISA：

  1. 适应从最袖珍的嵌入式控制器到最快的高性能计算机等各种规模处理器
  2. 兼容各种流行的软件栈和编程语言
  3. 适应所有实现技术（FPGA、ASIC、全定制芯片、未来技术）
  4. 对所有微体系结构实现方式都有效（微编码/硬连线、顺序/乱序、单发射/超标量）
  5. 支持广泛的定制化（加速器基础，应对摩尔定律消退）
  6. 基础 ISA 稳定，不会被弃用
  7. 完全开源（BSD 协议，允许企业自由使用并添加自有指令）

技术目标

目标 说明
基础 ISA + 可选扩展 RV32I / RV64I 是基础，可扩展
方便定制 ISA 扩展 紧耦合功能单元 + 松耦合协处理器
支持变长指令扩展 提高代码密度 + 扩展自定义 ISA
用户级/特权级正交 ABI 兼容 + 允许虚拟化 + 特权级实验
支持 32/64 位地址空间

RISC-V 子集命名约定

  • RV32I：32 位基础整数指令集
  • RV64I：64 位基础整数指令集
  • 扩展后缀：M (乘除), A (原子), F (单精度浮点), D (双精度浮点), C (压缩)

RV32I 处理器状态

  • 32 × 32-bit 整数寄存器 (x0–x31)
    • x0 总是 0
    • 其他寄存器通用，但有 software convention

⭐ RISC-V 指令格式 (RV32I)

支持变长指令：

  • 基础指令集 (RV32) 固定 32-bit（最低 2 位 = 11）
  • 条件/无条件转移地址 16-bit 对齐

RV32I 六种指令格式

格式 用途 结构
R-type 寄存器-寄存器操作 opcode[7] + rd[5] + funct3[3] + rs1[5] + rs2[5] + funct7[7]
I-type 立即数操作 / Load / 间接跳转 opcode[7] + rd[5] + funct3[3] + rs1[5] + imm[12]
S-type Store opcode[7] + imm[7] + funct3[3] + rs1[5] + rs2[5] + imm[5]
B-type 条件分支 opcode[7] + imm[1] + funct3[3] + rs1[5] + rs2[5] + imm[4] + opcode2
U-type 大立即数 opcode[7] + rd[5] + imm[31]
J-type 无条件跳转 (JAL) opcode[7] + rd[5] + imm[20]

RV32I 主要指令

R-type (寄存器-寄存器)

  • ADD, SUB：加减法
  • SLT, SLTU：有符号/无符号比较，小于则置 1
  • AND, OR, XOR：位逻辑操作
  • SLL, SRL, SRA：逻辑左移、逻辑右移、算术右移

I-type (立即数)

  • ADDI rd, rs1, imm：加立即数（ADDI rd, rs1, 0 实现 MV rd, rs1）
  • SLLI, SRLI, SRAI：移位常量（编码为 I-type 特化）
  • JALR rd, rs1, imm：间接跳转并链接
  • Load 指令：LB, LH, LW, LBU, LHU

S-type (Store)

  • Store 指令：SB, SH, SW
  • 有效地址 = rs1 + sign-extended 12-bit offset

B-type (条件分支)

  • BEQ, BNE：等于/不等于则分支
  • BLT, BLTU：有符号/无符号小于则分支
  • BGE, BGEU：有符号/无符号大于等于则分支
  • 12-bit B-immediate → 分支范围 ±4 KiB

J-type (无条件跳转)

  • JAL rd, offset：跳转并链接（rd=x0 时为普通跳转 J）
  • 20-bit J-immediate → 跳转范围 ±1 MiB
  • Position Independent!（位置无关）

RISC-V 指令执行阶段

  1. Instruction Fetch
  2. Instruction Decode
  3. Register Fetch
  4. ALU Operations
  5. Optional Memory Operations
  6. Optional Register Writeback
  7. Calculate Next Instruction Address

RISC-V vs MIPS 的改进

改进点 MIPS 问题 RISC-V 解决
无延迟槽 MIPS 有延迟转移 (delayed branch) RISC-V 无延迟槽
PC 相对跳转 MIPS 直接跳转无 PC 相对寻址 RISC-V JAL 使用偏移量 + PC
编码空间 MIPS 16 位立即数消耗空间 RISC-V 有更多扩展空间
条件码 MIPS 部分使用条件码 RISC-V 不使用条件码

2.14 微程序实现 (Microprogramming)

背景

  • 早期计算机设计者的最大挑战：控制逻辑的正确性
  • Maurice Wilkes 提出了微程序设计概念（EDSAC-II, 1958）

为什么 60-70 年代微程序盛行？

原因 说明
ROM 比 DRAM 快得多 真空管 (逻辑) < 磁芯存储器 (主存) < 二极管矩阵 (ROM)
复杂指令集更便宜 不修改数据通路即可增加新指令
bug 修复容易 修改 ROM 比修改硬件容易
型号兼容性简单 不同型号实现同一 ISA 成本低

单总线数据通路

处理器分为 Datapath（数据通路） 和 Control（控制逻辑） 两部分：

  • Datapath：存储数据、算术逻辑运算单元
  • Control：控制数据通路上的操作

微程序控制 CPU 结构

⭐ 微指令的寄存器传输级表示

微操作 含义
MA:=PC RegSel=PC; RegW=0; RegEn=1; MALd=1
B:=Reg[rs2] RegSel=rs2; RegW=0; RegEn=1; BLd=1
Reg[rd]:=A+B ALUop=Add; ALUEn=1; RegSel=rd; RegW=1

⭐ 微代码示例

微程序控制存储器大小计算

$$
\text{微控制器大小} = 2^{|\mu address|} \times |\text{data}|
$$

其中：

$$
|\mu address| = |\mu PC| + |\text{opcode}| + 1 + 1
$$

$$
|\text{data}| = |\mu PC| + |\text{control signals}|
$$

示例（单总线 RISC-V）：

  • 取指 3 步 + 12 组指令 × 5 步/组 = 63 条微指令 → μPC 需要 6 位
  • Opcode 5 位 + ~18 个控制信号
  • 大小 = 213×24≈ 25 KiB

μPC Jump 类型

类型 说明
next μPC + 1
spin 等待存储器就绪
fetch 跳回取指开始
dispatch 跳到操作码对应的微程序起始
ftrue / ffalse 条件为真/假时跳到取指

复杂指令的微程序实现

示例：Memory-memory add M[rd] = M[rs1] + M[rs2]

关键点：复杂指令的实现通常不需要修改数据通路，仅需编写微程序（可能占用更多控存）

减少 Control Store 大小

方法 说明
减少地址位数 用外部逻辑合并输入信号；合并操作码
减少数据位数 限制 μPC 编码（next/dispatch/wait）；编码控制信号

水平 vs 垂直微编码

水平微编码 (Horizontal) 垂直微编码 (Vertical)
每条微指令 多个微操作并行 一个数据通路操作
每条宏指令的微指令数 较少 较多
编码方式 稀疏 → 微指令较宽 紧凑 → 微指令较窄

Nanocoding：水平型和垂直型的结合

  • 利用微代码中重复的控制信号
  • 两级 ROM：μcode ROM → nanoinstruction ROM
  • 示例：Motorola 68000 的 17-bit μcode 包含 10-bit μjump 或 9-bit nanoinstruction 指针

Writable Control Store (WCS)

  • 使用 RAM 代替 ROM 存储微程序
    • MOS SRAM 与控制存储速度相当（过去磁芯/DRAM 比控存慢 2-10 倍）
  • User-WCS（用户可写控制存储）失败的原因：
    • 几乎没有编程工具支持
    • 很难将应用软件装入很小的 WCS
    • 微代码级模拟原 ISA 对他人用处不大
    • 大量 WCS 空间保存处理器状态 → 上下文切换代价高
    • 用户改变微代码时环境保护困难
    • 虚拟存储要求微代码具有 restartable 能力

微程序技术的衰落

80 年代初：

  • VLSI 技术使 ROM 和 RAM 速度相同（均为 MOS 晶体管）
  • 编译器技术进步 → 复杂指令不再那么重要
  • 微结构技术进步（流水线、Cache、Buffer）→ 多周期执行失去吸引力

IBM 360 系列中，只有最快型号 (75 和 95) 是硬布线控制的

IBM 360 微程序参数

型号 数据通路宽度 微指令宽度 微代码大小 控存技术 控存周期 主存周期 月租费
