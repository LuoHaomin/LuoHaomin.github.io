一、CPI / stall 计算题

题 1：按 hazard 分类计算平均 CPI [⭐⭐⭐]

题目：
某 5 级流水线（IF/ID/EX/MEM/WB），理想 CPI = 1。统计某程序得到如下数据：

Hazard 类型 发生频率（每条指令） 平均引入 bubble
结构相关（结构 stall） 0.05 1
数据相关（RAW，无 Load-Use） 0.20 0（forwarding 解决）
Load-Use 相关 0.10 1
控制相关（分支 mispredict） 0.15 2

求该程序的实际 CPI。

考点：CPI = Ideal CPI + 各类 stall 之和；forwarding 消除的 RAW 不计 stall。

解答：
分别求每类 stall 对 CPI 的贡献：

ΔCPI结构=0.05×1=0.05\Delta CPI_{结构} = 0.05 \times 1 = 0.05 ΔCPI结构​=0.05×1=0.05

ΔCPI数据(RAW,forwarding)=0.20×0=0\Delta CPI_{数据(RAW,forwarding)} = 0.20 \times 0 = 0 ΔCPI数据(RAW,forwarding)​=0.20×0=0

ΔCPILoad−Use=0.10×1=0.10\Delta CPI_{Load-Use} = 0.10 \times 1 = 0.10 ΔCPILoad−Use​=0.10×1=0.10

ΔCPI控制=0.15×2=0.30\Delta CPI_{控制} = 0.15 \times 2 = 0.30 ΔCPI控制​=0.15×2=0.30

求和：

CPI=1+0.05+0+0.10+0.30=1.45CPI = 1 + 0.05 + 0 + 0.10 + 0.30 = 1.45 CPI=1+0.05+0+0.10+0.30=1.45

统计：CPI = 1.45

要点/易错：

  • forwarding 成功解决的 RAW 不计 stall，否则会把 CPI 算大。
  • Load-Use 即使有 forwarding 也至少 1 个 stall（数据到 MEM 结束才可用）。
  • 题给"频率"是相对每条指令的平均值，直接相加即可，无需再除以指令总数。

题 2：纯结构相关下的时钟频率权衡（双端口 vs 单端口）[⭐⭐⭐]

题目：
两台机器 A、B 都是 5 级流水线，均执行同一程序（Load 指令占 40%）：

  • 机器 A：Harvard 结构（分离 I-Cache / D-Cache），无结构相关，时钟周期 tAt_AtA​。
  • 机器 B：单端口存储器（IF 与 MEM 抢同一端口），Load 在 MEM 段时下一条指令的 IF 必须停顿 1 周期。但 B 的时钟频率比 A 高 5%。

问：B 的平均指令执行时间相对 A 是快还是慢？快/慢多少？

考点：结构相关；Tavg=CPI×tclkT_{avg} = CPI \times t_{clk}Tavg​=CPI×tclk​；时钟频率提升不一定能补偿 CPI 上升。

解答：
A：CPIA=1CPI_A = 1CPIA​=1，tAt_AtA​。TA=1×tA=tAT_A = 1 \times t_A = t_ATA​=1×tA​=tA​。

B：Load 占 40%，每次 Load 引入 1 个结构 stall：

CPIB=1+0.40×1=1.40CPI_B = 1 + 0.40 \times 1 = 1.40 CPIB​=1+0.40×1=1.40

B 时钟快 5% → tB=tA/1.05t_B = t_A / 1.05tB​=tA​/1.05。

TB=CPIB×tB=1.40×tA1.05≈1.333 tAT_B = CPI_B \times t_B = 1.40 \times \frac{t_A}{1.05} \approx 1.333\, t_A TB​=CPIB​×tB​=1.40×1.05tA​​≈1.333tA​

TBTA=1.333\frac{T_B}{T_A} = 1.333 TA​TB​​=1.333

统计：B 反而慢约 33%（1.333/1−1≈33%1.333/1 - 1 \approx 33\%1.333/1−1≈33%）。

要点/易错：

  • 不要只看时钟频率：CPI 上升的代价（+40%）远大于频率提升（+5%）。
  • 公式链：TCPU=IC×CPI×tclkT_{CPU} = IC \times CPI \times t_{clk}TCPU​=IC×CPI×tclk​，ICICIC 相同时比 CPI×tclkCPI \times t_{clk}CPI×tclk​。

二、流水线时序图题（含完整时序表）

约定记号：IF / ID / EX / MEM / WB 为各流水段；bub 表示 bubble（stall）；→ 表示 forwarding 数据通路。

题 1：纯 RAW + forwarding（无 stall）[⭐⭐⭐]

题目：流水线带完整 forwarding（EX/MEM→EX、MEM/WB→EX）。画出以下指令的时序表，统计总周期数与 CPI。

考点：EX-EX forwarding（相邻）、MEM/WB→EX forwarding（隔一条），判断是否需要 stall。

解答：
分析 forwarding：

  • I2 需要 R1。I1 在 C3 的 EX 末尾算出 R1，I2 在 C4 进入 EX → EX/MEM→EX forwarding，0 stall。
  • I3 需要 R1。I1 的 R1 在 C4 处于 MEM（结果在 MEM/WB 寄存器），I3 在 C5 进入 EX → MEM/WB→EX forwarding，0 stall。
  • I4 需要 R4。I2 在 C5 的 EX 末尾算出 R4，I4 在 C6 进入 EX → EX/MEM→EX forwarding，0 stall。

时序表：

指令 C1 C2 C3 C4 C5 C6 C7 C8
I1 ADD R1,R2,R3 IF ID EX MEM WB
I2 SUB R4,R1,R5 IF ID EX MEM WB
I3 AND R6,R1,R7 IF ID EX MEM WB
I4 OR R8,R4,R9 IF ID EX MEM WB

Forwarding 标注：

  • C3→C4（I1.EX 末→I2.EX）：R1，EX/MEM→EX。
  • C4→C5（I1.MEM→I3.EX）：R1，MEM/WB→EX。
  • C5→C6（I2.EX 末→I4.EX）：R4，EX/MEM→EX。

统计：4 条指令，无 bubble，总周期 = $k + n - 1 = 5 + 4 - 1 = $ 8；CPI = $8/4 = $ 1.00。

要点/易错：

  • 相邻指令的 RAW 用 EX/MEM→EX forwarding；隔一条用 MEM/WB→EX forwarding，两者都 0 stall。
  • 隔两条以上（如 I1 与 I4 间还有 I2、I3）时数据已写回寄存器，直接读，无需 forwarding。

题 2：含 Load-Use hazard（必须 1 个 stall）[⭐⭐⭐]

题目：流水线带完整 forwarding。画出时序表，统计总周期与 CPI。

考点：Load-Use hazard 至少 1 个 stall；MEM/WB→EX forwarding 兜底。

解答：
分析：

  • I2 紧接 I1 用 R1。Load 的 R1 在 I1 的 **MEM 段末尾（C4）**才可用，而 I2 在 C4 就进入 EX（需在 EX 开头拿到 R1）。MEM 结束 = C4 末，EX 开始 = C4 初，时间对不上 → 必须插 1 个 bubble，I2 的 EX 推迟到 C5，用 MEM/WB→EX forwarding 取 R1。
  • I4 用 R3（I2 在 C5 EX 末算出 R3，I4 在 C7 进入 EX）→ EX/MEM→EX forwarding，0 stall。

时序表（I2 整体右移 1 个周期，C5 出现 bubble）：

指令 C1 C2 C3 C4 C5 C6 C7 C8 C9
I1 LD R1,0(R2) IF ID EX MEM WB
I2 ADD R3,R1,R4 IF ID bub EX MEM WB
I3 SUB R5,R6,R7 IF ID EX MEM WB
I4 SW R3,8(R2) IF ID EX MEM WB

Forwarding 标注：

  • C4末→C5（I1.MEM→I2.EX）：R1，MEM/WB→EX（1 个 stall 后转发）。
  • C5末→C7（I2.EX→I4.EX）：R3，EX/MEM→EX。

统计：总周期数 = $k + n - 1 + \text{bubble} = 5 + 4 - 1 + 1 = $ 9（用于回答"完成 n 条需多少周期"）。

CPI 说明：CPI 的定义是"每条指令平均占用的流水周期数"。若直接用 总周期/指令数 =9/4=2.25= 9/4 = 2.25=9/4=2.25，会把流水线装入时间（k−1=4k-1=4k−1=4 个周期的 fill）摊到指令上，使短程序 CPI 偏高。期末考试惯例：在流水线已稳定（n≫kn \gg kn≫k）或只问"稳态性能"时，用

CPI=1+bubble 数n=1+14=1.25CPI = 1 + \frac{\text{bubble 数}}{n} = 1 + \frac{1}{4} = 1.25 CPI=1+nbubble 数​=1+41​=1.25

来反映 hazard 的真实代价。若题目明确要求"完成这段程序的实际 CPI"，则用 总周期/指令数；若问"hazard 带来的 CPI 上升"或稳态 CPI，用 1+平均 stall/指令1 + \text{平均 stall/指令}1+平均 stall/指令。

统计：总周期 = 9；CPI = 1.25（含 0.25 平均 stall/指令）。

要点/易错：

  • Load-Use 必插 1 stall，这是 forwarding 也救不了的（数据在 MEM 末才出）。
  • 总周期数 = k+n−1+bubble 数k+n-1+\text{bubble 数}k+n−1+bubble 数。
  • CPI 用"1 + 平均 stall"算法，避免装入时间把 CPI 估高。

题 3：分支指令导致 flush（控制 hazard）[⭐⭐⭐]

题目：流水线采用 Predict Not Taken 策略（先顺序取，分支在 EX 段判定）。带完整 forwarding。指令序列：

已知 分支实际 taken（R1==0）。画出时序表，统计总周期。

考点：条件分支在 EX 段才确定方向 → 错误路径上 IF、ID 两段取的指令被 flush，penalty = 2。

解答：
分析（Predict Not Taken + 实际 taken）：

  • C2：I2 进入 ID，I3 进入 IF（顺序预测）。
  • C3：I2 进入 EX 判定方向（C3 末知 taken），I3 进入 ID，I4 进入 IF。
  • C3 末确定 taken → I3、I4（错误路径）被 kill（flush 为 bubble），目标指令 L1 从 C4 进入 IF。

时序表（I3、I4 在被 flush 前的段记作 IF*/ID*，flush 后变 bubble，实际表中标 bub）：

指令 C1 C2 C3 C4 C5 C6 C7 C8
I1 ADD R1,R2,R3 IF ID EX MEM WB
I2 BEQ R1,R0,L1 IF ID EX MEM WB
I3 SUB R4,R5,R6（错） IF* bub bub bub bub bub
I4 OR R7,R8,R9（错） IF* bub
L1 ADD R10,R11,R12 IF ID EX MEM WB

说明：I3 在 C3 进入 IF、C4 本应进入 ID，但 C3 末分支判定 taken，I3 的 ID、MEM、WB 全部废弃（标 bub）；I4 在 C4 进入 IF 也被废弃。等效于分支引入 2 个 bubble（C4、C5 的两个空槽），L1 从 C4 重新 IF。

Forwarding：I1→I2 的 R1（EX/MEM→EX，C3末→C3初，时间紧，实际需 C3 末判定，C3 的 EX 内 ALU 比较，R1 由 I1 的 EX/MEM 寄存器在 C3 初旁路给 I2 的 EX）。

统计：有效指令数 = 3（I1, I2, L1）；引入 2 个 bubble；总周期 = $5 + 5 - 1 + 2 = $ 8。

（5 条指令槽位含 2 条被 flush 的，但流水段仍被占用 → 总周期 8。）

要点/易错：

  • 条件分支 penalty = 2（IF、ID 两段取的错路径指令被 flush）。
  • Predict Not Taken + 实际 not taken → penalty = 0；实际 taken → penalty = 2。
  • 注意 flush 后的 bubble 要在表里体现，不能漏。

三、数据冒险与 forwarding 分析

题 1：RAW/WAR/WAW 判别 + forwarding 假设 [⭐⭐⭐]

题目：给定指令序列（5 级流水线，乱序完成模型用于讨论 WAR/WAW）：

(a) 识别所有数据相关并分类（RAW / WAR / WAW）。
(b) 假设 5 级顺序流水线 + 完整 forwarding，哪些相关需要 stall？哪些可由 forwarding 消除？

考点：真相关 vs 名字相关；顺序 in-order 流水线中 WAR/WAW 一般不出现。

解答：

(a) 相关识别（按逻辑序，找写-读/读-写/写-写对）：

相关对 类型 寄存器 说明
I1→I2 RAW R1 I1 写 R1，I2 读 R1（真相关）
I1→I3 WAW R1 I1、I3 都写 R1（输出相关）
I1→I4 RAW R1 I4 读 R1 —— 但 I3 在 I1 后又写 R1，I4 应读 I3 的 R1
I3→I4 RAW R1 I3 写 R1，I4 读 R1（真相关，最新定义）
I2→I5 RAW R4 I2 写 R4，I5 读 R4
I2→I3 WAR （I2 读 R1，I3 写 R1）但 I2 在 I3 前，I2 已在 ID 读过 R1 → 顺序流水线无实际 WAR 风险

关键纠错：I4 读 R1 应读到最近一次写，即 I3 的 R1，而非 I1 的。所以 I1→I4 不是真正的 RAW（被 I3 “拦截”）。

修正后的真相关（RAW）：

  • I1→I2（R1）
  • I3→I4（R1）
  • I2→I5（R4）

WAW：I1→I3（R1）。
WAR：逻辑上 I2→I3（R1）是反相关，但顺序流水线里 I2 先完成读、I3 后写，不构成 hazard。

(b) forwarding 处理：

RAW 对 forwarding 路径 stall?
I1→I2（R1） EX/MEM→EX（C3末→C4初） 0 stall
I3→I4（R1） MEM/WB→EX（I3 在 C5 MEM，I4 在 C6 EX） 0 stall
I2→I5（R4） I2 在 C5 EX，I5 在 C7 EX → EX/MEM→EX 0 stall
  • WAW（I1→I3）：顺序流水线按序写回，I3 的 WB 晚于 I1 的 WB，最终 R1 = I3 的结果，无 hazard。
  • WAR：顺序流水线按序读、按序写，无 hazard。

结论：5 级顺序流水线 + 完整 forwarding 下，全部 RAW 由 forwarding 消除，0 stall；WAW/WAR 在顺序流水线中天然不构成 hazard（仅乱序完成时才需处理）。

要点/易错：

  • 读寄存器应读最近一次写，不要把被覆盖的旧相关当 RAW（I1→I4 是常见陷阱）。
  • WAR/WAW 是名字相关，本质是寄存器重用；顺序流水线里几乎不出现，乱序完成（如 FP 多周期）才成问题。
  • forwarding 消除 RAW 的前提是数据在 EX 之前或之中可用；Load-Use 例外。

题 2：连续 Load-Use 与 forwarding 混合 [⭐⭐⭐]

题目：带完整 forwarding 的 5 级流水线。

(a) I3 与 I1、I2 各是哪种相关？需几个 stall？
(b) 画出时序表，统计总周期与 CPI。

考点：两条 Load 的结果汇入同一指令；最坏情况 stall 取决于最近一条 Load。

解答：

(a) I3 读 R1（来自 I1）、R3（来自 I2），均为 RAW（Load-Use）。

  • I1 与 I3 隔了 I2（距离 2），R1 在 I1 的 MEM（C4）末可用 → I3 若在 C6 进 EX，数据已通过 MEM/WB→EX 转发，0 stall。
  • I2 与 I3 相邻（距离 1），R3 在 I2 的 MEM（C5）末可用 → I3 原本 C5 进 EX，时间对不上 → 1 stall，I3 EX 推迟到 C6。

总 stall = 1（取最坏，即紧邻的 Load-Use）。

(b) 时序表：

指令 C1 C2 C3 C4 C5 C6 C7 C8 C9
I1 LD R1,0(R2) IF ID EX MEM WB
I2 LD R3,4(R2) IF ID EX MEM WB
I3 ADD R4,R1,R3 IF ID bub EX MEM WB
I4 SW R4,8(R2) IF ID EX MEM WB

Forwarding 标注：

  • C4末→C6（I1.MEM→I3.EX）：R1，MEM/WB→EX。
  • C5末→C6（I2.MEM→I3.EX）：R3，MEM/WB→EX（1 stall 后）。
  • C6末→C6（I3.EX→I4.EX 不对）→ 实际 C6末→C7：I4 SW 的 R4 在 EX 段旁路（EX/MEM→EX，C6末→C7初）。

统计：4 条指令，1 个 bubble，总周期 = $5 + 4 - 1 + 1 = $ 9；CPI = $1 + 1/4 = $ 1.25。

要点/易错：

  • 一条指令同时依赖多个 Load 时，stall 数 = 距离最近的那个 Load-Use 决定（这里是 I2→I3 的 1 个），不叠加。
  • 距离 ≥ 2 的 Load-Use 数据已在 MEM/WB 寄存器，可直接转发，0 stall。

题 3：无 forwarding 时的 stall 计算 [⭐⭐⭐]

题目：5 级流水线没有 forwarding（结果必须经 WB 写回寄存器后，后续指令在 ID 段才能读到）。设寄存器写（WB 段前半）与同周期 ID 段读（后半）可同时进行（write-then-read 同周期）。

求每条后继指令需几个 stall，并算 CPI。

考点：无 forwarding 时，必须等写回（WB）同周期 ID 才能读；stall 数随距离变化。

解答：
无 forwarding 规则：I1 在 C5（WB）写 R1，且写与读同周期（WB 前半写、ID 后半读）→ 依赖指令的 ID 必须落在 C5 或之后。

  • I2：理想 ID 在 C3，需推迟到 C5 → 插 2 个 stall（C3、C4 为 bub，I2 的 ID 在 C5）。
  • I3：理想 ID 在 C4，需推迟到 C5 → 插 1 个 stall（C4 为 bub）。

时序表：

指令 C1 C2 C3 C4 C5 C6 C7 C8 C9
I1 ADD R1,R2,R3 IF ID EX MEM WB
I2 SUB R4,R1,R5 IF bub bub ID EX MEM WB
I3 AND R6,R1,R7 IF bub ID EX MEM WB

统计：3 条指令，共 3 个 bubble，总周期 = $5 + 3 - 1 + 3 = $ 10；CPI = $1 + 3/3 = $ 2.00。

对比：若有完整 forwarding，本题 0 stall，CPI = 1。可见 forwarding 对无结构/控制 hazard 程序的收益巨大。

要点/易错：

  • 无 forwarding 时 stall 数 = 5−距离−15 - \text{距离} - 15−距离−1（距离 1→2 stall，距离 2→1 stall，距离 ≥3→0 stall）。
  • “WB 写与 ID 读同周期"是常见假设；若题目说"必须等 WB 完成才能读”，则 stall 数各 +1。

四、分支预测 / CPI 影响题

题 1：基本分支预测 CPI 计算 [⭐⭐⭐]

题目：某程序中分支指令占 pbranch=20%p_{branch} = 20\%pbranch​=20%，分支预测器的误预测率 pmiss=15%p_{miss} = 15\%pmiss​=15%，每次误预测的惩罚 penalty=3penalty = 3penalty=3 周期（流水线在分支结果出来前已取了 3 条错路径指令并需 flush）。理想 CPI = 1。

求实际 CPI。

考点：CPI=1+pbranch×pmiss×penaltyCPI = 1 + p_{branch}\times p_{miss}\times penaltyCPI=1+pbranch​×pmiss​×penalty。

解答：

CPI=1+pbranch×pmiss×penalty=1+0.20×0.15×3CPI = 1 + p_{branch} \times p_{miss} \times penalty = 1 + 0.20 \times 0.15 \times 3 CPI=1+pbranch​×pmiss​×penalty=1+0.20×0.15×3

=1+0.09=1.09= 1 + 0.09 = 1.09 =1+0.09=1.09

统计：CPI = 1.09。

要点/易错：

  • 三个因子都是概率/比例，相乘得"每条指令平均因分支误预测多花的周期"。
  • 别把 pbranchp_{branch}pbranch​（分支在所有指令中的占比）和 pmissp_{miss}pmiss​（分支中预测错的比例）搞混。

题 2：四种分支策略 CPI 对比（含延迟槽）[⭐⭐⭐]

题目：5 级流水线，条件 + 无条件分支总频率 fb=14%f_b = 14\%fb​=14%，其中 65% 的分支实际 taken。对以下四种策略分别计算 CPI 与相对加速比（以 Stall 策略为基准）：

策略 分支 penalty 说明
A. Stall pipeline 分支结果在 EX 末才知，penalty = 3（不论 taken 与否都停）
B. Predict Taken taken 正确 penalty=0；not-taken（预测错）penalty=1
C. Predict Not Taken not-taken 正确 penalty=0；taken（预测错）penalty=1
D. Delayed Branch 1 个延迟槽，50% 可填入有用指令，剩 50% 填 NOP（等效 penalty=0.5）

考点：分支策略定量评估；误预测率取自 taken 比例。

解答：

A. Stall：所有分支都付 penalty 3。

CPIA=1+3×0.14=1.42CPI_A = 1 + 3 \times 0.14 = 1.42 CPIA​=1+3×0.14=1.42

B. Predict Taken：预测所有分支 taken。65% 正确（penalty 0），35% 错（not-taken 实际，penalty 1）。

pmiss=35%=0.35,CPIB=1+0.14×0.35×1=1+0.049=1.049p_{miss} = 35\% = 0.35,\quad CPI_B = 1 + 0.14 \times 0.35 \times 1 = 1 + 0.049 = 1.049 pmiss​=35%=0.35,CPIB​=1+0.14×0.35×1=1+0.049=1.049

（注：此处按"预测错时 penalty=1"算；若题目给 penalty=2，相应调整。）

C. Predict Not Taken：预测所有分支 not-taken。35% 正确，65% 错。

pmiss=65%=0.65,CPIC=1+0.14×0.65×1=1+0.091=1.091p_{miss} = 65\% = 0.65,\quad CPI_C = 1 + 0.14 \times 0.65 \times 1 = 1 + 0.091 = 1.091 pmiss​=65%=0.65,CPIC​=1+0.14×0.65×1=1+0.091=1.091

D. Delayed Branch：等效 penalty = 0.5（一半延迟槽是 NOP）。

CPID=1+0.5×0.14=1.07CPI_D = 1 + 0.5 \times 0.14 = 1.07 CPID​=1+0.5×0.14=1.07

对比表：

策略 CPI 相对 Stall 加速比 ≈CPIA/CPI\approx CPI_A/CPI≈CPIA​/CPI
A. Stall 1.42 1.00
B. Predict Taken 1.049 1.35
C. Predict Not Taken 1.091 1.30
D. Delayed Branch 1.07 1.33

结论：

  • 因 65% 分支 taken，Predict Taken 略优于 Predict Not Taken（与笔记中 65% taken 时的定性结论一致——注意：本题设 taken=65%，故 predict taken 更优；若 taken<50% 则 predict not taken 更优）。
  • Delayed Branch 效果好，但现代 ISA 已因其他原因取消延迟槽。

要点/易错：

  • 误预测率 = 与实际方向相反的预测比例，取决于实际 taken 比例，不是固定值。
  • penalty 取决于"分支方向何时确定"：5 级流水线条件分支在 EX 末确定，Predict Not Taken 错时 penalty 通常 = 1（若 ID 段就能算目标地址则更小）。题目给定为准。

五、概念简答题

题 1：延迟槽与四种分支策略 [⭐⭐⭐]

题目：
(a) 什么是分支延迟槽（Branch Delay Slot）？为什么 1990 年后的 RISC ISA（如 MIPS32、RISC-V）取消了延迟槽？
(b) 简述控制相关的四种解决方法，并比较各自 penalty。

解答：

(a) 分支延迟槽：分支/跳转指令之后的 1 条（或若干条）指令，无论分支是否 taken 都先于控制流转移执行。语义上 j target 后紧跟的指令必执行。

取消原因：

  1. NOP 填充增多 I-cache 失效率，浪费带宽。
  2. 在深流水线、多发射（superscalar）架构中，延迟槽使硬件设计复杂化（需追踪延迟槽指令与分支的绑定关系）。
  3. 现代分支预测准确率高（>95%），延迟槽收益下降，得不偿失。

(b) 四种方法：

方法 策略 典型 penalty
Stall 暂停直到分支方向确定 最大（=分支前已取的段数，5 级约 2-3）
Predict Not Taken 先顺序取，猜错撤销 not-taken 正确时 0；错时 1-2
Predict Taken 先跳目标，猜错撤销 taken 正确时 0；错时 1-2（需先知目标地址）
Delayed Branch 延迟槽填充 最小（有用指令填入则 0，NOP 则 1）

要点：Predict Taken 的前提是先知道目标地址、后知道方向；对条件分支，目标地址可在 ID 段算出，方向在 EX 段定，故 Predict Taken 可行。

题 2：Load-Use hazard 与精确中断 [⭐⭐⭐]

题目：
(a) 为什么 Load-Use hazard 即使有完整 forwarding 也无法避免至少 1 个 stall？
(b) 什么是精确中断？为什么浮点长延迟操作使精确中断变得困难？给出一种硬件实现方法。

解答：

(a) Load 指令的数据在 MEM 段末尾才从存储器读出。紧跟其后的指令（距离 1）在 同一周期的 EX 段开头就需要该数据。MEM 结束（周期末）与后继 EX 开始（周期初）存在时间错位，forwarding 通路无法把"还没产生"的数据转出去，故必须插入 1 个 bubble，让后继指令的 EX 推迟到下一周期，此时 Load 结果已到 MEM/WB 寄存器，可经 MEM/WB→EX 转发。

(b) 精确中断：引起异常的指令之前的所有指令都已完整执行（写回），引起异常的指令及其后的指令没有改变机器状态（可重新执行）。处理器按逻辑序处理异常。

浮点长延迟（如除法 24-36 周期）导致乱序完成：后发的短指令可能先于先发的长 FP 指令到达 WB。若长 FP 指令异常，状态已被后续指令污染，无法回退 → 非精确。

硬件实现方法（任举一种）：

  • Future File（PowerPC 620, MIPS R10000）：执行结果先写"未来文件"缓存，按指令序提交到体系结构寄存器；异常时按序回卷。
  • History File（CYBER 180/990）：尽快提交，但同时保存原操作数；异常时用历史文件回卷到旧值。
  • 暂停发射（MIPS R2000-R4000, Pentium）：在 EX 段前期确认先前指令无异常前，不发射可能异常的长延迟指令，牺牲性能换精确性。

要点：整数流水线精确中断易实现；FP 长延迟是难点；IEEE FP 标准和虚拟存储器要求精确中断。
