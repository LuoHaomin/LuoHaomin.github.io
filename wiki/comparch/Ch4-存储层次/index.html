本章围绕存储层次结构展开，核心矛盾是 CPU 与 DRAM 之间不断增大的性能差距，解决思路是利用局部性原理构建多级存储层次。全章从基本概念出发，依次讨论 Cache 的四个核心设计问题（映像、查找、替换、写策略），然后深入三大优化方向（降低失效率、减少失效开销、缩短命中时间），最后扩展到存储器技术与虚拟存储器。

4.1 存储层次结构概述

存储系统设计的核心矛盾

存储器设计是计算机体系结构的关键问题之一，核心在于价格、容量、速度三者之间的矛盾：

速度快 容量大 价格低
速度快 — ❌ 容量越大速度越慢 ❌ 速度越快每位价格越高
容量大 ❌ — ✅ 容量越大每位价格越低
价格低 ❌ ✅ —

CPU-DRAM 性能差距

CPU 性能增长约 60%/year，而 DRAM 仅约 9%/year。差距可以用”一次完整 Cache 失效期间 CPU 可执行的指令数”来衡量：

处理器代次 失效期间可执行指令数
1st Alpha 136 条
2nd Alpha 320 条
3rd Alpha 648 条

差距越来越大，必须利用 Cache（高速缓存） 来缓解。

基本解决方法：多级层次结构

构建 CPU → M1 → M2 → … → Mn 的多级存储层次：

  • M1：速度最快，容量最小，每位价格最高
  • Mn：速度最慢，容量最大，每位价格最低

目标：使存储系统接近 M1 的速度，同时容量和价格接近 Mn。

典型参数（Server）

层次 Register L1 L2 L3 Memory I/O device
访问时间 300ps 1ns 3-10ns 10-20ns 50-100ns 5-10ms
容量 1000B 64KB 256KB 2-4MB 4-16GB 4-16TB

典型参数（PMD）

层次 Register L1 L2 Memory I/O device
访问时间 500ps 2ns 10-20ns 50-100ns 25-50us
容量 500B 64KB 256KB 256-512MB 4-8GB

局部性原理（Locality）

存储层次结构能够工作的根本原理：

  • 时间局部性（Temporal Locality）：最近被访问的数据很可能在不久后再次被访问 → 保持最近访问的数据项最接近处理器
  • 空间局部性（Spatial Locality）：地址空间上相邻的数据很可能在不久后被访问 → 以**块（Block）**为单位，从低层复制到上一层

存储层次基本概念

  • ⭐ 块（Block）：不同层次的块大小可以不同
  • ⭐ 命中（Hit） / 命中率（Hit Rate）：访问的块在较高层次上
  • ⭐ 失效（Miss） / 失效率（Miss Rate）：访问的块不在较高层次上
  • 镜像和一致性问题：高层是低层的镜像，高层修改必须反映到低层
  • 物理地址格式：Block Address + Block Offset

常见存储层次组织

层次对 调度方式
Registers ↔ Memory 编译器调度
Cache ↔ Memory 硬件调度
Memory ↔ Disks 硬件 + OS（虚拟管理）+ 程序员调度

Cache 无处不在：寄存器是变量的 Cache，L1/L2 是主存的 Cache，主存是磁盘的 Cache（虚拟存储），还有分支目标缓存、分支预测缓存等。

4.2 存储层次的性能参数

以两级存储 M1（上层）和 M2（下层）为模型，定义以下关键参数：

  • S1,C1,TA1：M1 的容量、每位价格、访问时间
  • S2,C2,TA2：M2 的容量、每位价格、访问时间

平均每位价格

$$
C = \frac{C_1 \times S_1 + C_2 \times S_2}{S_1 + S_2}
$$

命中率与失效率

$$
H = \frac{N_1}{N_1 + N_2}
$$

$$
\text{Miss Rate} = 1 - H = \frac{N_2}{N_1 + N_2}
$$

⭐ 平均访存时间（Average Memory Access Time, AMAT）

$$
\text{AMAT} = H \times TA_1 + (1-H) \times (TA_1 + T_M) = TA_1 + (1-H) \times T_M
$$

其中：

  • TA1：命中时间（Hit Time）
  • TM：失效开销（Miss Penalty），包含从 M2 传送块到 M1 的时间 TB

⭐ AMAT 是贯穿全章的核心度量公式，后续所有 Cache 优化方法的效果都以此公式为衡量标准。

4.3 Cache 基本知识 — 映像规则（Q1）

核心问题

⭐ Q1：当要把一个块从主存调入 Cache 时，放在哪里？

三种映像方式

方式 放置规则 公式 特点
全相联（Fully Associative） 可放在 Cache 中任何位置 无 命中率最高，实现最复杂
直接映象（Direct Mapped） 只能放在 Cache 中唯一位置 $j = i \mod M$（M 为 Cache 块数） 实现最简单，冲突最多
组相联（Set Associative） 放在唯一的一个组中任意位置 $K = i \mod G$（G 为组数） 折中方案

组相联的本质：组间直接映象，组内全相联；每组 N 个块 → N 路组相联（N-way Set Associative）。

示例：Block 12 放入 8 块 Cache

方式 放入位置
全相联 任意位置
直接映象 Block 4（12 mod 8）
2 路组相联 Set 0 内任意位置（12 mod 4）

不同相联度的路数与组数

方式 路数 N 组数 G
全相联 M 1
直接映象 1 M
其他组相联 1 < N < M 1 < G < M

关键结论

  • ⭐ 相联度越高 → Cache 空间利用率越高 → 块冲突概率越小 → 失效率越低
  • N 值越大 → 失效率越低，但实现越复杂，代价越大
  • 现代大多数计算机采用：直接映象、两路或四路组相联
  • 组数 G=M/N（M 为 Cache 块数）

4.4 Cache 基本知识 — 查找方法（Q2）

核心问题

⭐ Q2：如何在 Cache 中找到某个块？

Tag 标记

每个 Block 带有 tag 域，分两类：

  • Address Tags：标记访问单元在哪一块中
    • 物理地址分三部分：Address Tag | Block Index | Block Offset
    • 全相联映象时没有 Block Index
    • Tag 越短，查找代价越小
  • Status Tags：标记块状态，如 Valid、Dirty

查找原则

  • ⭐ 所有可能的标记并行查找（Cache 速度至关重要）
  • 并行查找方法：
    • 相联存储器（按内容检索）
    • 单体多字存储器 + 比较器
  • 相联度 N 越大 → 查找机制越复杂，代价越高
  • 直接映象和组相联只需比较 tag，index 无需参加比较

Tag 和数据阵列访问结构

  • 并行访问：Tag 和数据阵列同时访问，速度更快（现代常用）
  • 串行访问：先访问 Tag 阵列确定命中，再访问数据阵列

示例：1KB 直接映象 Cache（32B Blocks）

容量 $2^N$ 字节 Cache 的地址划分：

  • 最高 (32-N) 位 → Cache Tag
  • 中间位 → Cache Index
  • 最低 M 位 → Byte Select（Block Size = 2M）

每行存储：Valid Bit + Cache Tag + Cache Data（32 bytes）。

N 路组相联 Cache

Cache Index 选择一组 → 组内 N 个块的 Tags 与输入地址同时比较 → 根据比较结果选择数据（通过 Mux 和 OR 逻辑）。

4.5 Cache 基本知识 — 替换算法（Q3）

核心问题

⭐ Q3：当 Cache 块已满，需腾出位置时，替换哪一块？

  • 直接映象：只有一块，别无选择
  • 组相联和全相联：有多种选择

三种替换方法

方法 策略 优点 缺点
随机法（Random） 随机选择一块替换 简单，易于实现 不考虑使用历史，失效率较高
FIFO 选择最早调入的块 简单 最先进入的块可能经常使用，未充分利用局部性
⭐ LRU（Least Recently Used） 替换最近最少使用的块 较好利用程序局部性，失效率较低 硬件实现较复杂

关键结论

  • 相联度越高 → 失效率越低
  • Cache 容量越大 → 失效率越低
  • ⭐ LRU 在 Cache 容量较小时优势明显；容量加大后，Random 的失效率也在降低
  • 实际中 LRU 是最常用的替换算法

4.6 Cache 基本知识 — 写策略（Q4）

核心问题

⭐ Q4：何时更新主存？（Cache 与主存一致性问题）

访问比例

  • 程序对存储器：读占 26%，写占 9%
  • 写占数据 Cache 访问比例：9/(26+9)≈25%
  • ⭐ 大概率事件优先 → 优化读操作；但 Amdahl 定律 → 不可忽视写的速度

两种写策略

策略 原理 优点 缺点
写直达法（Write Through） 同时写 Cache 和主存 易于实现，容易保持一致性 速度较慢，访存次数多
⭐ 写回法（Write Back） 只写 Cache，替换时才写回主存 速度快，减少访存次数 一致性问题，需 dirty bit

写失效时的策略

策略 原理
按写分配法（Write Allocate） 写失效时先调入块再写（Fetch on Write）
不按写分配法（No-Write Allocate） 写失效时直接写入下一级，不调入 Cache（Write Around）

⭐ 典型搭配

  • Write Back + Write Allocate（多用于 L2 → Memory）
  • Write Through + No-Write Allocate（多用于 L1 → L2）

**写缓冲（Write Buffer）**用于缓解写直达的性能问题；Victim Buffer用于写回法的脏块处理。

4.7 Cache 实例与性能分析

Alpha 21064 数据 Cache

  • 容量 8KB，Block 32B，共 256 个 blocks
  • 直接映象，写直达法，写失效 no-write allocate
  • 写缓冲：4 个 blocks
  • 34 位物理地址：21 位 tag | 8 位 index | 5 位 offset
  • 失效时向 CPU 发暂停信号，传送 32B 需 10 cycles（16 字节通路）

Alpha 21264 数据 Cache

  • 容量 64KB，Block 64B
  • 两路组相联，Write Back + Write Allocate
  • 48-bit 虚拟地址 → 44-bit 物理地址
  • 地址结构：29 位 tag | 9 位 index | 6 位 offset

⭐ Cache 性能分析公式

$$
\text{CPU time} = (\text{CPU execution cycles} + \text{Memory stall cycles}) \times \text{Clock cycle time}
$$

$$
\text{Memory stall cycles} = \text{Reads} \times \text{Read miss rate} \times \text{Read miss penalty} + \text{Writes} \times \text{Write miss rate} \times \text{Write miss penalty}
$$

简化形式：

$$
\text{Memory stall cycles} = \text{Memory accesses} \times \text{Miss Rate} \times \text{Miss Penalty}
$$

$$
\text{AMAT} = \text{Hit Time} + \text{Miss Rate} \times \text{Miss Penalty}
$$

性能分析举例 1

  • Clock Rate = 200 MHz，Ideal CPI = 1.1
  • 指令混合：50% ALU，30% ld/st，20% control
  • Data cache miss rate 10%，Instruction cache miss rate 1%，Miss penalty = 50 cycles

$$
\text{CPI} = 1.1 + 0.30 \times 0.10 \times 50 + 1 \times 0.01 \times 50 = 3.1
$$

⭐ 65%（2/3.1）的时间处理器在等待存储器！ AMAT = 2.54。

性能分析举例 2：Harvard vs Unified

  • 16KB I&D 分离（Harvard）：Inst miss 0.64%，Data miss 6.47%
  • 32KB 统一（Unified）：Agg miss 1.99%
  • AMATHarvard=2.05，AMATUnified=2.24
  • Harvard 更优

UltraSPARC III 例子

  • Cache 失效开销 100 cycles，Ideal CPI = 1
  • 失效率 2%，每条指令访存 1.5 次 → CPI = 4

⭐ 关键结论：

  • CPI 越低，Cache 失效开销的相对影响越大
  • 时钟频率越高，失效开销（以 cycle 为单位）越大
  • Cache 对低 CPI、高时钟频率的 CPU 更重要

4.8 直接映象 vs 组相联的性能比较

例题

比较 128KB 直接映象和两路组相联 Cache：

条件 值
理想 CPI 1.0
时钟周期 0.35 ns
每条指令访存 1.4 次
块大小 64B
组相联时钟周期增加 1.35 倍（多路选择器）
失效开销 65 ns
直接映象失效率 2.1%
两路组相联失效率 1.9%
方案 AMAT CPU time Speed up
直接映象 $0.35 + 0.021 \times 65 = 1.72$ ns $2.26 \times IC$ 1.0
两路组相联 $0.35 \times 1.35 + 0.019 \times 65 = 1.71$ ns $2.20 \times IC$ 1.03

⭐ 组相联降低了失效率，但增加了命中时间。综合效果需要具体计算，不能只看失效率。

⭐ 改进 Cache 性能的三个基本途径

$$
\text{AMAT} = \text{Hit Time} + \text{Miss Rate} \times \text{Miss Penalty}
$$

途径 对应方法
⭐ 降低失效率 1. 增加块大小 2. 增大容量 3. 提高相联度
⭐ 减少失效开销 4. 多级 Cache 5. 读失效优先于写失效
⭐ 缩短命中时间 6. 避免索引缓存时进行地址转换

4.9 降低失效率 — 3C 模型与块大小选择

⭐ Cache 失效的三大原因（3C Model）

类型 英文名 原因 受相联度影响 受容量影响
⭐ 强制性失效 Compulsory / Cold 第一次访问某块，必须从下一级 Load 否 否
⭐ 容量失效 Capacity 程序所需块因容量不足不能全部调入，替换后重访问 否 是（容量↑ → 失效↓）
⭐ 冲突失效 Conflict / Collision 太多块映射到同一组，即使其他组有空闲位置 是（相联度↑ → 失效↓） 间接
  • 容量失效可能导致**“抖动（Thrashing）”**现象
  • 统计规律：相联度越高 → 冲突失效越小；容量越大 → 容量失效越少

⭐ 2:1 Cache 经验规则

  • 容量为 N 的直接映象 Cache 失效率 ≈ 容量为 N/2 的两路组相联 Cache 失效率
  • 8 路组相联在降低失效率方面已和全相联一样有效

减少各类失效的方法

手段 对哪种失效有效
增大 Cache 容量 容量失效、冲突失效
增大块大小 强制性失效（但可能增加冲突失效）
提高相联度 冲突失效
预取 强制性失效

⭐ 块大小的权衡

块大小增加时，失效率先降后升：

  • 块增大 → 强制性失效减少（空间局部性）
  • 块增大 → 冲突失效增加（Cache 块数量减少）
  • 块增大 → 失效开销增大（传输时间变长）
  • ⭐ Cache 容量越大，使失效率最低的块大小越大

设计原则：不能仅看失效率，必须综合考虑 AMAT = 命中时间 + 失效率 × 失效开销。

4.10 提高相联度与 Victim Cache

提高相联度

  • ⭐ 8 路组相联的失效率已接近全相联
  • 2:1 Cache 经验规则：直接映象 N 的失效率 ≈ 组相联 N/2 的失效率
  • 但提高相联度会增加命中时间

⭐ Victim Cache

  • 基本思想：在 Cache 和 Memory 之间增加一个小的全相联 Cache
  • 用于存放因冲突失效而被丢弃的块

工作流程

  • Cache 失效时，先检查 Victim Cache 是否有该块
  • 如果有 → 将该块与 Cache 中相应块互换
  • 如果没有 → 从 Memory 取块，被替换的块放入 Victim Cache

效果（Jouppi, DEC SRC）

  • 1-5 项的 Victim Cache 对减少失效很有效
  • ⭐ 4 项 Victim Cache 能使 4KB 直接映象数据 Cache 冲突失效减少 20%-90%
  • 对小型直接映象数据 Cache 效果最好

4.11 多级 Cache 与包容性

设计动机

  • 一级 Cache（L1）：保持较小容量 → 降低命中时间、降低每次访问能耗
  • 二级 Cache（L2）：减少与存储器的 gap、减少存储器总线负载
  • L2 容量大 → 捕捉 L1 的许多失效 → 降低全局失效率

多级包容性（Inclusive）

  • ⭐ L1 的块总是存在于 L2 中
  • L1 miss，L2 hit → 从 L2 拷贝到 L1
  • L1、L2 均 miss → 从更低级拷贝到 L1 和 L2
  • 写操作：同时写 L1 和 L2（Write Through L1→L2）；L2→更低级可用 Write Back
  • ⭐ L2 的替换对 L1 可见：L2 替换一块 → L1 对应块也要被替换
  • 缺点：浪费 L2 空间（L1 数据占 L2 空间）

多级不包容（Exclusive）

  • ⭐ L1 中的块不会在 L2 中，避免浪费空间
  • L1 miss，L2 hit → Cache 间块互换（L1 替换块移至 L2）
  • L1、L2 均 miss → 仅从低层拷贝到 L1
  • L1 到 L2、L2 到更低级均为 Write Back

包容 vs 不包容比较

维度 包容（Inclusive） 不包容（Exclusive）
空间利用 浪费（L1 数据重复） 高效（互补）
L2 替换影响 L1 是（需同步失效） 否
实现复杂度 较低（L2 总有 L1 副本） 较高（块互换）

4.12 两级 Cache 性能分析与读优先于写

⭐ 多级 Cache AMAT 公式

$$
\text{AMAT} = \text{Hit Time}{L1} + \text{Miss Rate}{L1} \times (\text{Hit Time}{L2} + \text{Miss Rate}{L2} \times \text{Miss Penalty}_{L2})
$$

其中 L1 的失效开销 $= \text{Hit Time}{L2} + \text{Miss Rate}{L2} \times \text{Miss Penalty}_{L2}$

Memory Stall Cycles Per Instruction

$$
\text{Stall per Inst} = (1+%LS) \times \text{Miss Rate}{L1} \times \text{Miss Penalty}{L1}
$$

$$
= \text{MPI}{L1} \times \text{Hit Time}{L2} + \text{MPI}{L2} \times \text{Miss Penalty}{L2}
$$

性能例题

  • 1000 次存储器访问：I miss = 5，D miss = 35，L2 miss = 8
  • L1 hit = 1 cycle，L2 hit = 8 cycles，L2 miss penalty = 80 cycles
  • CPI-exec = 1.1，Load+Store = 25%
  • L1 miss rate = 4%，MPI_L1 = 0.05，MPI_L2 = 0.01

$$
\text{Stall per Inst} = 0.05 \times 8 + 0.01 \times 80 = 1.2
$$

$$
\text{CPI}_{L1+L2} = 1.1 + 1.2 = 2.3
$$

⭐ 无 L2 时 CPI = 1.1 + 0.05 \times 80 = 5.1（差距巨大！）

两级 Cache 研究结论

  • L2 比 L1 大得多时，全局失效率接近容量等于 L2 的单级 Cache 失效率
  • ⭐ 局部失效率（Local Miss Rate）不是衡量 L2 的好指标，应看全局失效率
  • L2 设计特点：容量大、高相联度、块较大、重点减少失效次数

⭐ 让读失效优先于写

写直达法 → Write Buffer：

  • CPU 将数据和地址送入 Write Buffer 后继续执行，不必等待
  • ⭐ 读失效时检查 Write Buffer，无冲突则继续（推荐方案）

写回法 → Victim Buffer：

  • 被替换的脏块放入 Victim Buffer
  • 读失效时先查找 Victim Buffer，命中则直接调入 Cache

4.13 缩短命中时间 — Virtually Indexed Cache

核心问题

⭐ Cache index 用虚拟地址还是物理地址？

Virtual Index

  • 避免在 Cache indexing 时进行 virtual→physical 地址转换 → 命中时间短
  • 与 TLB 地址转换可并行进行

纯虚拟 Cache（Virtual Index + Virtual Tag）

  • 似乎更快，但有严重问题：进程切换时可能需清空整个 Cache，或需附加 PID 字段
  • 不实用

⭐ 通常采用：Virtually Indexed, Physically Tagged（VIPT）

  • Index 使用虚拟地址（快，无需等 TLB）
  • Tag 使用物理地址（正确，支持多进程）
  • 虚拟地址转换与 Cache 定位并行

典型层次结构

⭐ 关键约束

Index 部分的位数必须 <= 页内偏移位数

  • 否则虚拟地址的 Index 位可能跨页，导致不同物理页映射到同一 Cache 位置
  • 例：块大小 64B + 页大小 16KB → 页内偏移 14 bits → 直接映象 L1 最大 214−6=256 组（16KB）
  • 页大小增大可以放宽此约束

4.14 十大 Cache 优化方法

优化方法总览

类别 方法 目标
缩短命中时间 1. 小而简单的 L1 Cache 降低 hit time、降低功耗
⭐ 2. Way Prediction（路预测） 预测选中路，加速命中
增加带宽 3. Cache 访问流水化 提高 Cache 带宽
4. Nonblocking Cache（无阻塞） 失效时继续命中
5. Multibanked Cache（多体） 并行访问不同体
减小失效开销 6. Critical Word First & Early Restart 块大时有效
7. Write Merging（合并写） 缓解写缓冲满停顿
降低失效率 8. 编译器优化 软件改善局部性
并行 9. 硬件预取 利用空闲带宽
10. 编译器控制预取 ISA 增加预取指令

1. 小而简单的 L1 Cache

  • 容量小 → 命中时间短 → 易做在片内
  • 方案：Tag 在片内，块数据在片外（如 DEC Alpha）
  • Critical timing path：定位组 → 比较 tags → 选择正确块
  • 直接映象：数据传输和 tag 比较可并行
  • 低相联度：减少 tag 比较次数 → 降低功耗

2. Way Prediction（路预测）

  • 预测被选中的路，减少等待时间
  • 预测错误 → 更长的命中时间
  • 准确率：2-way 90%+，4-way 80%+，I-cache > D-cache
  • 首次使用：MIPS R10000；用于 ARM Cortex-A8

3. Cache 访问流水化

  • 将 L1 访问分为多个时钟周期
  • 示例：Pentium 1 cycle，PPro-P3 2 cycles，P4-i7 4 cycles，Power7 3 cycles
  • 缺点：增加流水线段数 → 分支预测错误开销增大、Load-Use latency 增加

4. Nonblocking Cache（无阻塞 Cache）

  • ⭐ 允许 Cache 失效时 CPU 继续命中
  • Hit under Miss → 减少有效失效开销
  • Hit under Multiple Misses → 进一步减少开销，但增加控制器复杂性
  • MSHR（Miss Status Holding Register）：
    • Primary miss：第一次发起的失效
    • Secondary miss：后续过程中的失效
    • Structural Stall miss：MSHR 资源耗尽
    • 相同块的多个 Load/Store 可共用一个 MSHR 表项

5. Multibanked Cache（多体 Cache）

  • 将 Cache 组织为多个独立 banks 支持并行访问
  • ARM Cortex-A8：1-4 banks L2；Intel i7：4 banks L1，8 banks L2
  • Multi-Ported Cache：两个地址端口（支持每 cycle 两条 load/store）
    • True Multi-ported：所有控制和数据通路多份 → 面积和访问时间显著增加
  • ⭐ Multi-Banked 是更实际的方案

6. Critical Word First & Early Restart

  • 关键字优先（Critical Word First）：首先请求 CPU 所需的字，到达即发给 CPU
  • 提前重启（Early Restart）：请求字顺序不变，到达即发给 CPU
  • 通常块较大时才有效

7. Write Merging（合并写）

  • 写缓冲器中已有被修改的块时，新写入数据与该块合并
  • 可缓解写缓冲满造成的 CPU 停顿
  • 减少 Store 到同一块的多次写缓冲占用

8. 编译器优化

无需硬件改动，通过软件优化降低失效率：

方法 原理 示例
⭐ 数组合并 融合循环，利用时间局部性 两个连续循环融合为一个
⭐ 内外循环交换 改变遍历顺序，利用空间局部性 for(j) for(i) → for(i) for(j)
⭐ 分块（Blocking/Tiling） 子矩阵运算适合 Cache 矩阵乘法分块执行

指令重新排序可使 2KB 直接映象 I-cache 失效率降 50%，8KB 降 75%。

4.15 预取技术

硬件预取（Hardware Prefetching）

CPU 执行当前块时，硬件预取下一块代码。⭐ 利用存储器的空闲带宽，不与正常操作竞争。

指令预取

  • AXP 21064：失效时取 2 块（目标块 → I-cache，下一块 → ISB 指令流缓冲）
  • ISB 命中 → 取消访存请求，从 ISB 读取，发下一块预取
  • 4KB 直接映象 Cache，16B blocks：1-block ISB 捕获 15%-25% 失效，4-block ISB 捕获 50%，16-block ISB 捕获 72%

数据预取

  • 4KB 直接映象，16B blocks：1-block DSB 捕获 25%，4-block DSB 捕获 43%
  • 64KB 4-way（I+D）+ 8-block 流缓冲：50%-70%

预取 AMAT 计算

$$
\text{AMAT}_{prefetch} = \text{Hit Time} + \text{Miss Rate} \times \text{Prefetch Hit Rate} \times 1 + \text{Miss Rate} \times (1-\text{Prefetch Hit Rate}) \times \text{Miss Penalty}
$$

$$
\boxed{
\text{AMAT}{pf}
= T_h ;+; MR \Big(\phi\cdot C{pf_eff} ;+; (1-\phi)\cdot MP\Big)
}
$$

并显式定义：

  • Th：Hit Time（含 tag/数据取出，不含 miss 路径）
  • MR：观测到的（或原始）miss rate / access
  • ϕ：在“会发生 miss 的请求”中，比例多少因预取而命中且足够早（需实验或严格定义为条件概率）
  • Cpf_eff：此时仍要付的残余代价（0～MP 之间；若你认为理想隐藏=0，就写 0，但要承认这是理想化）
  • 若你还想严谨：再加一项 ρpf：预取引起的 per-access 干扰/带宽税

编译器控制预取（Compiler Prefetching）

ISA 中增加预取指令，让编译器控制。

预取种类

种类 说明
寄存器预取 数据取到寄存器
Cache 预取 数据只取到 Cache，不放入寄存器

故障问题

  • 故障性预取：预取时若虚地址故障或违反权限，产生异常
  • 非故障性预取：异常转化为空操作
  • ⭐ 只有 CPU 可继续执行时预取才有意义 → 需配合非阻塞 Cache

编译器预取策略

  • 循环是预取优化的主要目标
  • 失效开销小 → 循环展开 1-2 次
  • 失效开销大 → 展开多次，为较远循环预取
  • 避免不必要的预取（预取指令本身有开销）

预取例题

  • 8KB 直接映象 D-cache，16B blocks，write-back + write allocate
  • 数组 a[3][100]，b[101][3]，元素 8B（double）
  • 原始：a 导致 150 misses，b 导致 101 misses → 共 251 misses
  • 优化：预取 a[i][j+7] 和 b[j+7][0]，提前 7 次迭代
  • 结果：仅 19 次非预取 misses，避免了 232 次 misses，代价为 400 条预取指令
  • ⭐ 非常值得！ 减少了 232×100=23200 cycles 的停顿

4.16 存储器技术与优化

存储器性能指标

  • Access Time：发出请求到数据到达
  • Cycle Time：两次访问之间的最小间隔（Cycle Time >= Access Time）

DRAM vs SRAM

维度 DRAM SRAM
每位晶体管数 1 个 6 个
读特性 ⭐ 破坏性读（读后需重新写回） 非破坏性
刷新 必须周期性刷新 不需要
地址线 复用（RAS + CAS） 不复用
功耗 需要刷新功耗 只需保持状态

DRAM 访问三阶段

  1. Precharge（预充电）
  2. Row Access（行访问，RAS）
  3. Column Access（列访问，CAS）

DRAM 性能两个维度

  • Latency：请求发出到第一组数据到达的 cycle 数
  • Bandwidth：第一组数据到达后后续数据的传输速率

DRAM 优化技术

技术 原理

Wider Interfaces 增宽数据通路
⭐ DDR（Double Data Rate） 上升沿和下降沿都传输数据

提高主存性能的三种组织方式

方式 结构 特点

Wide CPU/Mux-1 word → Mux/Cache-多 words 简单直接，增加宽度，部分写问题
⭐ Interleaved 多个 Memory Modules 交叉编址 带宽高，冲突少

⭐ 多体交叉存储器（Interleaved Memory）

  • 存储器组织为多个 Bank，每个 Bank 宽度一个字
  • 基本原则：Bank 数 >= 访问一个字所需的时钟周期数
  • 4-way 交叉后可连续无等待访问

性能计算例题

    • 32 位不交叉：CPI = 3.54
    • 32 位多体交叉：CPI = 2.86（性能提高 10%）
    • 64 位不交叉：CPI = 2.77（性能提高 14%）

Memory 功耗优化

  • 降低电压
  • 低功耗模式（忽略时钟，继续刷新）
  • 三种状态：Shutdown（最低）、Typical system（DRAM 活跃 30% 读 + 15% 写）、Fully active

4.17 虚拟存储器

核心概念

  • ⭐ 目的：允许应用程序大小超过主存容量，提高存储系统容量；帮助 OS 进行多进程管理
    • 每个进程有自己的地址空间
    • 提供多个进程空间的保护
    • 多个逻辑块映射到共享的物理存储器
    • 静态重定位和动态重定位（虚实转换对用户透明）
  • 失效：页失效（Page Fault） / 地址失效
  • 块：页（Page） 或 段（Segment）

⭐ VM 的四个问题（类比 Cache 的 4Q）

Q1: 映像规则

  • ⭐ 选择全相联映射（因为失效开销很大，需要低失效率）

Q2: 查找算法

  • 固定页大小 → 页表（Page Table）：VPN → PPN + Protection + Valid + Dirty + Use Bit
  • 页表项数 = 虚页数量（通常很大）
  • 可变长段 → 段表（Segment Table）：段号 → 段基址 + 偏移量

Q3: 替换规则

  • LRU 最好，但硬件代价大
  • ⭐ 用 use bit 辅助近似 LRU：访问某页时 use bit 置位，OS 定期复位所有 use bit，根据复位前的 use bit 值反映最近访问情况来决定替换

Q4: 写策略

  • ⭐ 总是用写回法（因为访问硬盘速度很慢）

⭐ TLB（Translation Lookaside Buffer）

  • 问题：页表存放在主存 → 每次访存可能要两次访问主存
  • 解决：TLB — 存放近期常用页表项，是页表的部分副本
  • 必须在片内（速度至关重要）
  • 每项包含：VPN，PPN，Protection Field，use bit，dirty bit
  • OS 修改页表项时需刷新 TLB
  • 相联度较高（容量小，适合全相联或高相联）

TLB 典型参数

参数 值
Block size 与页表相同（一个页）
Entry 1-2 words
Hit time 1 cycle
Miss penalty 10-30 cycles
Miss rate 0.1%-2%
TLB size 32B - 8KB

4.Z 本章关键概念清单

  • 局部性原理：时间局部性和空间局部性是存储层次工作的根本原理
  • 块（Block）：存储层次间数据传输的基本单位，不同层次块大小可以不同
  • 命中/失效（Hit/Miss）：访问数据在当前层次中找到/未找到
  • AMAT 公式：Hit Time + Miss Rate x Miss Penalty，贯穿全章的核心度量
  • 三种映像方式：全相联、直接映象、组相联，相联度与失效率/命中时间的权衡
  • Tag 标记：Address Tags（块定位）和 Status Tags（块状态如 Valid、Dirty）
  • 并行查找：所有可能的标记必须并行比较，以保证 Cache 速度
  • 替换算法：LRU 最常用，利用时间局部性；Random 简单；FIFO 较少使用
  • 写策略：写直达（Write Through）vs 写回（Write Back）；按写分配 vs 不按写分配
  • 3C 模型：强制性失效（Cold）、容量失效（Capacity）、冲突失效（Conflict）
  • 块大小权衡：失效率先降后升，必须综合考虑 AMAT
  • Victim Cache：小全相联 Cache 存放冲突失效块，有效减少冲突失效
  • 多级 Cache：L1 小且快，L2 大且慢；包容 vs 不包容
  • 局部失效率 vs 全局失效率：全局失效率是衡量 L2 的更好指标
  • 多级 AMAT：递归公式，L1 失效开销 = L2 Hit Time + L2 Miss Rate x L2 Miss Penalty
  • 读优先于写：Write Buffer 检查避免 RAW 冲突；Victim Buffer 缓存脏块
  • VIPT Cache：虚拟地址做 Index、物理地址做 Tag，需满足 Index 位数 <= 页内偏移位数
  • 十大 Cache 优化方法：涵盖缩短命中时间、增加带宽、减小失效开销、降低失效率、并行五个类别
  • 无阻塞 Cache：允许失效时继续命中，MSHR 管理多个并发失效
  • 路预测（Way Prediction）：预测选中路加速命中，预测错误代价是更长命中时间
  • 编译器优化：数组合并、内外循环交换、分块（Tiling）三种方法改善局部性
  • 硬件预取：利用空闲带宽预取下一块，指令流缓冲（ISB）和数据流缓冲（DSB）
  • 编译器预取：循环展开 + 预取指令，需配合非阻塞 Cache
  • DRAM vs SRAM：DRAM 破坏性读、需刷新、用于主存；SRAM 非破坏性、用于 Cache
  • DDR：双倍数据速率，上升沿和下降沿都传输数据
  • 多体交叉存储器：Bank 数 >= 访问周期数，实现无等待连续访问
  • 虚拟存储器目的：提高容量（对比 Cache 提高速度），支持多进程管理
  • VM 四个问题：全相联映射、页表查找、use bit 近似 LRU、写回法
  • TLB：页表的高速缓存，片内全相联/高相联，hit time 1 cycle
  • Cache vs VM 对比：速度 vs 容量、硬件处理 vs OS 处理、块大小差异、失效开销差异巨大
