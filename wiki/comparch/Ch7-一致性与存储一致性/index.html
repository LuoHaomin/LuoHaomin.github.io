Ch7 多处理器：Cache 一致性与存储一致性

Ch7 多处理器：Cache 一致性与存储一致性

课件：chapter07-1-Coherence-I.pdf + chapter07-1-Coherence-II.pdf + chapter07-1-Consistency.pdf
教材：Computer Architecture: A Quantitative Approach 6th Ed, Appendix & Ch5；Sorin/Hill/Wood《A Primer on Memory Consistency and Cache Coherence》

7.0 本章概述

单处理机的性能提升正在走向尽头（复杂度与硅技术改进带来的收益递减），把多个处理器连在一起是获得超过单处理器性能最直接的方法。多处理机带来两个核心挑战和一个重要问题：

  1. 有限的并行性（Amdahl 定律约束）；
  2. 较高的通信开销（远程访问延迟 35～>500 周期）；
  3. 存储器访问的序问题 —— 又细分为两个层次：
    • 存储一致性（Cache Coherence，一致性）：不同处理器访问同一存储单元时的顺序；
    • 存储同一性（Memory Consistency，同一性）：不同处理器对所有（不同）存储单元并发操作的顺序。

本章正是围绕这两个"序"展开：先讲一致性协议（监听 Snooping + 目录 Directory，含 MSI/MESI/MOESI），再讲同一性模型（SC + 松弛模型 TSO/RMO/WO/RC + 同步原语）。

7.1 引言：并行计算机的动因与分类

7.1.1 Flynn 分类法

按**指令流（instruction stream）和数据流（data stream）**的多寡，Flynn 把计算机分为：

类别 全称 典型
SISD Single Instruction Single Data 传统单处理机
SIMD Single Instruction Multiple Data 向量机、GPU 的 warp
MISD Multiple Instruction Single Data 罕见（容错结构）
MIMD Multiple Instruction Multiple Data 通用多处理机的主流选择

MIMD 成为通用多处理机的选择，原因：① 灵活性高；② 可充分利用商品化微处理器的性价比优势。

7.1.2 两种地址空间与两种通信模型

地址空间的两种组织方案：

  1. 共享存储（多处理机，Multiprocessor）：物理上分离的多个存储器可作为一个逻辑上共享的地址空间编址。
  2. 非共享存储（多计算机，Multicomputer）：整个地址空间由多个独立的地址空间构成，逻辑上也独立，远程处理器不能对其直接寻址。每个"处理器-存储器模块"实际就是一台单独的计算机。

两种通信模型：

模型 通信方式 优点
共享地址空间 用 Load/Store 指令的地址隐式通信 编程易（通信模式复杂/动态变化时占优）、通信数据小时开销低、硬件 Cache 减少远程通信频度
消息传递（多个地址空间） 处理器间显式传递消息 硬件简单、通信显式促使程序员关注昂贵通信

7.1.3 基于共享存储的 MIMD 分类

按存储器组织与处理器数量：

类型 全称 别名 特点
SMP 集中式共享存储器 UMA（Uniform Memory Access） 处理器少时经济；所有处理器访问任意存储器延迟相同
DSM 分布式共享存储器 NUMA（Non-Uniform Memory Access） 每个结点含 CPU+存储器+I/O；可扩放性好；需要高带宽互连；本地访问快、远程访问慢

拓扑示意：SMP 是多个 Cache → 共享总线 → 集中存储器；DSM 是多个（CPU+Cache+本地存储器+I/O）结点 → 互连网络。

7.1.4 挑战之一：有限的并行性 —— Amdahl 定律 ⭐⭐⭐

例 7.1：想用 100 个处理器达到 80 的加速比，求原程序中串行部分所占比例。

Amdahl 定律加速比公式：

Speedup=1可加速部分比例理论加速比+(1−可加速部分比例)\text{Speedup} = \dfrac{1}{\dfrac{\text{可加速部分比例}}{\text{理论加速比}} + (1 - \text{可加速部分比例})} Speedup=理论加速比可加速部分比例​+(1−可加速部分比例)1​

代入：

80=1并行比例100+(1−并行比例)80 = \dfrac{1}{\dfrac{\text{并行比例}}{100} + (1 - \text{并行比例})} 80=100并行比例​+(1−并行比例)1​

解得 并行比例 = 0.9975，即串行部分仅能占 0.25%。这说明要发挥大规模并行的性能，程序中哪怕极小的串行比例都会成为瓶颈。

7.1.5 挑战之二：远程访问延迟 ⭐⭐⭐

多处理机中远程访问延迟较大：

  • 同一芯片 core 之间：35～50 cycles
  • 不同芯片 core 之间：100～>500 cycles

典型机器远程访问时间（查表）：

机器 通信机制 互连网络 处理机数 典型远程访存时间
SPARC Center 共享 总线 ≤20 1 μs
SGI Challenge 共享 总线 ≤36 1 μs
Cray T3D 共享 3 维环网 32–2048 1 μs
Convex Exemplar 共享 交叉开关 + 环 8–64 2 μs
KSR-1 共享 多层次环 32–256 2–6 μs
CM-5 消息传递 胖树 32–1024 10 μs

IBM SP-2 消息传递 多级开关 2–512 30–100 μs

例 7.2（⭐⭐⭐ 高频数值题）：32 个处理器，远程访存时间 2000 ns，处理器时钟 10 ns，基本 CPI=1.0（所有访存命中 Cache），有 0.5% 指令需远程访问（发出远程请求时本处理器挂起），求有/无远程访问两种情况的速度比。

解：

远程访问开销=2000 ns10 ns=200 cycles\text{远程访问开销} = \dfrac{2000\,\text{ns}}{10\,\text{ns}} = 200\,\text{cycles} 远程访问开销=10ns2000ns​=200cycles

CPI有远程=CPI基+远程访问率×远程访问开销=1.0+0.5%×200=1.0+1.0=2.0\text{CPI}_{\text{有远程}} = \text{CPI}_{\text{基}} + \text{远程访问率} \times \text{远程访问开销} = 1.0 + 0.5\% \times 200 = 1.0 + 1.0 = 2.0 CPI有远程​=CPI基​+远程访问率×远程访问开销=1.0+0.5%×200=1.0+1.0=2.0

所以无远程访问（CPI=1.0）的机器是远程访问机器的 2.0/1.0 = 2 倍快。

结论记忆点：即使只有 0.5% 的指令触发远程访问，也能让 CPI 翻倍 —— 通信延迟对性能的杀伤极大，必须靠体系结构支持和编程技术来隐藏/降低。

7.1.6 通信延迟的隐藏

  • 并行性不足 → 用并行性更好的算法解决；
  • 远程访问延迟 → 靠体系结构支持 + 编程技术（如预取、多线程切换隐藏延迟、Cache 减少远程访问频度）；
  • 共享存储访问序 → 靠一致性协议 + 同一性模型。

7.2 集中式共享存储器与 Cache 一致性问题

7.2.1 集中式共享存储（SMP）特点

  • 多个处理器共享一个存储器；
  • 处理器规模较小时经济；
  • 支持对共享数据和私有数据的 Cache 缓存：
    • 私有数据：只有一个处理器使用；
    • 共享数据：多个处理器使用。
  • 共享数据进入 Cache 引发了新的问题：Cache 一致性问题。

7.2.2 Cache 一致性问题的来源

两类原因：

  1. I/O 操作：Cache 内容可能与 I/O 子系统 DMA 读写形成的存储器内容不同。
    • Memory→Disk：若 Cache 数据被改过未写回，存储器是陈旧数据；
    • Disk→Memory：DMA 写了存储器，但 Cache 不知道这次写操作，Cache 中的数据陈旧。
  2. 共享数据：不同处理器的 Cache 都保存了同一存储单元的副本。

典型不一致例子（P1/P2/P3 共享变量 u，初值 5）：P3 执行写操作后，各处理器看到的 u 不同（P1 cache=5, P2 cache=5, P3 cache=7, 内存=5）。对 write-back cache，处理器访问主存可能读到陈旧值，且结果依赖 cache 写回顺序。

7.2.3 存储系统"一致"的正式定义 ⭐⭐⭐

非正式定义：对某数据项的任何读操作均可得到其最新写入的值，则称该存储系统是一致的（coherent）。

正式三条件：

  1. 处理器 P 对 X 写之后又对 X 读，读写之间没有其它处理器对 X 写，则读总返回写进的值；
  2. 一个处理器对 X 写之后，另一处理器对 X 读，读写之间无其它写，则读返回写进的值；
  3. 对同一单元的写是**串行化（serialized）**的：任意两个处理器看到的同一单元的两次写顺序都相同。

两点假设（保证手段）：

  • 写传播（Write Propagation）：直到所有处理器都"看到"了写的结果，一次写才算完成；
  • 写串行化（Write Serialization）：允许处理器无序读，但必须以程序序写。

7.2.4 一致性（Coherence）vs 同一性（Consistency）⭐⭐⭐

这是最容易混淆的概念，务必区分：

Coherence（一致性） Consistency（同一性）
关注的地址 相同存储单元 **所有（含不同）**存储单元
关注的序 访问每个 Cache 块的局部序 所有存储器操作的全局全序
解决手段 Cache 一致性协议（监听/目录） 存储同一性模型（SC/松弛模型）

参见 Sorin, Hill, Wood《A Primer on Memory Consistency and Cache Coherence》(2011)。

7.2.5 Cache 在多处理机中的两种功能

一致性多处理机中，Cache 提供：

  1. 共享数据的迁移（migration）：降低对远程共享数据的访问延迟、降低对共享存储器的带宽需求；
  2. 共享数据的复制（replication）：不仅降低延迟，还减少访问共享数据产生的冲突。

小规模多处理机用硬件（非软件）实现 Cache 一致性。

7.2.6 跟踪共享数据状态的两种技术 ⭐⭐⭐

技术 思想
目录（Directory） 在一个集中/分布的"目录"数据结构里保存每个可被 Cache 的块的访问状态、共享状态、修改状态
监听（Bus Snooping） 每个 Cache 除数据外，还保存各块的共享状态；Cache 控制器**监听（snoop）**总线上的事务

7.3 监听协议（Snooping）：写作废 / 写更新

7.3.1 写作废 vs 写更新 ⭐⭐⭐

协议 写时动作
写作废（Write-Invalidate） 写之前保证写者对该数据项有唯一访问权（作废其他 Cache 副本）
写更新（Write-Update） 写时通过广播更新其他 Cache 中所有对应副本

写作废时序示例（write-back cache）：

处理器行为 总线行为 CPU A Cache CPU B Cache 主存 X
CPU A 读 X Cache 失效 0 0
CPU B 读 X Cache 失效 0 0 0
CPU A 写 X=1 作废 X 1 （作废） 0
CPU B 读 X Cache 失效 1 1 1

写更新时序示例：

处理器行为 总线行为 CPU A Cache CPU B Cache 主存 X
CPU A 读 X Cache 失效 0 0
CPU B 读 X Cache 失效 0 0 0
CPU A 写 X=1 广播写 X 1 1 1
CPU B 读 X （命中） 1 1 1

性能差别（记忆）：

  • 同一数据多次写中间无读：写更新需多次广播，写作废只需一次作废；
  • 同一块中多个字写：写更新对每个字都要广播，写作废仅第一次写时作废；
  • 写→读延迟：写更新较低（读者直接看到新值）；写作废需读新拷贝（一次 miss）。

结论：基于总线的多处理机中，写作废协议成为绝大多数系统的选择。

7.3.2 监听协议的基本实现技术

  • 小规模多处理机用总线进行作废（invalidate）操作；每个块的有效位让作废机制易于实现。
  • 写直达 Cache：所有写同时写回主存，主存总能取到最新值。
  • 写回 Cache：最新值可能在某 Cache 也可能在主存 —— 实现：
    • 用 Cache 块的**标志位（tag）**实现监听；
    • 给每个 Cache 块加一个状态位说明它是否共享。

总线作为广播媒介的两个关键性质：

  1. 总线上的事务对所有 Cache 可见；
  2. 这些事务对所有控制器以同样的顺序可见（这是写串行化的基础）。

Cache 控制器接收两类输入：处理器请求（load/store） + 监听器（snooper）的总线请求/响应，据此更新状态、提供数据、产生新总线事务。

7.4 MSI 协议（写回、写作废）⭐⭐⭐

7.4.1 三态定义

状态 含义
M（Modified） 仅该 Cache 拥有修改过的、有效的块副本；内存中的值陈旧
S（Shared） 干净块（clean），其他 Cache 中也可能含该块；内存内容是最新的
I（Invalid） 无效块

7.4.2 四类总线事务

信号 含义
BusRd（Bus Read） 读失效时产生，请求一个块的只读副本
BusRdX（Bus Read Exclusive） 写失效时产生，读进并意图修改；导致其他 Cache 中对应块作废，得到独占副本
BusUpgr（Bus Upgrade） S→M 升级，仅引起作废，不读块（已有副本）
Flush（on BusRd or BusRdX） Cache 把块放到总线上（而非从存储器取），完成 Cache-to-Cache（C2C） 传送并更新存储器
BusWB（Bus Write-Back） 替换操作把修改过的块写回

写操作时作废所有其他副本；直到 invalidate 事务出现在总线上，写操作才算完成；写串行化由总线事务的总线串行化保证。

7.4.3 MSI 完整状态转换表 ⭐⭐⭐（最高频考点）

下表中行为"事件"，列为"当前状态"，单元格为"新状态 / 动作"。— 表示无动作。

(a) 由处理器请求触发（PrRd / PrWr / Replace）：

当前事件 \ 状态 I S M
PrRd（处理器读） → S / 发 BusRd → S / —（命中） → M / —（命中）
PrWr（处理器写） → M / 发 BusRdX → M / 发 BusRdX（或 BusUpgr） → M / —（命中，无总线事务）
Replace（块替换） → I / — → I / — → I / 发 BusWB

(b) 由监听总线事务触发（其他处理器的总线请求）：

监听到的事件 \ 状态 I S M
BusRd → I / — → S / — → S / 发 Flush（更新内存和请求方）
BusRdX / BusUpgr → I / — → I / —（被作废） → I / 发 Flush

关键迁移：M 态收到 BusRd 时 M→S 并 Flush（数据回写）；M 态收到 BusRdX 时 M→I 并 Flush（让出所有权）。

7.4.4 M→S 还是 M→I？低层设计选择

当 M 态块观察到 BusRd 时，可选择迁到 S 或 I：

  • M→S：适合不久后本地还要读、其他处理器很少写的访问模式（读多写少）；
  • M→I：适合其他处理器频繁写、数据迁移模式（连续对称式访问）。

不同选择影响存储器性能。

7.4.5 MSI 工作示例 ⭐⭐⭐

设 A1、A2 映射到同一 Cache 块，初值 u=5，各 Cache 初始 Invalid：

步骤 处理器动作 P1 状态 P2 状态 P3 状态 总线动作 数据来源
1 P1 读 u S BusRd Memory
2 P3 读 u S S BusRd Memory
3 P3 写 u I M BusRdX Memory
4 P1 读 u S S BusRd, Flush P3 cache
5 P2 读 u S S S BusRd Memory

注意步骤 4：P3 处于 M 态，数据最新在 P3 cache，故 P3 发起 Flush 完成 C2C 传送，自身降为 S。

7.4.6 MSI 满足一致性的两条保证

写传播（Write propagation）：对 shared/invalid 块的写，其他 Cache 都可见 —— 通过 BusRdX 事务作废其他 Cache，其他处理器在看到该写效果前体验到 Cache Miss。

写串行（Write serialization）：总线上所有写操作（BusRdX）被总线串行化，所有处理器以同样方式排序；先更新写者本地 cache，再处理其他事务。注意：不是所有写都在总线上（对 M 块的连续写来自同一处理器，不发总线事务），同一处理器对它的读看到串行写序；其他处理器的读会触发总线事务，保证对该处理器也串行。

7.5 MESI 协议（Illinois 协议）⭐⭐⭐

7.5.1 为什么要加 Exclusive 态

MSI 的缺陷：读进并修改一个块，即使该块在系统中只有这一个 Cache 副本（本可独占），仍产生两个总线事务：先 BusRd（I→S），再 BusRdX（S→M）。这在多道程序负载下非常普遍。

解决办法：增加 Exclusive（E）态，表示仅当前 Cache 含该块，且是干净块（与内存一致）。E 态写时不产生总线事务（S→M 之间省一次作废），从而区分了独占块的 clean 和 dirty。

7.5.2 四态定义

状态 含义 内存最新？
M（Modified） 仅当前 Cache 含该块，且已修改 否（陈旧）
E（Exclusive / Exclusive-clean） 仅当前 Cache 含该块，且未修改 是（最新）
S（Shared） 多个 Cache 含本块，都未修改 是（最新）
I（Invalid） 无效 —

也称 Illinois 协议，广泛用于现代微处理器。

7.5.3 硬件支持：Shared signal（wired-OR）

总线互连的新要求：增加一根 shared signal S，必须对所有 Cache 控制器可用，可做成 wired-OR（线或）线。所有 cache 监测 BusRd：

  • 若所访问块在自己 cache 中状态为 S/E/M，则置位 shared signal；
  • 请求方根据 shared signal 是否被置位决定进入 E（未被置位，独占）还是 S（被置位，共享）。

7.5.4 MESI 完整状态转换表 ⭐⭐⭐

记 BusRd(S) 表示 BusRd 且 shared 置位，BusRd(~S) 表示 shared 未置位。

(a) 处理器请求触发：

事件 \ 状态 I S E M
PrRd → E or S / 发 BusRd（看 S 线：~S→E，S→S） → S / — → E / — → M / —
PrWr → M / 发 BusRdX（+ 作废） → M / 发 BusUpgr（仅作废） → M / —（无需总线！） → M / —
Replace → I / — → I / — → I / —（干净，丢弃） → I / 发 BusWB

(b) 监听到总线事务触发：

监听事件 \ 状态 I S E M
BusRd → I / — → S / — → S / —（被分享了） → S / Flush（C2C + 更新内存）
BusRdX / BusUpgr → I / — → I / — → I / — → I / Flush

E→M 写无需总线事务是 MESI 相比 MSI 的核心收益（一次"读-改"从 2 个总线事务降为 1 个 BusRd）。

7.5.5 MESI 低层设计选择

  • E/S 态时由谁提供数据？Original Illinois MESI：Cache 提供（假设 cache 比 memory 快）。但 cache-to-cache 增加复杂性：内存如何知道该不该提供（必须等 cache 响应）、多个 cache 共享时要有选择机制。
  • M 态 flush 时是否更新内存？内存比 cache 慢。若只让 cache 接收、内存不接收 → 需要第 5 个状态 Owned → 引出 MOESI。

7.5.6 Cache-to-Cache（C2C）Sharing

原 Illinois 版本支持 C2C：由 Cache 提供数据而非由内存提供。BusRd(S) 时由 cache 而非 memory 提供 → BusRd/C2C 转换。

7.6 MOESI 协议（加 Owned 态）⭐⭐

7.6.1 为什么加 Owned 态

MESI 的 M 态在 flush 时必须同时更新 cache 和内存（内存慢）。引入 Owned（O）态：一个"共享的 Modified 态"——存储器不是最新，但块可被多个 Cache 共享，所有者（owner）只有一个。

7.6.2 O 与 S 的区别（重点辨析）

  • Owned 位 = 1：当前 Cache 含有最新数据拷贝，且其他 CPU 中一定有该块副本（其他副本处于 S）。当内存数据在多个 CPU Cache 中都有副本时，有且仅有一个 CPU 的 cache 处于 O，其他只能处于 S。O 态 cache 数据与内存不一致。
  • Shared 位：S 态 cache 数据不一定与内存一致：
    • 若其他 CPU 中无 O 副本 → S 态数据与内存一致；
    • 若其他 CPU 中有 O 副本 → S 态数据与内存不一致。

简言之：MESI 的 M 被"拆"成 M（独占脏）和 O（共享脏，有 owner），使脏块被读共享时不必回写内存，M→O 即可（owner 继续提供数据）。

7.7 Coherence Miss（一致性别失效）⭐⭐⭐

7.7.1 第 4 个 C

Cache 性能由两部分构成：单处理器 cache miss 的通信量 + 通信引起的通信量（作废机制导致后续访问失效）。后者称 Coherence Miss，又称 Communication Miss，是继 Compulsory、Capacity、Conflict 之后的第 4 个 C。

7.7.2 True Sharing vs False Sharing ⭐⭐⭐

类型 定义 关键特征
True Sharing Miss（真共享） Cache 一致性机制引起的真实数据通信：不同处理器读写同一变量 即便块大小为 1 个字，失效仍会发生
False Sharing Miss（假共享） 失效只因某个字处于一个被作废的块中：读写同一块中不同变量 失效未通过通信产生新值，仅产生额外失效；块大小为 1 字时不会发生

7.7.3 True & False Sharing 例子

变量 X、Y 属于同一 Cache 块。初始：P1、P2 均读了共享变量 X，Block(X,Y) 在 P1、P2 中均处于 Shared 态。

  • P1 写 X → P2 的 Block(X,Y) 被作废；
  • P2 读 Y（或 X）→ Cache miss。
    • 若 P2 读 X：真共享（确实需要 X 的新值）；
    • 若 P2 读 Y：假共享（Y 没变，只因 Y 与 X 同块而被连累）。

7.7.4 消除 False Sharing 的方法 ⭐⭐

  • Padding（填充）/对齐：把可能被不同处理器访问的变量分到不同 Cache 块（按 cache line 大小对齐），避免无辜变量被作废。
  • 调整数据布局（数组 vs 数组结构 / 结构数组）。
  • 减小并行粒度对齐到块边界。

7.7.5 实测数据观察（OLTP/数据库/搜索引擎，4 处理器）

  • 单处理器类 miss（Instruction、Capacity/Conflict、Compulsory）随 cache 增大（1MB→8MB L3）改善；
  • True/False sharing miss 几乎不随 cache 增大而改善（1MB→8MB 基本不变）；
  • 但它们随处理器数增加（1→8）而显著上升。这是 SMP 可扩放性的核心瓶颈。

7.8 监听协议的局限与目录协议（Directory）

7.8.1 监听协议的局限

  • 总线可扩放性受限：能连接的处理器数目有限；共享总线存在竞争；大量处理器时监听带宽是瓶颈。
  • 片上互连网络（多 bank 并行通信）只部分缓解，仍受限。
  • 在非总线/非环网络上监听困难：必须广播到所有处理器，效率低。

核心问题：如何不用广播而保持 cache coherence？→ 用目录记录每个 Cached 块的状态。

7.8.2 目录协议核心思想

目录（Directory）：记录共享块相关信息的数据结构，记载可进 Cache 的每个数据块的访问状态、在各处理器的共享状态、是否被修改等。

分布式共享存储（DSM）结构：每个结点（CPU+Cache+存储器+I/O）配备一个目录，目录项说明哪些私有 Cache 含该块副本。

7.8.3 目录项结构 ⭐⭐⭐

每个 Cache 块在目录中对应一项，含：

  • Presence bits（存在位）：k 个处理器 → k 位，每位指示对应处理器是否含该块副本；
  • State（状态位）：M / S / I（私有 cache 中）；
  • 可能的 owner 指针（粗/细指针）。

粗指针（Coarse pointer） vs 细指针（Fine pointer）：

  • 细指针：完整 presence bits（k 位），精确但占用空间；
  • 粗指针：用少量位近似（如指向一组处理器），节省空间但增加无效化广播范围。

7.8.4 目录位置

  • DSM 中：目录分布在每个 home 结点，记录本地存储器块的共享信息；
  • 片上多处理器（CMP）中：目录放在所有处理器共享的最外层 Cache中，外层 cache 分成多个 bank 并行访问。共享 cache 是私有 cache 块的超集（例：Intel Core i7），每个共享 cache 块加 presence bits(k) + state。

7.8.5 关键术语

术语 含义
Local / Private Cache 处理器请求的源
Home Directory 存放 Cache 块相关信息，用 presence bits + state 追踪
Remote Cache 含某 Cache 块副本（modified 或 shared）的其他 cache

Cache 一致性即保证 Single-Writer, Multiple-Readers。无总线，不广播，所有消息都有显式回复。

7.8.6 目录中块的状态

  • 私有（本地）cache 块：M / S / I（同 MSI）；
  • 共享 cache 块（4 态）：M（仅一个本地 cache 是 owner）/ Owned（modified 块已写回共享 cache 但未到内存，可被多本地 cache 共享）/ Shared / Uncached（不在任何本地或共享 cache）。

7.8.7 目录协议操作流程 ⭐⭐⭐

Read Miss by processor P（向 home directory 发 Read Miss）：

  • Home 状态 = M：directory 发 Fetch 给拥有者 remote cache；remote 发 Write-Back 到 directory（共享 cache），自身降为 S；directory 把块状态改为 Owned，置位 P 的 presence bit，发数据给 P；P 设为 S。
  • Home 状态 = Shared/Owned：directory 直接发数据给 P，置位 P 的 presence bit；P 设为 S。
  • Home 状态 = Uncached：从存储器取块，发数据给 P；P 设为 S。

Write Miss by P（向 directory 发 Write Miss）：

  • Home 状态 = M：directory 发 Fetch-Invalidate 给拥有者 Q；Q 直接发数据给 P，自身置 I；P 设为 M；directory 复位 Q 的 presence bit、置位 P 的。
  • Home 状态 = Shared/Owned：directory 据 presence bits 向所有共享者发 invalidate；收齐 ACK 后复位对应位；directory 发数据给 P，置位 P 的；P 与 directory 状态都改为 M。
  • Home 状态 = Uncached：从存储器取数据，发 P，P 设为 M。

Invalidating a block with sharers：据 presence bits 向所有 sharer 发 invalidate，收齐 ACK 后复位。

7.8.8 目录协议的 MSI / MOSI 状态图

  • 本地 cache 块的 MSI 状态图：与 7.4 监听 MSI 一致，把"总线事务"换成"目录消息"；
  • directory 端用 MOSI（多 Owned 态，记录共享脏的拥有者）。

7.9 存储同一性（Memory Consistency）

7.9.1 为什么需要同一性模型

一致性协议只保证：当对共享存储空间某单元修改后，对所有读者可见，即"每个单元都能返回最后一次写操作的值"。但它没有规定：

  • 写入的数据何时成为可见；
  • 处理器 P1、P2 对不同地址单元访问的顺序；
  • P2 对不同单元的读，相对于 P1 所见顺序。

一致性保证"flag 和 A 各自的写最终可见"，但不保证 P2 看到 flag=1 时一定看到 A=1。这正是同一性模型要规范的。

7.9.2 同一性的正式定义

定义：共享地址空间的存储同一性模型，是关于"多个处理器对不同存储单元并发读写时，每个进程看到的这些操作被完成的序"的一种约定。

7.9.3 顺序同一性 SC（Sequential Consistency）⭐⭐⭐ —— Lamport 定义

“A system is sequentially consistent if the result of any execution is the same as if the operations of all the processors were executed in some sequential order, and the operations of each individual processor appear in the order specified by the program.” —— Leslie Lamport

即 SC = 多个进程之间的存储器操作可以任意交叉 + 每个进程的存储器操作按程序序。

7.9.4 SC 的充分条件 ⭐⭐⭐

实现 SC 的三条充分条件：

  1. 每个进程按程序序发出存储操作；
  2. 发出写操作后，进程要等写的完成才能发下一个操作；
  3. 发出读操作后，进程不仅等读完成，还要等"产生所读数据的那个写操作"完成才能发下一操作 —— 即若该写对此处理器完成，则要等它对所有处理器都完成。

第 3 条保证写操作的原子性（write atomicity）：读操作必须等待逻辑上先前的写操作变得全局可见。

7.9.6 SC 实现困难的三个优化反例 ⭐⭐⭐（高频考点）

直觉上"单处理器上合理的存储器操作重排"会违反 SC。三种性能优化都会破坏 SC：

优化 1：带旁路的写缓冲（Write Buffer with Bypassing）
flag 的新值停在 write buffer 中，导致存储器操作序与程序序不同。例（Dekker 算法）：

若 flag=1 先于 Data=新值生效，两个进程可能同时进入临界区，违反 SC。

优化 2：重叠写（Overlapping Writes）
非总线互连 + 多存储器模块允许并行读写，导致 write Data 与 write Head 的完成序与程序序相反。P2 可能先读到 Head 新值、Data 旧值，违反 SC。

优化 3：非阻塞读（Non-blocking Reads）
P1 按程序序写，但 P2 允许重叠/投机/动态调度执行读。P2 的 Read Data 可能提前于 P1 的 Write Data，读到旧值，违反 SC。

7.9.7 为什么商用机不用严格 SC ⭐⭐

“No common commercial architecture has a sequentially consistent memory model!”

SC 约束所有四类序（W→R、W→W、R→R、R→W）。但现代微处理器普遍用 write buffer、overlapped writes、non-blocking reads 提升性能，这些都会破坏 SC。问题转化为：如何协调性能提升与 SC 约束？ → 松弛一致性模型。

7.10 松弛一致性模型（Relaxed Consistency Models）⭐⭐⭐

7.10.1 记号约定

X → Y：操作 X 必须在 Y 开始前完成。

SC 要求全部 4 种保序：

SC:R→W, R→R, W→R, W→W\text{SC}: \quad R \to W,\ R \to R,\ W \to R,\ W \to W SC:R→W, R→R, W→R, W→W

7.10.2 各模型放松的序与归属 ⭐⭐⭐

模型 全称/归属 保留的序 放松的序 典型架构

7.11 同步（Synchronization）

7.11.1 为什么需要同步

即使单核系统，存在并发进程就需要同步。两类经典问题：

7.11.2 Acquire / Release 语义与 Fence ⭐⭐⭐

实现弱/松弛一致性模型的处理器（允许不同地址 loads/stores 乱序）必须提供**存储器栅栏（Memory Fence / Memory Barrier）**指令，强制对某些存储器操作串行化。

Acquire 语义：acquire 操作之后的读写不能重排到 acquire 之前（保护临界区入口）。
Release 语义：release 操作之前的读写不能重排到 release 之后（保护临界区出口）。

ARM — DMB（Data Memory Barrier）
x86/64 TSO mfence（Global Memory Barrier）

Fence 代价较高，仅按需使用。

7.11.5 信号量（Semaphore，Dijkstra 1965）⭐⭐

信号量 s 是非负整数，两个操作：

  • P(s)：若 s>0 则 s 减 1，否则等待；
  • V(s)：s 加 1 并唤醒一个等待进程。
