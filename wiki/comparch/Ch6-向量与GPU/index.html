Ch6 数据级并行：向量处理器与 GPU

Ch6 数据级并行：向量处理器与 GPU

课件：chapter06-1-Vector.pdf (70 页) + chapter06-2-GPU.pdf (97 页)

主题：Data-Level Parallelism (DLP) in Vector, SIMD, and GPU Architectures

6.0 本章概述

本章回答一个核心问题：当**指令级并行（ILP）的挖掘接近极限时，如何利用程序中天然存在的数据级并行（Data Level Parallelism, DLP）**来继续提升性能？答案是 SIMD 类结构，它有三个主要变种：

子主题 核心思想 代表硬件 重要程度
向量体系结构 (Vector) 一条指令处理一整组（N 个）元素 Cray 系列超级计算机、NEC SX ⭐⭐⭐⭐⭐
多媒体 SIMD 扩展 (Subword SIMD) 把宽寄存器拆成多个窄通道并行 x86 MMX/SSE/AVX、ARM NEON、PowerPC AltiVec ⭐⭐⭐
GPU (SIMT) 大量线程 + 硬件动态聚合成 warp 执行 NVIDIA CUDA、AMD ⭐⭐⭐⭐⭐

Flynn 分类（1966）回顾：SISD（单处理器）、SIMD（挖掘 DLP，本章）、MISD（无商用实现）、MIMD（通用性最强，挖掘线程级/数据级并行，可松耦合也可紧耦合）。

6.1 数据级并行 DLP 的动机

6.1.1 传统 ILP 技术的问题

挖掘 ILP 提高性能的传统方法存在若干根本缺陷：

  • 程序内在的并行性有限：可挖掘的指令间并行度有上限。
  • 提高时钟频率可能反而使 CPI 增加：更高频率下 branches、其他 hazards 的影响被放大。
  • 指令预取和译码困难：每个周期很难预取/译码多条指令。
  • Cache 命中率受限：计算量大的应用（科学计算、连续媒体流 multimedia）局部性差，Cache 效果有限。

6.1.2 DLP 的兴起

应用需求推动体系结构发展：

  • 图形、机器视觉、语音识别、机器学习等新应用需要大量数值计算，其算法天然具有数据并行特征。
  • SIMD-based 结构（vector-SIMD、subword-SIMD、SIMT/GPUs）是执行这些算法的最有效途径。

6.1.3 SIMD 结构的优势 ⭐

优势 说明
有效挖掘 DLP 基于矩阵运算的科学计算、图像和声音处理
更节能 针对每组数据操作仅需取指一次（vs MIMD 每个数据一条指令），对 PMD（个人移动设备）尤其有吸引力
程序员友好 允许程序员继续以串行模式思维
潜在加速比高 对 x86：每年增加 2 cores/chip，但 SIMD 宽度每 4 年翻一番；SIMD 潜在加速比约为 MIMD 的 2 倍

6.1.4 SIMD 结构的三种类型

  1. 向量体系结构（Vector Architecture）
  2. 多媒体 SIMD 指令集扩展（Multimedia SIMD Extensions）
  3. 图形处理器（Graphics Processor Units, GPUs）

6.2 向量体系结构（Vector Architecture）

6.2.1 向量处理模型

向量处理机具有更高层次的操作：一条向量指令可以处理 N 个或 N 对操作数（处理对象是整个向量）。

6.2.2 起源：超级计算机（Supercomputers）

超级计算机的定义（任一即可）：

  • 对于给定任务而言世界上最快的机器；
  • 任何造价超过 3 千万美元的机器；
  • 计算能力达到每秒万亿次的机器。

历史脉络（均由 Seymour Cray 设计）：

  • CDC 6600（Cray, 1964）——被认为是第一台超级计算机。
    • 60-bit 字，128 Kword 主存，32 个存储体（banks）；
    • 10 个功能部件（并行、非流水线）：FP adder、2 multipliers、divider，integer adder、2 incrementers 等；
    • 硬布线控制（无微码）；Scoreboard 动态调度指令；
    • 10 个外设处理器（一个快速多线程 12-bit 整数 ALU）做 I/O；
    • 时钟 10 MHz（FP add 4 clocks），>40 万晶体管，750 平方英尺，5 吨，150 kW，氟利昂冷却；
    • 世界最快达 5 年（直到 7600），售出超过 100 台（每台 700-1000 万美元）。

有趣轶事：IBM CEO Thomas Watson Jr. 1963 年的备忘录感叹 CDC 只有 34 人（含清洁工）却造出世界最强计算机，Cray 回应：“看来 Watson 先生已经自己回答了自己的问题。”

典型应用领域：军事研究（核武器、密码学）、科学研究、天气预报、石油勘探、工业设计（汽车碰撞仿真）、生物信息学、密码学——均涉及大量数据集处理。

70-80 年代：Supercomputer = Vector Machine。

6.2.3 向量处理机的基本特性 ⭐

  • 基本思想：两个向量的对应分量进行运算，产生一个结果向量。
  • 一条向量指令包含多个操作 → fewer instruction fetches。
  • 每一结果独立于前面的结果：
    • 长流水线，编译器保证操作间无相关性；
    • 硬件仅需检测两条向量指令间的相关性；
    • 较高的时钟频率。
  • 向量指令以已知的模式访问存储器：
    • 可有效发挥多体交叉存储器的优势；
    • 可通过重叠减少存储器操作的延时（64 elements）；
    • 不需要数据 Cache！（仅使用指令 cache）。
  • 流水线控制中减少了控制相关。

6.2.4 向量处理机的基本结构

两种结构：

类型 说明 代表
memory-memory vector processors 所有向量操作是存储器到存储器 CDC Star-100 (1973)、TI ASC (1971)
vector-register processors ⭐ 除 load/store 外，所有操作是向量寄存器之间 Cray-1 (1976，第一台寄存器型)、Cyber-205、ETA-10；1980 年后所有向量机都是这种结构（Cray、Convex、Fujitsu、Hitachi、NEC）

对比（以 for(i) {C[i]=A[i]+B[i]; D[i]=A[i]-B[i];} 为例）：

存储器-存储器型（VMMA）的缺点：

  • 需要更高的存储器带宽（所有操作数都要读入写出存储器）；
  • 多个向量操作重叠执行较困难（必须在存储器地址上检查相关性）；
  • 启动时间更长（CDC Star-100：向量元素小于 100 时，标量代码比向量化代码还快）。

Cray-1 的实现特点：标量单元采用 Load/Store 结构；向量扩展部分包括向量寄存器和向量指令；硬布线逻辑控制；高效流水化功能部件；多体交叉存储系统；无 Data Cache；不支持 Virtual Memory。

向量指令集的优势 ⭐

  • 格式紧凑：一条指令包含 N 个操作；
  • 表达能力强，一条指令告诉硬件：
    • N 个操作之间无相关性；
    • 使用同样的功能部件；
    • 访问不相交的寄存器；
    • 以已知模式访问存储器（unit-stride load/store 连续块，或 strided load/store）；
  • 可扩展性好：可在多个并行的流水线（lanes）上运行同样代码。

6.2.5 向量处理机的基本组成单元 ⭐

部件 说明
向量寄存器（Vector Register） 固定长度区域，存放单个向量。至少 2 个读端口 + 1 个写端口（一般最少 16 读 8 写）。典型 8–32 个向量寄存器，每个寄存器存放 64–128 个 64-bit 元素
向量功能单元（Vector Functional Units, FUs） 全流水化，每一个 clock 启动一个新操作。一般 4–8 个 FUs：FP add、FP mult、FP reciprocal (1/X)、integer add、logical、shift；可能有些重复设置
向量 Load/Store 单元（LSUs） 全流水化地 load 或 store 一个向量，可能配置多个 LSU
标量寄存器（Scalar registers） 存放单个元素用于标量处理或存储地址
交叉开关（Cross-bar） 连接 FUs、LSUs、registers

向量运算执行（Vector Arithmetic Execution）

使用较深的流水线（=> fast clock）执行向量元素操作。由于向量元素相互独立，简化了深度流水线的控制（no hazards!）。例如六段乘法流水线执行 V3 <- V1 * V2。

多车道（Multiple Lanes）结构 ⭐

向量元素在多个 lane 之间**条带化（striped）**分布，每个 lane 含一个功能单元：

以 ADDV C,A,B 为例：

  • 单功能部件：A[0…6]、B[0…6] 依次进入，C[0]…C[2] 依次流出。
  • 4 条功能部件（4 lanes）：A[0…3]→C[0…3]，A[4…7]→C[4…7]…… 每周期可完成 4 个结果。

并行度来源：以「每个向量 32 元素，8 lanes」为例，可达到 24 operations/cycle，而每周期只发射 1 条短指令。

6.2.6 向量存储器系统（Interleaved Vector Memory）⭐

以 Cray-1：16 banks，4 cycle bank busy time，12 cycle latency 为例。

  • Bank busy time（体忙时间）：存储体在准备好接受下一个请求之前所需的时间。
  • 关键条件：若 stride = 1 且连续元素交错分布在各 bank 上，且 bank 数 ≥ bank latency，则可维持 1 element/cycle 的吞吐率。

体冲突（Bank Conflict）⭐

产生条件：当多个向量元素落到同一个 bank 且访问间隔小于 bank busy time 时。

  • stride = 1：理想情况，元素依次落入不同 bank。
  • stride = 32 + 16 banks：每次访问都命中同一个 bank → 严重体冲突（每 16 步回到同一 bank，但 stride 32 = 2×16，永远落在偶数 bank 之一……关键是 stride 与 bank 数不互质时易冲突）。

通用规则：若 stride 是 bank 数的整数倍（或二者不互质），会发生 bank conflict。设计时应使 bank 数为质数，或保证 stride 与 bank 数互质。

三类 Load/Store 寻址方式 ⭐

类型 说明 特点
Unit stride（单步长） 连续访问 最快
Non-unit (constant) stride（常数步长） 固定步长跳着访问 可能导致 bank conflict
Indexed (gather-scatter)（间接寻址） 地址由另一个向量（index vector）给出，等价于寄存器间接寻址 对稀疏矩阵有效；向量化操作的指令增多

6.2.7 向量执行时间与性能评估 ⭐⭐⭐

核心概念

概念 定义
Initiation rate（启动率） 功能部件消耗向量元素的速率
Convoy（编队） 可在同一时钟周期开始执行的指令集合（指令之间无结构或数据冲突）
Chime（钟鸣） 执行一个 convoy 所花费的近似时间
向量启动时间 由两部分组成：功能部件延时（一个操作通过功能部件的时间）+ 截止/恢复时间（dead time / recovery time）（运行下一条向量指令的间隔时间）

Chime 估算公式 ⭐

  • m 个 convoys 执行需要 m 个 chimes；
  • 每个 chime 约花费 n 个 clocks（n 为向量长度）；
  • 总时间 ≈ m×n clock cycles（忽略额外开销；向量长度较长时近似合理）。

⇒ 4 convoys × 64 = 256 clocks（约 4 clocks/result）。

分段开采（Strip Mining）⭐⭐

当 向量长度 N > 最大向量长度 MVL（Max Vector Length，向量寄存器长度，如 64）时怎么办？

Strip Mining（分段开采 / 分段向量化）：生成新代码，使每次向量操作的元素数 ≤ MVL。

  • 第一次循环做最小片 n mod MVL；
  • 之后按 VL = MVL 操作。

向量长度寄存器（VLR, Vector Length Register）⭐

  • VLR 控制特定向量操作的长度，包括向量的 load/store；
  • 一次操作的向量长度不能 > 向量寄存器长度（MVL）；
  • 例如 do 10 i=1,n: Y(i) = a*X(i) + Y(i) 中 n 只有运行时才知道；
  • n > MVL 时配合 strip mining 分多段处理。

性能计算公式 ⭐⭐⭐

含启动开销的总执行时间：

$$
T_n = \left\lceil \dfrac{n}{MVL} \right\rceil \times (T_{loop} + T_{start}) + n \times T_{chime}
$$

其中：

  • n：实际向量长度；
  • MVL：最大向量长度（如 64）；
  • Tloop：每段标量循环开销（如 15 cycles）；
  • Tstart：启动开销之和；
  • Tchime：每元素每 chime 的执行时间（约 1 cycle）。
⭐ 考题示例：$A = B \times s$

求 $A = B \times s$，其中 $A, B$ 为长度为 200 的向量（每个元素占 8 字节），$s$ 是标量。向量寄存器长度 MVL = 64。各功能部件启动时间如前所述（Load 12，Multiply 7，Store 12），$T_{loop} = 15$。

计算过程：

  1. 段数：⌈200/64⌉=4 段（前 3 段每段 64，最后一段处理 200 − 192 = 8 个元素，但分段开采里第一段处理 200 mod 64 = 8，后 3 段各 64）。
  2. 启动开销之和：Tstart=12(Load)+7(Multiply)+12(Store)=31。
  3. Chime 部分：3 条指令、3 个 convoy、每元素 1 cycle ⇒ n×Tchime=200×3=600（按公式分段：n×Tchime 项）。课件给出：
  • T200=660+4×31=660+124=784（其中 660 = 3 chimes × 220 之类的近似；以课件数字为准：总时间 784 cycles）。
  1. 每元素平均时间：784/200=3.92 cycles/element。

⭐ 务必记住：$T_{start} = 12 + 7 + 12 = 31$；$T_{200} = 660 + 4 \times 31 = 784$；每元素 = 3.9 cycles。

常用向量性能指标 ⭐

指标 含义
$R_\infty$ 向量长度为无穷大时的最大性能（峰值性能），单位 MFLOPS。实际问题向量长度有限，start-up 开销影响大
$R_n$ 向量长度为 $n$ 时的性能
$N_{1/2}$ 达到 $R_\infty$ 一半性能所需的向量长度，衡量 start-up 时间对性能的影响
$N_V$ 向量流水方式优于标量串行方式所需的向量长度临界值，既衡量建立时间也衡量标量/向量速度比

6.2.8 向量优化技术

优化 1：向量链接（Vector Chaining）⭐⭐⭐

定义：寄存器定向路径（register forwarding）的向量机版本。前一条向量指令的第一个结果出来后，立刻启动下一条相关指令的执行，而不必等待整条指令全部完成。首次在 Cray-1 上使用。

链接时序示意（LV v1; MULV v3,v1,v2; ADDV v5,v3,v4）：

不采用链接：必须处理完前一条指令的最后一个元素才能启动下一条：

采用链接：前一条指令第一个结果出来即可启动下一条：

⭐ 链接条件：两条向量指令间存在数据相关，但目标/源寄存器不冲突；功能部件不冲突；硬件提供 FU → FU 的直接通路。链接把多个 convoy 合并成一个，极大降低 chime 数。

优化 2：条件执行 / 向量掩码（Vector Mask）⭐⭐

  • vector-mask control：使用长度为 MVL 的**布尔向量（mask 寄存器）**控制向量指令执行；
  • 当 mask 使能时，向量指令仅对 mask 中对应位为 1 的分量起作用。

两种实现：

实现 说明
Simple Implementation（简单实现） 执行全部 N 个操作，根据 mask 关闭结果写回
Density-Time Implementation（密度-时间实现） 扫描 mask 向量，只执行 mask 非零的元素

缺陷：

  • 简单实现下，条件不满足时向量指令仍需花费时间；
  • 有些向量处理器只控制写回，可能导致除零等异常。

优化 3：稀疏矩阵（Sparse Matrices）⭐⭐

  • gather（收集，LVI 操作）：使用 index vector 中给出的偏移加基址读取 → 在向量寄存器中形成一个密集向量；
  • 这些元素以密集方式操作完成后，再用同样的 index vector **scatter（散射）**存储回稀疏矩阵的对应位置；
  • CVI 指令（Create Vector Index）设置步长 index 0, 1×m, 2×m, …, 63×m；
  • 这些操作编译时可能无法完成（编译器无法预知 K(i) 以及是否有数据相关）。

稀疏矩阵性能对比（Cache 1993 vs Vector 1988）：

IBM RS6000 Cray YMP
Clock 72 MHz 167 MHz
Cache 256 KB 0.25 KB
Linpack 140 MFLOPS 160 (1.1×)
Sparse Matrix (Cholesky Blocked) 17 MFLOPS 125 (7.3×)

关键原因：Cache 每 cache block（32–64B）只需 1 个地址，而 Vector 每元素（4B）只需 1 个地址——对稀疏访问，向量机的地址效率高得多。

优化 4：自动代码向量化（Automatic Code Vectorization）

向量化是指在编译期间对操作重定序，需要进行大量的循环相关分析：

向量/SIMD 处理小结

  • 向量/SIMD 机适合挖掘 DLP（同样操作作用于不同数据元素；元素操作独立，提高性能、简化设计）；
  • 性能提升受限于代码的向量化程度（标量操作限制性能 —— Amdahl’s Law）；
  • 许多 ISA 都包含 SIMD 操作：Intel MMX/SSEn/AVX、PowerPC AltiVec、ARM Advanced SIMD。

在已有 ISA 中添加向量长度很短的向量操作指令。将已有的宽寄存器拆分为多种窄通道：

历史：1957 年 Lincoln Labs TX-2 已将 36-bit datapath 拆为 2×18b 或 4×9b。现代设计寄存器更宽：128b（PowerPC AltiVec、Intel SSE2/3/4）、256b（Intel AVX，可扩展到 1024b）。

  • Stride 恒为 1。

多媒体扩展 vs 向量机 ⭐

维度 多媒体 SIMD 扩展 向量机
指令集 受限：无向量长度控制；无常数步长寻址；无 scatter/gather 完整
对齐 load/store 必须 64/128-bit 边界对齐 灵活
向量寄存器长度 短（128/256/512b），需超标量发射保持 multiply/add/load 忙 长（64–256 元素）
循环展开 通过循环展开隐藏延时 → 增加寄存器读写压力 不需要
发展方向 更好支持非对齐、双精度浮点；AVX 256b（可扩到 1024b） —

阵列处理器（Array Processor）vs 向量处理器 vs VLIW

  • Array processor（并行处理机、SIMD 处理器）：核心是多个处理单元构成的阵列，单一控制部件控制多个 PE 对各自数据做相同运算。
  • VLIW：多个独立的操作由编译器封装在一起。
  • Array processor：单个操作作用在多个不同数据元素上。

6.3.2 GPU 的图形流水线背景（理解演进用）

GPU 原始设计目标：3D rendering——从场景描述（3D 表面几何如三角网格、表面材质、光照、相机等）生成照片级真实感图像。核心问题：计算 3D mesh 中每个三角形对图像中每个像素外观的贡献。

图形实体（nouns）：vertices（顶点）、triangles（三角形）、fragments（片段）、pixels（像素）。

图形操作（verbs）：图形流水线对这些实体执行各种操作。Fragment processing 模拟真实世界材质的反射。

关键观察（2001–2003）：GPU 在对数据集合（顶点/片段/像素流）执行**相同计算（shaders）**时是非常快的处理器——这听起来很像数据并行！于是有了 GPGPU。

6.3.6 SIMT 执行模型 ⭐⭐⭐

编程模型 vs 执行模型（重要区分）⭐

概念 含义 例子
Programming Model（编程模型，软件视角） 程序员如何描述应用 顺序（von Neumann）、数据并行（SIMD）、数据流、多线程（MIMD、SPMD）
Execution Model（执行模型，硬件视角） 硬件底层如何执行代码 乱序执行、向量机、数据流处理机、多处理机、多线程处理机

执行模型与编程模型可以差别很大：

  • 顺序模型可以在乱序执行的处理器上执行；
  • SPMD 模型可以用 SIMD 处理器实现（即 GPU）。

SPMD（Single Program Multiple Data）⭐

  • 单程序多数据：一种编程模型而不是计算机组织；
  • 每个处理单元执行同样的过程，处理不同的数据；
  • 这些过程可以在程序中某个点同步（barriers）；
  • 多条指令流执行相同的程序：每个程序操作不同数据、运行时可执行不同的控制流路径；
  • 许多科学计算以 SPMD 编程，运行在 MIMD 硬件上；现代 GPU 也以这种方式编程，但运行在 SIMD 硬件上。

SIMT（Single Instruction, Multiple Thread）⭐⭐⭐

GPU 不是用 SIMD 指令编程，而是用线程（SPMD 编程模型）：

  • 每个线程执行同样的代码，但操作不同的数据元素；
  • 每个线程有自己的上下文（可独立启动/执行）；
  • 一组执行相同指令的线程由硬件动态组织成 warp；
  • 一个 warp 是由硬件形成的 SIMD 操作（NVIDIA 把 32 个 CUDA 线程组成一个 warp）。

SIMD vs SIMT 执行模型 ⭐⭐⭐

维度 SIMD（传统向量机） SIMT（GPU）
指令流 一条指令流（一串顺序 SIMD 指令），每条对应多个数据输入 多个指令流（标量指令）构成线程，这些线程动态构成 warp
编程模型 SIMD（无额外线程），SW 需知道向量长度 SPMD（多个标量线程），SW 不必知道向量长度
Lock step 是：一条向量指令执行完才启动下一条 否：不需要 lock step
线程独立性 单一线程，不可单独对待 每个线程可单独对待（可映射到不同 warp）
ISA 包含 vector/SIMD 指令 标量 ISA，可动态形成逻辑上的向量指令
本质 在 SIMD 硬件上直接表达 SIMD 在 SIMD 硬件上实现的 SPMD 编程模型

SIMT 的两大优点 ⭐：

  1. 可以独立处理线程——每个线程可在任何标量流水线上单独执行（MIMD 处理模式）；
  2. 可以组织成 warp——把执行相同指令流的线程构成 warp，形成 SIMD 处理模式，充分发挥 SIMD 优势。

Warp 级细粒度多线程（Warp-Level FGMT）⭐⭐

设一个 warp 由 32 threads 构成。若有 32K 次循环 → 1K 个 warp。这些 warp 可在同一条流水线上交替执行（Fine grained multithreading of warps）。

Warp 指令级并行：例机每 warp 32 线程、8 lanes，发射 1 warp/cycle 即可完成 24 operations/cycle。

通过 warp 级 FGMT 隐藏延迟 ⭐：

  • 流水线上每次执行每个线程的一条指令（No interlocking）；
  • 通过 warp 的交叉执行来隐藏延时；
  • 所有线程的寄存器值保存在寄存器文件中；
  • FGMT 可容忍长延时（百万像素级）。

SM Warp 调度与记分牌 ⭐

  • 每个 SM 启动 warp（2 级并行：block 级 + warp 级；每 32 线程共享指令取）；
  • SM 硬件实现零开销 Warp 调度：
    • 下一条指令操作数就绪的 warp 为可执行（eligible）；
    • 按优先级调度策略选择 eligible warp；
    • 一个 warp 内所有线程执行相同指令。
  • SM 指令缓冲 + Warp 调度：
    • 每周期取一个 warp 指令到任意指令缓冲槽；
    • 每周期发射一个就绪 warp 指令；用**操作数记分牌（operand scoreboarding）**防止冒险；
    • 发射选择基于轮转（round robin）或 warp 年龄；
    • SM 把同一指令广播给 warp 的 32 个线程。
  • 记分牌（Scoreboarding）：CDC 6600（1960s）的老概念，硬件表格跟踪：指令的取/发/执行状态；所需资源（功能单元和操作数）；哪些指令修改哪些寄存器。

6.3.8 GPU 分支处理：Warp Divergence（线程发散）⭐⭐⭐

问题

GPU 控制逻辑使用 SIMD 流水线以节省资源（标量线程构成 warp）。当一个 warp 中的线程分支到不同执行路径时，产生分支发散（Branch Divergence）。

这与向量处理机的条件执行（Vector Mask / Masked Vector Operations）类似。

条件分支的处理机制 ⭐

GPU 使用**内部屏蔽字（masks）**和 SIMT-Stack（分支同步堆栈）：

  • 分支同步堆栈（branch synchronization stack）：
    • 保存分支的路径地址；
    • 保存该路径的 SIMD lane 屏蔽字（mask）（指示哪些 lane 可提交结果）。
  • 指令标记（instruction markers）：管理何时分支（divergence）到多个路径、何时路径汇合（converge）。

PTX 层：CUDA 线程的控制流由 PTX 分支指令（branch、call、return、exit）控制，外加程序员指定的每车道 1-bit 谓词寄存器（predicate register）。

GPU 硬件指令层：分支指令 + 管理分支同步栈的特殊指令；为每个 SIMD thread 提供堆栈保存分支路径；硬件指令带 1-bit 谓词寄存器。

分支发散的处理流程 ⭐⭐

  1. 硬件跟踪各 µthread 转移方向（判定哪些是成功转移、哪些失败）；
  2. 若所有线程走相同路径 → 保持 SIMD 执行；
  3. 若方向不一致 → 创建 mask 向量指示各线程转移方向；
  4. 继续执行分支失败的路径，把分支成功的路径压入硬件堆栈（分支同步堆栈），待后续执行；
  5. 通过 pop 弹出执行路径及 mask，执行该路径；
  6. SIMD lane 完成整个分支路径后再执行下一条指令称为 converge（汇聚）。

⭐ 代价：对相同长度的路径，IF-THEN-ELSE 的效率平均只有 50%（两条路径要串行执行）。

动态 Warp 形成/合并（Dynamic Warp Formation/Merging）⭐

Idea：分支发散之后，动态合并执行相同指令的线程——从等待的 warp 中形成新 warp，若足够多线程分支到每条路径，可能创建完整的新 warp（参考 Fung et al., MICRO 2007）。

限制：

  • 硬件约束：线程到 lane 的映射受寄存器布局约束，不能任意把线程移到任意 lane；
  • 存储器访问：动态构成 warp 使访问模式随机化 → 降低存储器访问局部性 → 带宽利用率下降。

Memory Divergence（存储器发散）⭐

  • 现代 GPU 含高速缓存减少存储器访问；
  • 理想：一个 warp 中所有线程的存储器访问都命中；
  • 问题 1：一个 warp 中有些命中、有些失效；
  • 问题 2：一个线程的 stall 导致整个 warp 停顿；
  • 需要相关技术解决存储器发散访问问题。

6.3.10 合并访存（Coalesced Access）⭐⭐

SIMT 存储器访问

不同线程的相同指令使用 thread id 存取不同数据元素。例：N=16，4 threads/warp → 4 warps：

Global Memory Access 与合并 ⭐

  • 每个线程发射不同大小（最小 1 byte）的访存请求；
  • 给定一个 load/store 地址，存储器返回/更新 32 / 64 / 128 字节的段（segment）；
  • 最大化带宽：每次存储器传输操作整个 128 字节段。

合并（Coalescing）算法（Tesla / GTX 平台，以 half-warp 为单位）：

  1. 从最小编号线程的访存请求开始；
  2. 找到包含该地址的存储段（32/64/128 byte，取决于数据类型）；
  3. 找到该段内其他活跃线程的请求地址，合并（coalesce）；
  4. 尽可能缩减事务大小；
  5. 访问存储器，把这些线程标记为 “inactive”；
  6. 重复直到 half-warp 内所有线程都被服务。

⭐ 合并访存的关键：warp 中连续线程访问连续地址（且对齐）→ 合并为一次宽访存。非连续访问 → 多次访存 → 带宽严重浪费。

Chaining Warp 间 ILP（warp 调度重叠）
Vector mask Active mask / 谓词寄存器
Vector length register (VLR) （隐式，由 warp 大小决定）

6.3.13 适合 GPU 的应用特征 ⭐

  • 大量数据并行：每个元素可独立计算（像素、矩阵元素、粒子）；
  • 规则控制流：分支尽量少，避免 warp divergence；
  • 计算密集：计算/访存比高，能喂饱大量 SP；
  • 可容忍较高延时：warp 切换能隐藏的延时；
  • 访存模式规则：连续线程访问连续地址（coalesced）。

6.4 公式速查表

向量执行时间

Chime 近似：

$$
T \approx m \times n \text{ (clock cycles)}
$$

（$m$ = convoy 数，$n$ = 向量长度；忽略启动开销）

含启动开销与分段开采的精确公式 ⭐⭐⭐：

$$
\boxed{, T_n = \left\lceil \dfrac{n}{MVL} \right\rceil \times (T_{loop} + T_{start}) + n \times T_{chime} , }
$$

向量性能指标

  • R∞：n→∞ 的峰值性能（MFLOPS）；
  • Rn：向量长度 n 时的性能；
  • N1/2：达到 R∞/2 所需的 n；
  • NV：向量流水性能超过标量性能的最小 n。

考题数字（$A = B \times s$，$n=200$，MVL=64）

  • 段数 = ⌈200/64⌉=4；
  • Tstart=12(Load)+7(Mul)+12(Store)=31；
  • T200=660+4×31=784 cycles；
  • 每元素 = 784/200=3.9 cycles/element。
